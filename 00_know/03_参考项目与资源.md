### 0.2 组织与提取规范（摘要；完整规则见 `_SPEC.md`）

1. **一个来源项目 = 一个目录** `00_resources/<project>/`，**原样保留该项目的目录结构与组织思想**（不做适配、不改写、不改名）。
2. **机型归属写在索引里**，不靠目录重复体现（旧做法"按机型复制十几份"已废弃）。
3. **保留**：源码、配置与机型描述、文档、数据集（≤20 MB）、**推理策略文件（不限大小，4 GB 兜底）**。
4. **省略但有登记**：网格/CAD/点云/录包/归档/可执行/媒体/字体/大表/日志/超限文件 → 原目录 `_OMITTED.md` 逐条登记（文件 | 体积 | 类型 | 源路径）。
5. **整目录跳过**（不登记）：`.git`、`__pycache__`、虚拟环境、`node_modules`、缓存目录、`build/ dist/ outputs/ logs/`。
6. **不纳入**（只记在 `_SPEC.md` §6）：通用工具与素材（`ComfyUI`/`InvokeAI`/`langflow`/`n8n`）、非目标机型（`dm_dog`/`min_dog`）、纯网格描述汇总（`awesome-robot-descriptions`）等。

### 0.3 与 `assets/robots/` 的分工（**别搞混**）

| | `00_resources/` | `assets/robots/<id>/` |
|---|---|---|
| 角色 | **只读参考底座**（原始素材取证，保留来源项目的路径与全部变体） | **归一化后的可执行资产包**（按 contract v3 收敛为单一事实源） |
| 用途 | 核对"上游是什么值、怎么组织的" | 训练 / 仿真 / 浏览器实际加载的东西 |
| 纪律 | **禁止**把它当运行时资产加载 | 唯一可加载处 |

### 0.4 怎么把省略的文件取回来

1. 项目内路径 = `00_open/<project>/` 下的原始相对路径，**一一对应**；
2. 目录里的 `_OMITTED.md` 的「源路径」列 = 可直接取用的位置；
3. 要成批恢复某类文件：改 `tools/sync_resources.py` 的 `OMIT_EXTS` 后跑 `--only <project>` 重同步。

> **前提**：`00_open/` 是工作区外的完整克隆，**不在 git 里**。换机器后先按 §2 补齐克隆，否则"取回省略文件"和跨源对照都不可用（踩过一次，见 §4.4）。

## 2. 官方源完整克隆（回答"这个值什么时候被改的"）

### 2.1 为什么必须是**完整**克隆

`00_resources/*` 全是**文件快照、没有 `.git`** —— 只能回答"现在是什么值"，**回答不了"这个值是什么时候被改的、被谁去掉的"**。而浅克隆（`--depth 1`）同样只有 1 个 commit，一样查不了历史。所以：**官方源要完整克隆**，落在工作区外 `/00_open/<name>`，**不进 git**，仓库里只登记"上游地址 + commit + 用途"。

### 2.2 已克隆的源（5 个，均为完整历史）

| 目录 | 上游 | 用途 |
|---|---|---|
| `mujoco_menagerie` | `google-deepmind/mujoco_menagerie` | **独立第三方**权威模型库；MJCF 带 `actuatorfrcrange` |
| `unitree_ros` | `unitreerobotics/unitree_ros` | **官方 URDF/xacro**：关节侧 `<limit effort velocity>` 的权威来源（g1 的速度限幅就是这里救的场） |
| `unitree_rl_mjlab` | `unitreerobotics/unitree_rl_mjlab` | **官方训练栈**：电机型号表（`effort_limit`/`velocity_limit`/`reflected_inertia`）+ 四连杆等建模假设注释 |
| `unitree_rl_gym` | `unitreerobotics/unitree_rl_gym` | 官方早期 RL 工程（go1/go2/h1 的 urdf 与 config），第三方工程的上游 |
| `unitree_mujoco` | `unitreerobotics/unitree_mujoco` | 官方 MuJoCo 仿真仓（b2w/go2w/g1 等落地模型与场景） |

> **具体 commit 不在本文档登记**（它天天在动，登记了就过期 —— §2.4）。用法：`git -C 00_open/<name> rev-parse --short HEAD`，或直接跑 §2.3 的工具看它读到了什么。

### 2.3 已知缺口（未克隆）

- 非官方快照（`AMP_mjlab` / `InstinctMJ` / `LeggedGym-Ex` / `robot_mujoco` / `rc_old` 等）的**上游地址未记录**（快照没有 `.git`，README 也没写 URL）→ 想补历史需先确认上游；
- `wuji_hand` 在审计中**完全无源**（`00_resources/wuji-mjlab` 里没有 `effort/limit` 类声明），需找舞肌官方模型仓；
- 非宇树机型的官方源（DeepRobotics lite3/m20、LimX tron1 ×3、microduck）目前**只有快照**。

### 2.4 用法、局限与两个踩过的坑

```bash
python tools/cross_source_audit.py                # 全 14 机型
python tools/cross_source_audit.py unitree_g1     # 单机型
python tools/cross_source_audit.py --json         # 机器可读
```

**工具只列事实，不替你判"谁对"**（判定口径见 §3）。**不进 CI**：它依赖本地克隆，CI 里没有这些源（会全部报"无源"，没有意义）。

⚠️ **坑一：源根解析**。`tools/model_field_diff.py` 原先把官方源根**硬编码成 `/00_open/...`**，在 Windows 上被解析成 `C:\00_open` → **永远找不到源**，于是打印"（无官方 MJCF）"。看起来像"官方没有该模型"，实际是工具找不到克隆。现改为按 `LEGGED_STUDIO_UPSTREAM_ROOT` → `/00_open` → **本仓上级目录** 顺序解析。
👉 **规则：工具报"无源"时，先怀疑工具，再怀疑上游。**

⚠️ **坑二：检错分支 / 登记过期**。本机 `unitree_mujoco` 曾检出在 `old` 分支（2022-08-30，只有 a1/aliengo/go1/laikago），而它的 `main` 就是最新 —— **不是"缺克隆"，是检错了分支**；切回后 `unitree_robots/` 下 a2/as2/b2/b2w/g1/go2/go2w/h1/h1_2/h2/r1 全部到位。
👉 **规则：对照结果异常时先 `git branch --show-current` + `rev-parse HEAD`，并记录实测 HEAD 而不是照抄旧登记。**

### 2.5 工具已知局限（补齐才能扩大覆盖面）

1. **关节名别名**：官方 URDF 里轮腿机的轮叫 `*_foot_joint` / `*_foot_motor_joint`，我方契约叫 `*_wheel_joint` → 会被报成"无源"。需要一张 per-robot 的关节名别名表。
2. **快照噪声**：`00_resources` 里同一机型常有 6–10 份副本（第三方工程各自 vendored），版本混杂 → "源间冲突"计数噪声大。应以**官方克隆**为一等源、快照为参考。
3. **只比 `effort` / `velocity`**：`armature` / `friction_loss` / 刚度阻尼还没纳入对照（URDF 侧无对应字段，需从训练常量抽）。

## 3. 多源对照溯源方法

**用于回答"某个数值是原本就没有、后续被去掉、还是我方录入错"**，共三步（完整判据见 [`05_任务清单.md`](./05_任务清单.md) §方法固化）：

1. **找官方项目并完整 git clone**（非浅）—— 有历史才能 `git log`/`blame` 回答"什么时候被改的"；
2. 再找若干**非官方**提供 URDF/MJCF 的仓，作为**独立实现**交叉验证；
3. **三向对照**（我方 ↔ 官方 ↔ 非官方），差异逐条判定归属。

| 现象 | 判定 |
|---|---|
| 多源一致、与我方不同 | **我方错**（应改我方） |
| 源间不一致（不同版本给不同值） | **版本差异**（登记，改数需人工拍板） |
| 任何源都没有 | **原本没有**（登记缺口；或按官方写明的公式推导，**不猜**） |

**已在 g1 上验证有效**：官方 URDF 补齐 4 个角色的速度限幅 37（缺的原因是**只查了电机型号表、没查关节侧 URDF**）；同时发现 `hip_roll` 的 URDF(88) vs MJCF(139) 版本差异并正确判为"以我方模型为准"。

## 4. 字段级对照：我们的 MJCF vs 官方

工具：`tools/model_field_diff.py` —— 把两侧**编译成 `MjModel` 再逐数组比**（比文本 diff 可靠：defaults 展开、单位换算、引用都已生效）。官方 MJCF 取 `unitree_mujoco/unitree_robots/*` 与 `mujoco_menagerie/*`。

### 4.1 **当前口径**（源根修好后的实测，2026-09-14）

| 机型 | 规模 | option 差异 | 关节级 dof 差异 | 接触 / 摩擦 | 执行器 | 质量 |
|---|---|---|---|---|---|---|

| `unitree_b2w` | 一致 | 3（同上） | 0 | **8**：geom25 / geom37 的 `contype`·`conaffinity`（我方 0 vs 官方 1） | **0**（`nu` 16/16 ✓） | 0 |
| `unitree_go2` | nbody 14 vs 18 | 1：integrator | **16**：calf `armature` 0.02 vs 0.01；hip/thigh/calf `damping` 0.5 vs 0.1 | **0**（首轮 37 处摩擦差异已消失） | 0 | 0 |
| `unitree_go2w` | nbody 20 vs 18 | 1：integrator | 4：calf `armature` 0.02 vs 0.01 | **75** | 0 | 0 |
| `unitree_g1` | ngeom 68 vs 73 | 3：integrator / iterations / ls_iterations | **62**：ankle `armature` 0.007219 vs 0.01、`damping` 0 vs 0.05；elbow `armature` 0.003623 … | — | 0 | **0**（首轮 torso 差 23% 已消失） |

### 4.2 怎么读这张表（避免再次误判）

1. **`integrator`（我方 `implicitfast` vs 官方 `Euler`）是统一的有意口径**，不是漂移；b2/b2w 的 `cone=elliptic` + `impratio=100` 同理。
2. **关节级 `armature` / `damping` 的差异是"我方按角色区分、官方一刀切"**（0.02 / 0.01、0.5 / 0.1），值来自契约 v3 → **有意**，应标注而不是当缺口。
3. **接触参数类差异**已于 2026-09-14 裁决为「训练域」口径（见 [`04_参数真值标准.md`](./04_参数真值标准.md) §6.1）⇒ **不再要求与官方对齐，也不需要为此重刷基线**；数值真源仍是包内 MJCF 一处，契约只做 `physics_domain.contact` 声明。
   > ⚠️ **计数口径提醒**："37 处 / 75 处"是**继承 default 的几何个数**，不是"这么多个独立数值不同"。以 go2 为例，真正的决策点只有 **1 个 default `friction` + 4 个足端**。
4. **首轮已消灭**：`b2w nu=0`、`go2` 摩擦 37 处、`g1` torso 质量差 23%。

### 4.3 已收口的贴标结论（2026-09-14 全部关闭，**无待贴标签项**）

**① 关节级 `armature` / `damping` 差异（g1 / go2 / go2w）→【有意】**
我方按**关节角色**区分取值，官方对同类关节一刀切；真源在契约 v3 `joint_constant_tables`、由 `bake_mjcf_physics` 固化进 MJCF —— 属"上游训练工程口径 vs 官方展示模型口径"的**版本差异 + 我方有意细化**，不改。

**② `g1` ngeom 68 vs 73（净少 5 个）→【有意 · 碰撞建模流派差异】**
两份 MJCF 来自 Unitree 的**两条发布线**：我方（契约 `source: mjswan (unitree_rl_mjlab)` → playground 流派）＝**视觉网格 + 基元 capsule 碰撞**（足端 7 capsule、显式 `friction 0.6`）；官方 `unitree_mujoco` g1_29dof ＝**每连杆视觉+碰撞双份 STL 网格**，足端例外为 4 个 r=5 mm **角点接触球**。净 −5 是两侧多与少互相抵消（编译后逐 body 对账：官方 +13 / 我方 +8），判定为"**对细小中间连杆不设碰撞**"的刻意简化。

> **诚实边界**：网格碰撞在**手臂自碰 / 臂-躯干贴合**等场景比 capsule 近似更保真。将来做 g1 上肢操作类任务若出现"手臂穿模/穿身"，应回到本条把肩/腕碰撞补上，而不是当成 bug 排查。当前 g1 策略的接触面以足-地为主，此差异不构成验收风险。

**③ go1 的 12 处质量差异 + 关节 `range` 不同 →【版本差异 · 以我方声明上游为准】**
go1 在 `unitree_mujoco` main 分支已无（只在 `old` 分支），官方对照走 menagerie。实测**三条官方线肢体质量互不相同**：

| 部件（×4 腿） | unitree_ros URDF（ROS 线） | unitree_mujoco 仿真线 ＝ LeggedSkillDeploy ＝ **我方** | menagerie |
|---|---|---|---|
| hip | 0.591 | **0.679292** | 0.68 |
| thigh | 0.92 | **0.898919** | 1.009 |
| calf | 0.135862 | **0.218015** | 0.195862 |
| 躯干 | 5.204 | **4.801** | 5.204 |

按 §3 裁决规则（"不同版本给出不同值 → 版本差异，登记不改数"），与 g1 `hip_roll` effort 的先例同口径：**以我方模型为准**。

## 9. 取用纪律（本次清点得出的规则）

1. **只读底座三条禁止**：禁止把 `00_resources/` 当运行时资产加载；禁止就地修改（要改就改 `assets/robots/` 的归一化包）；禁止把它的文件复制进交付物（引用路径即可）。
2. **引用必须带路径**：本文件与任务清单里的"依据"要写到**具体文件或目录**（例：`unitree_ros/.../g1_description/xacro/...`），而不是"某某项目里写着"。写不出来的依据 = 没有依据。
3. **许可前置**：新引入上游资产前先看顶层许可文件（本库相当一部分目录**顶层无许可**，见 `_index.json` 与 `tools/audit_resource_licenses.py` 的输出）；许可不清的资产不得进包（`registry/licenses.json` 随包对账）。
4. **数字要带口径**："37 处摩擦差异"这类计数会因**统计口径**而失真（见 §4.2）。引用计数时必须写明"按什么口径数的"。
5. **引用前先验"它还成立吗"**：本文件里的差异表**成对存在**（首轮 vs 当前，§4.1 与 §4.5）—— 引用一律取**当前口径**，并顺手跑一次工具确认（`tools/model_field_diff.py`）。
6. **工具报"找不到源"时先怀疑工具**（§2.4 坑一）；**对照结果异常时先看分支/HEAD**（§2.4 坑二）。
