## 追记（2026-10-04）：三条工程规则（源自 m20-dreamwaq 排障，规则化沉淀）

1. **冒烟 = 产品同接线**：`tools/_smoke_one.py` / `validate_training_smoke` 透传并应用 profile 的
   `algorithm_plugin` 声明（同一 `apply_algorithm_plugin` 函数）——冒烟验的就是产品会跑的那份接线，
   "声明了的算法从未被训练层验证"这类缝隙已封。
2. **`--repeat N` 间歇故障门禁**：一次绿不算绿；任何一次非 ok 即判 `flaky`。
   源起：warp 层时间窗式间歇 CUDA 故障（见下条）一次通过无法排除。
3. **runner 工厂禁写死包内私有算法类名**（`backend/test_runner_classname_rule.py` AST 全源树扫描）：
   算法类名只许 `mjlab.*`（框架默认）或 `adapters.mjlab.algorithms.*`（注册插件），
   由 profile 的 `algorithm_plugin` 声明在装配期覆写；包内私有算法扩展（`<pkg>.mdp.rl:*`）判红。
   附：AMP 源口径实现已上移 `adapters/mjlab/algorithms/amp/source_amp.py`（跨族可用），
   族 Kit imitation 薄 re-export；豁免清单清零。

另：**训练前 GPU 环境健康检查**——`validate_training_smoke` 起跑前检测 GPU 上驻留的
VM/hypervisor 类进程（MuMu/VirtualBox 等，启发式进程名匹配），命中打印 `[env!]` 警告并写入报告
`env_warnings`：其显存/调度压力会产生**时间窗式**间歇 CUDA 故障（代码无关、红绿成簇），
实证案例 m20-dreamwaq（2026-10-04，MuMu 驻留期 ~50% 红、关闭后稳定绿）。

## 追记（2026-10-05）：第四条工程规则——完训≠达标（completion 判据钩子）

4. **档案声明了验收判据就在训练终态后自动出判定**：launcher `finalize` 在
   `train_completed` 终态后检查 profile 的 `criteria.tracking` 声明（`training_config.json`
   → `assets/robots/<robot_id>/training/profiles/<id>.json`），已声明且无既有判定 ⇒
   后台发一次 `tools/trend_probe.py`（fail-soft，stdout 落 `criteria_probe.log`，
   产物 `trend_probe.json` 随 run 存证），`TrainingTask.to_dict` 把其中的
   `criteria_tracking` 暴露成 API 的 `criteria` 字段。语义锚点：`train_completed`
   只证明"训练循环没 NaN"——2026-10-05 实测 1024 rough 完训但策略全零（站着活局部最优），
   判负必须显式出数而不是靠人记得跑探针。未声明判据的档案不发探针（大多数档案）；
   声明是唯一开关（与 algorithm_plugin 同风格：加面板 = 一行声明，判定 = 一行声明）。

## 追记（2026-10-12）：交互层重构裁决——「Web 单壳 × 统一设计系统 / CLI 薄内核 / 桌面真托管」

> 触发：用户指令「UI 设计与逻辑要符合项目定位，充分参考网络上各类相关项目，大幅优化；不只是 Web，还有桌面端与 CLI——总体来说就是交互层，可大幅重构，结合 dsh 的一切皆插件与统一架构；**技术方案不必认定现状去修补，有更优秀的方案直接转向，长痛不如短痛**」。本节是交互层的目标架构裁决，与 §14（一切即插件）、§0.5（三形态一页图）同口径落地。

### A. 现状诊断（实测 2026-10-12，交互层四面）

| 面 | 现状 | 痛 |
|---|---|---|
| Web 信息架构 | `workbench.html` 单壳已具雏形（hash 路由 8 视图 + 注册表侧栏 `#registrySideNav` + 面板 manifest 含 `cli`/`desktop`/`home_card` 四投影字段），但 6 个视图靠 **iframe** 嵌独立页（双套导航并存：壳侧栏 vs 各页 topnav） | 导航心智分裂；第一入口是「开始一次实验」（链路中段），不是竞品验证过的「零训练上手」（1000frames 第一入口 = 加载已训 ONNX 直接试，`00_resources` 已入库取证） |
| Web 视觉 | **三套互不相通的样式**：`shared/ui.css`（浅色 `--ls-*` tokens）/ `workbench.css` + `play-overrides.css` + `urdf-viewer.css`（浅色）/ `web/sim2sim/` 内联深色 HUD | 同一产品两种肤色；竞品（Foxglove Studio / Isaac Sim / RViz / MuJoCo simulate）工程工具**清一色深色优先**——深色不是审美偏好，是长时盯屏 + 3D 视口融合的工程标准 |

| 桌面 | `electron/launcher/` 只 spawn 后端 + `shell.openExternal(系统浏览器)`；快捷按钮**硬编码**、不消费 `/api/panels` | 产品根本不在 Electron 里跑——"桌面版"名不副实；四投影的 desktop 面断裂 |

### B. 目标架构（三形态同一份注册表投影，设计系统唯一）

```
registry/plugins/panel/*.json（legged-plugin-1.0，唯一装配清单）
      │ surfaces: panel(导航/入口) · http · cli · desktop · home_card
      ├─► Web 单壳（workbench.html）：侧栏/首页卡片 = 投影产物；
      │     视图容器 = hash 路由 + iframe（过渡形态，见 C-2 分期）
      ├─► CLI：薄内核 = argparse 树从声明派生（panel 面已如此）+ 领域 provider 模块
      └─► 桌面：Electron **BrowserWindow 直连后端** 托管产品本体；
            启动器快捷动作 = /api/panels 投影（desktop:false 不出现）
web/shared/ui.css = **唯一设计系统**（tokens + 组件类，暗色优先 + 亮色同 tokens 派生）
      └─► 全页面（含 sim2sim 深色 HUD、Electron 启动器）共享同一 tokens
```

### C. 六条裁决（含否决理由，§21 规则 7）

1. **设计系统：暗色优先的统一 tokens，唯一基座 = `web/shared/ui.css`**。参考依据（可核验）：Foxglove Studio（面板坞深色工程台）、Isaac Sim / RViz / MuJoCo simulate（仿真器深色 HUD 传统）、Linear（密度与字阶）、仓内取证 StackForce/1000frames（浅色转换器/试玩站——浅色系适合营销站，不适合长时工作台）。**语义色两态（soft/solid）对比度按 WCAG AA 预挑**（`test_ui_metrics_gate.py` 的 4.5:1 门禁是硬约束）。亮色主题保留为 `data-theme="light"` 派生（同一 tokens 换值，不维护第二套组件）。**否决「保持浅色默认」**：产品主场景是仿真视口 + 长时训练监控，浅色壳与深色 3D 视口割裂（现状正是如此）。
2. **Web 视图容器：本期保留 iframe 嵌入，先统一壳与视觉；「面板 = 懒加载 ES module」的目标形态登记为后续分期**。否决「本期拆 12 页为 module」：`training_create.html` 179 KB 巨石拆分是独立任务（§19 Rk4 已裁：巨石拆分与插件化收编解耦）；且四个 UI audit 文件 + metrics gate 锁住大量选择器与文案，大爆炸重写 = 门禁全红却无行为收益。**否决迁 Vue/React + 构建链**：§15 候选 A 裁决不变（离线包以 `web/sim2sim/` 为根、无构建 ES module 是既有裁决）；构建链不解决"两个世界"（sim2sim 永远无构建）。
3. **首页信息架构：试玩优先**。「预训练策略 · 免训练即玩」从第三屏提到首屏（hero 即试玩入口），「开始实验」降为次行动——对齐「可信试玩场」定位与 1000frames 的第一入口证据；`homeDemos` 卡加载即校验 ONNX 章（D3 判据的产品面表达）。
4. **CLI：薄内核化 = 机械拆分**（`scripts/legged_studio_cli.py` 入口保留 → `scripts/cli/` 领域模块），**不引 click/typer**（零依赖纪律；subprocess 测试面 6 文件不动）；注册表投影面（`panel`/`panels`）保持声明驱动并扩到 `home_card`（CLI `status` 与首页卡片同源）。
5. **桌面：Electron 真托管**——`BrowserWindow.loadURL(后端 workbench)`（健康轮询就绪后加载，失败回退启动器诊断页）；启动器快捷动作改为 `/api/panels` 投影（`desktop:false` 的第三方包不出现）。**否决换 Tauri**：Rust 工具链 + 重写打包链（`scripts/package_windows_*.ps1` 全废）换 20MB 体积，收益与成本不成比例；Electron 的问题不在壳而在"没托管"。
6. **sim2sim 保持独立离线根**（§3.1 裁决不动），但**视觉并入统一 tokens**（深色 HUD 取值 = tokens 派生，品牌头与壳同源）——离线包结构零改动（tokens 以 `<link>` 引共享 CSS，离线打包白名单同步）。

### 13.1 原定位的四个失效点（对照 §12 证据）

| "从模型到实机的整条链路收进一个产品" | 链路各段都有更深的竞品：模型段（StackForce）、训练段（1000frames）、动作段（RoboCraft/LainLab）、部署段（DimOS/RoboCraft）。**全链路每段都做 = 每段都不够深** | §12.2 |

### 13.2 新定位

**一句话**：**腿足机器人策略的配方工厂与可信试玩场**——机型×技能×地形×判据全部声明式组合，改配置不改代码；每个策略零训练可试、加载即验章，产物带着证据链上机。

### 12.3 LainLab 源码级解剖（最直接的同类）

**三个可抄**：

1. **工具链补链**：`src/toolchain/{calibrate,collect,bc,dagger,evaluate,export}.py`——**BC 与 DAgger 是本仓完全没有的一段**（本仓 imitation 只到 AMP/CTS/TS 蒸馏，缺"从参考动作到可部署策略"的离线模仿路径）。这是竞品证据里**唯一我们缺的实链路**。
2. **基线随包分发**：`src/baseline/opendoge/skills/baseline.json` + `baselines.py` 发现机制——训练产物成为一等资产，工作台直接列出。本仓 `tools/baselines/*.json` 是门禁基线，不是**产品基线**（用户可一键试玩的参考策略）。
3. **任务类型即目录**：`src/tasks/{velocity,tracking,getup,handstand,jump,multiskill,amp}`——**getup（起身）与 multiskill（单策略多技能）是本仓没有的任务类型**。

**一个反例（价值最大的发现）**：`src/workbench/catalog.py` 用**硬编码 Python 字典**表达任务目录——`TASKS`（11 条字符串）、`TASK_ASSETS`（13 条路径）、`SKILLS`（9 条）、`ALGORITHMS`。注释明确写"importing the workbench never imports torch"（纪律同本仓控制面），但**加一个任务 = 改 dict + 改 robots 注册 + 改 skills 表，三处手工同步**。这正是 `01` §五"差异由数据表达"要消灭的形态——**LainLab 证明市场上没有第二个"注册表驱动 + 机器可查"的同类**。本仓 `registry/` 20 个子域是既成差异化资产，插件化重构是把它们从"一堆 JSON"升级为"一套协议"。
