## 1. 准入规则（本次新增的硬门）

| 规则 | 内容 | 判据 |
|---|---|---|
| **T. 训练准入** | 机器人包可携带**训练**资产，当且仅当 `00_resources` 中存在该机型的**训练任务源码** | 路径同时命中「任务目录」（`tasks/`、`envs/`、`config/`、`mdp/`、`agents/`、`learning/`）×「任务文件」（`*_env_cfg.py`、`rl_cfg`、`*_ppo_cfg.py`、`robot_cfg`、`reward`…）×「训练框架」（mjlab / isaaclab / isaacgym / legged_gym / rsl_rl） |
| **S. 仿真准入** | 机器人包可携带**仿真策略**（onnx），当且仅当该策略能对应到具体的训练任务源码 | 逐条策略在 `POLICY_ADMISSION` 表中给出可核对的上游路径；无证据 = 不移植 |
| **C. 包自包含** | 包内不得出现**其他机型**的训练任务目录 | 违规样例：`unitree_go2` 包内携带 `local_tasks/robots/unitree/g1/` |
| **X. 一致性** | 策略声明 ↔ onnx 文件一一对应 | 悬空策略路径、孤儿 onnx 均为违规 |

> 规则 T/S 是**准入下限**（有证据才可移植），不是移植义务；是否实际移植由 B8/B14 的排期决定。

## 4. 未决与后续

1. **规则 T 只判"能不能移植"，不判"要不要移植"**。`unitree_go1` 与 `limx_tron1_wf` 有上游训练源但包内未移植（profiles = 0），属于 **B14** 范围：
   - `limx_tron1_wf`：`tron1-rl-isaaclab` 的 WF 配置（`cfg/WF/limx_base_env_cfg.py`、`robots/limx_wheelfoot_env_cfg.py`、`assets/config/wheelfoot_cfg.py`）可移植；注意上游为 IsaacLab，需按 mjlab 适配。
   - `unitree_go1`：`mjlab_new/src/mjlab/tasks/velocity/config/go1/env_cfgs.py` 与 `mujoco_playground` 的 joystick/handstand/getup 可移植；移植后可按 `git show v0.43.0` 恢复演示策略准入。
2. **框架层去重（B8 原意）尚未实施**：`unitree_go2/training/source/local_tasks/` 仍带整套通用框架（`core/` `learning/` `integrations/` `workflows/` `experiments.py` `bootstrap.py` `cli.py`，约 190 个文件条目），其余 13 个包为机型专属紧凑树（跨包同内容文件仅 75 个）。上移该框架层需要改写 `local_tasks.learning.symmetry.*` 这类**字符串模块路径**（rsl_rl 的 `symmetry_func` 按字符串解析），且验收要求"各包训练冒烟全绿"——**需在有 mjlab venv / GPU 的环境执行并冒烟**，本环境不具备，故未动。
3. **`validation.py` 的 G1 分支**已随本次一并清除（原引用 stock mjlab 的 `unitree_g1` asset，属跨机型验证残留）。
4. **维护约定**：新增机型包或新增策略时，先补 `POLICY_ADMISSION` 证据行，再运行审计；`00_resources` 更新后运行 `--refresh` 重生成证据清单并在 PR 中一并提交。
