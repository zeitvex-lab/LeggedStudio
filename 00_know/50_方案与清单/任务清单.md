### 待决 #7：T-N 曲线与 decimation（2026-09-13 分析，**待拍板**）

> **① T-N 曲线（转矩-速度曲线）：建议"先不做数据字段，但先把矩形 T-N 曲线用满"。**
>
> * **现状**：只有 `effort`（一个数）+ `velocity_limit`（一个数）= **矩形 T-N 曲线**。真机是双曲线（高速力矩衰减）+ 连续扭矩受热限。D9 之前 `velocity_limit` 三端都没生效，等于**连矩形 T-N 曲线都没有**——先把 D9 落地并观察一批验收数据，再谈曲线。
> * **载体评估**：mjlab 的 `ActuatorCfg` 只有 `armature` / `frictionloss` / `effort_limit`，**无速度相关字段**（实测 `00_resources/unitree_rl_mjlab_go2w/mjlab/actuator/actuator.py`）；MuJoCo 的 `actuatorfrcrange` 是静态的，也没有 dof 速度上限属性。→ 真曲线只能在**控制器层**做（每步按 `|τ| ≤ min(effort, P/|v|)` 削顶）。
> * **风险**：削顶会改训练动力学 → 既有 48 策略基线与 headless 结论全部可能翻转（同 armature 修好后的 `go2-moe-cts` 退化）。**建议先作为可选开关**（默认关）+ 在验收报告里出"若启用削顶会削掉多少"的对照数，再决定是否默认开。
> * **数据来源**：需要 `effort_peak` / `effort_continuous` / `v_at_peak_torque` 三个数。当前 **0/14 包有 datasheet 级来源**（g1 训练树的 `ElectricActuator` 只有 `velocity_limit` + `effort_limit` 两个数）→ 加字段必然先要人工录入，属"真机验收阶段"的活，不是现在的瓶颈。
>
> **📌 2026-09-13 续五 状态更新**：① **T-N 曲线字段已就位**（D11：`actuatorParams.t_n_curve` + `control.actuator_model`，UI「高级参数」折叠区，默认不生效）；"先接 velocity_limit、再做可选削顶开关+对照数"两步骤中的**开关**已具备，下一步是**在 mjlab venv 里跑一组 dot 对照数**（本机无 mjlab，无法验证训练侧）。② **decimation 已按"派生量"处理**（D12：保存链不再用 v2 旧值覆盖 v3；一致性检查进 `tools/check_control_consistency.py`），但仍未做成只读展示——建议并入下次 UI 打磨。
>
> **② decimation：不建议加，且不建议做成可编辑。**
>
> * **它已经是契约一等参数**（`control.decimation`，go2 = 20，且与 `control_hz=50` / `physics_hz=1000` 自洽），训练/验收/浏览器三端已在用——**不存在"要不要加"的问题**。
> * **它是派生量**：`decimation = physics_hz / control_hz`。做成可编辑数字就允许三者互相矛盾（例如 50/1000 却写 decimation=10），而策略频率、观测频率、验收判定全按它算——**矛盾不会报错，只会让策略抽**。
> * **建议形态**：在 UI 里**只读展示 + 一致性校验**（三个数不自洽时红标），而非输入框。与 D8/D9/D10 的"可编辑"区别正在于此：那三项是**独立物理事实**，decimation 是**约束**。
>
> **③ 【2026-09-13 已查清，方法：多源对照】** `g1` 的 `ankle_pitch/ankle_roll/waist_pitch/waist_roll` 四个角色 `effort=50` 的来源已确认，**不是迁移丢失、也不是编造**：

## §方法固化：多源对照溯源（2026-09-13 用户提出，已用 g1 验证）

**方法**（用于回答"某个数值是**原本就没有**、**后续被去掉**、还是**我方录入错**"）：

1. **找官方项目**，并且**完整 git clone**（非浅）—— 有历史才能 `git log`/`blame` 回答"什么时候被改的"；
2. 再找**若干份非官方**提供 URDF/MJCF 的仓，作为**独立实现**交叉验证；
3. 三向对照（我方契约 ↔ 官方 ↔ 非官方），差异逐条判定归属：
   * 官方与多份非官方**一致** → 我方错了（改我方）；
   * 只有**单一**来源有、或不同版本给出不同值 → 判为**版本差异**（登记，不改数）；
   * 任何来源都**没有** → 判为"原本没有"（登记为缺口或按官方写明的公式推导，**不猜**）。

**已在 g1 上验证有效**（本轮）：官方 URDF 补齐 4 个角色的速度限幅 37（缺的原因是只查了电机型号表）；同时发现 `hip_roll` 的 URDF(88) vs MJCF(139) 版本差异并正确判为"以我方模型为准"。

**现状短板**：`00_resources/*` 全是**文件快照，没有 `.git`**（无法查历史、无法 blame/diff 版本）；`/00_open/` 只剩 7 个**浅克隆**。所以上面第 1 步现在做不到——这正是下一条行动项。
