# 机器人参数单一真值表（标准）

> **目标**：机器人参数**只确定一套**——不允许多个位置叠加维护，不允许"两边都写错就一直错"。
> 调试时只需看一个地方，改了必然生效。
>
> 日期：2026-09-10 ｜ 对应里程碑：B3 / B5 / B5-2 / B2 / B2-2

## 0. 规则（三条）

1. **一个参数只有一个家**：标准是 `assets/robots/<pkg>/contract_v3.json`。
2. 其它位置只允许两种身份，且**不得独立维护**：
   * **派生视图**：由真值计算得到（如 `locomotion_type` ← `morphology`）；
   * **兼容投影**：给 v2/旧消费方读取的形状（如 `urdf.mass_source` ← `morphology.mass_source`）。
3. **声明值必须等于派生值**，由测试守护（漂移即失败），而不是靠人工对账。

## 1. 各文件的角色

| 文件 | 角色 | 是否机器人参数的"家" |
|---|---|---|
| `contract_v3.json` | **标准**：构型、角色、执行器、动作、观测、控制 | ✅ **唯一** |
| `contract.json`（v2） | 兼容快照：URDF 路径/hash/**总质量**、关节限位、观测组件名 | ⚠️ 仅这些"数据类"字段；语义字段一律由 v3 覆盖 |
| `simulation/config.json` | 未迁移包的**兼容回落**（标记 `source="legacy_config"`） | ❌ 不再参与取值 |
| `robot_package.json` | 打包元数据（capabilities / 目录布局 / demo_policies） | ❌ 非机器人参数 |
| `packs/*.pack.json` | 资源组合**纯引用** + `sha256` | ❌ 引用，不拷贝内容 |

## 5. 仍未收敛（明确记录，不静默放过）

| 项 | 状态与所需证据 |
|---|---|
| `unitree_go1` 的档位 | mjlab 规则 `0.25*effort/stiffness` 算出 hip/thigh≈**0.3727**、calf≈**0.2485**（我们现为均匀 0.25）。但**必须连同 `effort`/`stiffness` 一起对齐**——我们契约写 calf 33.5 N·m，mjlab 的 `KNEE_ACTUATOR.effort_limit` 是 35.55，属更深一层的物理参数收敛，需先定物理参数的真值源 |
| `mode` 字段口径 | schema 定义为"执行器控制模式（position/velocity/torque）"。实测 `g1`/`go2` 的 `by_role.mode = "torque"` 而其**动作项是位置控制**（`JointPositionActionCfg`）——若 `mode` 指动作类型则这两个值存疑；若指驱动器类型则需补文档说明。**待定口径** |
| `simulation/config.json` 里的 `action_scale*` 字段 | B5-2 后已**不再被读取**，但字段仍留在文件中。建议随迁移清理，避免后人误读为"还有一套" |
| `contract.json`（v2）文件本身 | 语义字段已全部收敛为派生/投影，但文件仍是手写的（含 URDF hash 等数据类字段）。彻底单轨需把 v2 变为 v3 的产物 |
| 质量数据本身的准确性 | `lite3` 的 `total_mass_kg = 6.252` 对一台 12-DoF 四足偏低（官方约 11~12kg）。派生 `size_class` 会忠实反映这个质量；若质量数据有误，应在**质量这一处**修正（这也正是单一家带来的好处：错只错一处、且立刻可见） |
