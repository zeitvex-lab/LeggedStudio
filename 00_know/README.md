> 产品文档在 [`../docs/`](../docs/)（面向使用者），资源库索引在 [`../00_resources/`](../00_resources/README.md)。

## 目录结构

```
00_know/
├─ 00_项目价值观.md          ← 最高裁决依据（V1–V10 + 裁决序 + 反面清单）
├─ 10_参考项目分析/           ← 外部项目深度分析与移植评估
├─ 20_调研盘点/               ← 本工作区资产与知识地图的盘点证据
├─ 30_参数标准/               ← 参数单一真值与机型来源对照（契约输入）
├─ 40_专题报告/               ← 逐专题的技术报告（契约收敛 / 准入 / 物理事实）
└─ 50_方案与清单/             ← 愿景 · 重构方案 · 可执行任务清单
```

> **编号前缀 = 阅读顺序**，不是优先级。`00_` 是总纲，`10_`–`50_` 是从「外部」到「内部落地」的推进。

## 维护约定

1. **新文档先归位**：按 §目录结构 放到对应编号目录；**不要放在 `00_know/` 根**（根只放总纲与索引）。
2. **代码里已有结论的不要再写一份文档**——文档负责「为什么」，代码负责「是什么」。
3. **结论类文档必须带日期与证据来源**；状态用实测口径（已完成 / 部分完成 / 未动），区分「本次实测」与「继承标注」。
4. **决策类文档必须写 `Alternatives Considered`**（被否决的方案 + 理由），否则不算决策文档（价值观 V10）。
5. **路径引用**一律以 `00_resources/<project>/…`（按项目组织）或 `assets/robots/<id>/…` 为准；不写旧的「按机型」路径。
6. **报告类只追加、不改写历史结论**；结论被推翻时新开一节说明，保留裁决链。
