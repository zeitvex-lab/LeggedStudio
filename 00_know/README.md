## 为什么变简洁了

问题从来不是"文档太多"，而是**过程记录与结论混在一起**，导致要查的结论被淹没：

| 原来 | 处置 |
|---|---|
| 任务清单单文件 **107 KB**（51 个已完成任务各自留着完整实现细节） | **已完成压成一行**（ID + 状态 + 关键落点 + 一句结论）；细节留给 git log 与代码注释。**"此路不通"的结论必须留** |
| **3 份讲同一件事**的参数文档（单一真值表 / 全部机型来源对照 / go1-go2-g1 三方对照） | 合并为 [`03_参数真值标准.md`](./03_参数真值标准.md)；三方逐参数过程表归档 |
| **2 份上游索引**（官方源对照清单 / 高级仿真参考资料切片） | 合并为 [`04_参考项目与资源.md`](./04_参考项目与资源.md) |
| **一次性快照与逐日流水**（本轮进展 / 进度流水 / 待你确定） | 「待你确定」并入 `01` 的待决事项；其余归档 |
| **B 系列专题报告**（B2/B3×3/B5/B8，已完成工作的过程记录） | 归档（结论已固化进代码、测试与 `03`） |
| **参考项目评估**（MATRiX / UniLab+motrixsim） | 归档（决策已下：不引用 / 已删除移植规划）；`04` §6 留索引 |
| **调研盘点**（资产总盘点 / 技术维度 / RL 知识地图） | 归档（盘点前提已变：`00_resources` 现为权威；知识地图属领域学习材料） |

## 一处"没动"的边界

**代码与门禁对文档路径有硬依赖**，移动文档时已同步（否则 `npm run check:docs` 会红）：

| 依赖方 | 内容 |
|---|---|
| `tools/doc_reality_check.py` | **8 个锚点**指向 `01_任务清单.md`（§0 现状锚点），1 个指向本文件（见下条维护规则 2） |
| `registry/motion_commands.json` | `evidence` 字段的路径 |
| `backend/test_asset_inspection.py`、`contracts/tests/test_physics_{binding,payload_view}.py` | 注释里的文档引用（已改指新路径与 `90_归档/`） |
| `tools/sync_resources.py` | 生成 `00_resources/README.md` 时的链接 |

## 维护规则（改文档前先读）

1. **数字必须有出处**：要么是工具实测（写明命令），要么是源码/资产路径。禁止"大概是"。
2. **对账措辞不要改**：本文件里的「更多参考项目（83 个）」被 `tools/doc_reality_check.py` 当锚点校验，改数字必须同步改实测值。
3. **一件事一个家**：参数真值只在 [`03_参数真值标准.md`](./03_参数真值标准.md)；任务只在 [`01_任务清单.md`](./01_任务清单.md)；上游依据只在 [`04_参考项目与资源.md`](./04_参考项目与资源.md)；决策只进 `01` 的待决事项。
4. **已完成的不堆细节**：已完成任务压成一行；**"此路不通"的结论必须留**（它比"做了什么"更省时间）。
5. **作废不删史**：文档作废移到 `90_归档/` 并在归档索引里说明原因（`git log --follow` 仍可追全文）。
