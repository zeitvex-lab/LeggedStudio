## 内容插件清单（2026-10-18）

文档身份由 [`_manifest.json`](./_manifest.json) 管理：`id` 稳定、`path` 可变、`aliases` / `renamed_from` 记录逻辑别名与历史名、`depends_on` 表达依赖。对应 dsh 的插件思想：**身份是 id，不是路径**。改名只改 manifest，仓库不保留旧文件。

- 校验：`npm run check:docs`（已含 manifest/链接检查）；单独跑：`npm run check:docs:manifest`
- 索引：`python tools/docs_manifest.py --index`
- 解析：`python tools/docs_manifest.py --where rl-survey`
- 工具引用：01–07 的 `tools` 数组是 `audit_tools_inventory` 的消费面；活跃文档正文不再被工具清单扫描。
- 改名流程：改 manifest 的 `path` → 旧名写入 `renamed_from` → 同步仓库内引用；不保留旧文件。

## 活清单与归档的边界

1. **活清单只留未完成行与生效裁决**：任务完成即压一行、结构性重排时整组进归档；"此路不通"的结论与用户裁决不随历史行失效（仍在 `05` §2.2 与定位/架构裁决块中生效）。
2. **归档只读、编号不动**：后续重排只新增归档编号，不改旧档；代码注释与历史讨论按行号（A1…U9）或笔号（第 N 笔）引用时，去处是 08/09。
3. **逐轮明细一律 git log**：流水不再在活清单累积。
4. **工具跟着走**：N6 可查性门禁与任务计数统计的扫描面 = `05` + 归档 08；工具孤儿检测的语料面 = `_manifest.json` + 本索引 + 归档 08/09 + 代码/测试——新增归档时同步这三个工具。

## 维护规则（改文档前先读）

1. **数字必须有出处**：要么是工具实测（写明命令），要么是源码/资产路径。禁止"大概是"。
2. **对账措辞不要改**：本文件末尾「更多参考项目」的计数被 `tools/doc_reality_check.py` 当锚点校验（正则 `更多参考项目（N 个）`，取文件内首个匹配）——别在本说明行里写出同样的字面句式；改数字必须同步改实测值。
3. **一件事一个家**：参数真值只在 [`04`](./04_参数真值标准.md)；任务状态只在 [`05`](./05_任务清单.md)（历史在归档）；上游依据只在 [`03`](./03_参考项目与资源.md)；落地方案与阶段计划只在 [`02`](./02_项目规划.md)；统一边界与插件协议只在 [`06`](./06_统一架构方案.md)。
4. **已完成的不堆细节**：已完成任务压成一行；"此路不通"的结论必须留。
5. **作废不删史**：文档作废移到 `90_归档/` 并在归档头部说明原因；归档时同步上面的三个工具。
