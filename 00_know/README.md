## 活清单与归档的边界（2026-09-28 起生效）

1. **活清单只留未完成行与生效裁决**：任务完成即压一行、结构性重排时整组进归档；**"此路不通"的结论与用户裁决不随历史行失效**（仍在 `05` §2.2 与定位/架构裁决块中生效）。
2. **归档只读、编号不动**：后续重排只新增归档编号（10、11…），不改旧档；代码注释与历史讨论按行号（A1…U9）或笔号（第 N 笔）引用时，去处是 08/09。
3. **逐轮明细一律 git log**：流水不再在活清单累积（09 号归档是最后一批）。
4. **工具跟着走**：N6 可查性门禁与任务计数统计的扫描面 = `05` + 归档 08；工具孤儿检测的语料面含两份归档——**再归档新内容时必须同步这三个工具**（见下表）。

## 维护规则（改文档前先读）

1. **数字必须有出处**：要么是工具实测（写明命令），要么是源码/资产路径。禁止"大概是"。
2. **对账措辞不要改**：本文件末尾那行「更多参考项目」的计数被 `tools/doc_reality_check.py` 当锚点校验（正则 `更多参考项目（N 个）`，取**文件内首个匹配**）—— **别在本说明行里写出同样的字面句式**；改数字必须同步改实测值。
3. **一件事一个家**：参数真值只在 [`04`](./04_参数真值标准.md)；任务状态只在 [`05`](./05_任务清单.md)（历史在归档）；上游依据只在 [`03`](./03_参考项目与资源.md)；落地方案与阶段计划只在 [`02`](./02_项目规划.md)；统一边界只在 [`06`](./06_统一架构方案.md)；决策只进 `05` 的待决事项。
4. **已完成的不堆细节**：已完成任务压成一行；**"此路不通"的结论必须留**（它比"做了什么"更省时间）。
5. **作废不删史**：文档作废移到 `90_归档/` 并在归档头部说明原因（`git log --follow` 仍可追全文）；**归档时同步第 4 节表格里的三个工具**。
