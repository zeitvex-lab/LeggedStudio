## 0. 如何读这份综述

### 0.1 这份综述回答什么

腿足强化学习看起来是一堆算法、仿真器和框架的集合，实际是一条工程链：

```text
任务与评价
  → 仿真与 MDP（观测/动作/奖励/终止/命令/课程/DR）
  → 学习算法与策略表示
  → 训练系统（并行/预算/日志/复现）
  → 导出与部署（图边界/契约/执行器/延迟/安全）
  → 数据、资产与许可
```

**算法只是中间一层。** 这条链上任何一段错位，都会表现为“算法不work”：观测错序、动作缩放不对、PD 不匹配、历史长度漂移、相机投影口径不同，都会让一个在仿真里正常的策略在另一端失效。

本综述按“形态 × 能力 × 证据”组织，而不是按算法名字罗列。阅读顺序建议：

- 想快速判断一个项目/论文值不值得跟进：看 §0.2 证据分级与 §9 横向证据。
- 想做四足/轮足：看 §2（MDP）、§5（部署）、§6/§7。
- 想做或理解人形：看 §8。
- 想搭一条新流水线：直接看 §10.3 检查表。

### 0.2 证据分级

| 级别 | 标准 | 能支持什么结论 |
|---|---|---|
| **A** | 训练代码 + 配置 + 导出/部署物齐全，关键常量可核对 | “这套做法被实际实现并可复现” |
| **B** | 有训练代码/配置，但缺产物、评测或部署链 | “这套做法存在”，不能证明效果 |
| **C** | 只有 README/论文声明，或快照缺训练代码/依赖 | 只能作机制参考，不能当实现证据 |

本综述所有“强结论”尽量给 A 级证据；B 级只用于说明存在性；C 级只用于方向参考。快照不完整的情况在 §9.3 单列——**目录名不等于上游能力**。

### 0.3 坐标系：形态 × 能力 × 证据

| 形态 | 主要能力 | 典型 DoF | 关键约束 |
|---|---|---|---|
| **四足** | 速度跟踪、地形、感知跑酷、特技 | 12 | 步态/接触、足端几何、地形课程 |
| **轮足** | 速度/全向、越障、站立、轮轴姿态 | 16（12 腿 + 4 轮） | 腿轮协调、轮地接触、轮速尺度 |
| **人形** | 全身跟踪、行走/跑跳、操作 | 23–29（或 12 仅腿） | 平衡、手/膝/躯干接触、参考动作、安全 |

同一能力在不同形态上的难点不同。例如“速度跟踪”对四足是步态与接触，对轮足是轮速分配与轮地滑移，对人形是平衡与全身耦合。**不要把四足的经验直接平移到人形**，也不要把人形的“全身跟踪”当成四足的“跑酷”。

### 0.4 主要结论（先看这六条）

1. **PPO 是足式速度跟踪/盲走的工程默认，但不是唯一方法。** 抽样中 15+ 项目重复同一组 PPO 超参；同时存在 APPO、SAC/TD3、FB/TeCH、采样 MPC 等替代。
2. **教师-学生是感知任务的常见工程方案，不是普遍规律。** 本地可核对的实现有五种；PIE 用单阶段 Transformer 也成立。
3. **AMP 是奖励层，不是性能保证。** 代码能证明判别器和权重存在，不能证明“用了 AMP 就更好”；本地没有同预算对照。
4. **MoE 的证据有限。** 只有两条同源分支（Go2 系），无真机证据；不宜写成行业趋势。
5. **MPC/WBC 是独立控制层，不是 PPO 的替代品。** 本地没有真正的 RL+MPC 混合系统；`legged_mpc_amp` 是 AMP 数据生成器，不是 RL 训练。
6. **Sim2real 的第一道关常常是契约漂移，而不是动力学误差。** 历史长度、关节序、动作缩放、PD、相机投影，比“模型不够准”更常见。

### 0.5 三层证据：综述、经典论文、本地项目

这份综述现在引用 22 篇综述与 33 条经典论文线。它们不是同一层证据：

| 层 | 数量 | 回答什么 | 不能证明什么 | 入口 |
|---|---:|---|---|---|
| A 跨域方法/审计综述 | 11 | 审计框架：奖励、训练环、环境设计、长时序 | 腿足实现与效果 | §11.1.1 |
| B 腿足/人形子方向综述 | 11 | 子方向地图：人形控制、MPC、感知、IL、BFM | 具体论文的效果 | §11.1.2 |
| C 经典论文线 | 33 条（34 篇） | 原始方法与工程节点：ETH / KAIST / 四足 / WBC / 人形 | 本仓可复现 | §11.2 |

## 1. 问题空间

### 1.1 任务与能力

| 任务族 | 目标 | 代表能力 | 主要难点 |
|---|---|---|---|
| 速度跟踪 | 按命令走/转/侧移 | velocity、trot、omni | 命令分布、步态、跟踪与平滑 |
| 复杂地形 | 碎石、台阶、斜坡、沟壑 | rough、stairs、traversal | 地形课程、接触、高度感知 |
| 感知运动 | 看见再走 | parkour、避障、跨沟 | 深度、延迟、教师-学生 |
| 特技 | 跳、后空翻、站姿 | jump、backflip、handstand | 参考轨迹、安全课程、落地 |
| 模仿/跟踪 | 像参考动作一样运动 | motion tracking、AMP | 数据、重定向、关节序 |
| 全身控制 | 人形全身协调 | whole-body tracking、loco-manipulation | 高 DoF、平衡、接触语义 |
| 任务组合 | 导航、巡检、操作 | 策略 + 规划/感知 | 分层接口、失败恢复 |
| 通用策略 | 一个策略多技能/多机型 | multi-skill、generalist | 数据覆盖、容量、任务冲突 |

### 1.2 形态差异

| 形态 | 典型 DoF | 动作接口 | 关键难点 | 证据成熟度 |
|---|---:|---|---|---|
| **四足** | 12 | 关节位置 + PD | 步态/接触、地形、盲走到感知 | 最高，项目最多 |
| **轮足** | 16 | 腿位置 + 轮速 | 腿轮协调、轮地接触、站立/全向 | 细分，可复现项目少 |
| **人形** | 23–29 | 全身关节位置 + PD | 平衡、接触、参考动作、安全 | 进展快，但本地证据集中在少数项目 |

四足和轮足的核心是“接触时序 + 机身稳定”；人形的核心是“全身平衡 + 参考动作 + 多接触点”。这决定三者的观测、奖励、终止和部署契约都不同。

### 1.3 评价：指标、预算与可比性

当前腿足 RL 的评测有几个结构性问题：

- **预算差三个数量级。** 本地项目从约 `1.5e8` 到 `1.2e11` env steps；env 数从 2048 到 16384；评测时长从 3 s 到 20 s 不等。
- **观测/动作不可互喂。** 45、270、450、705、756 维并存；动作 scale 0.25 vs 0.5；历史 1/5/6/10/15 帧；还有深度 + GRU/Transformer。
- **指标定义不统一。** 跟踪误差有的除以命令幅值、有的除以命令上限；总 reward、episode length、fall rate 常混用；CoT、力矩平滑、动作饱和多数项目不报。
- **统计不足。** 多数项目单 seed；质量矩阵的重复实验在 DR 关闭时方差结构性为 0。
- **评测工具分工不同。** 本仓 `sim2sim_headless` 是 3 s/条、5 条指令的快速回归；`check_user_criteria` 是 8 s、4 条指令的判据；`quality_matrix` 是 64 envs × 400–800 iter；`effect_criterion` 有 7 档但 5/7 尚无观测值。它们不是同一把尺子。

**结论：当前没有跨项目可比的统一 benchmark。** 任何“某策略 0.9”“某方法提升 X%”的数字，必须先看 metric card：任务/指令分布、obs 布局、动作 scale、控制频率、地形、episode 上限、seed 数、训练预算、评测 horizon、成功定义、聚合方式。

一个可用的 metric card 至少应包含：

| 项 | 内容 |
|---|---|
| 任务 | 指令分布、地形、episode 上限 |
| 观测 | 维度、布局、历史长度/方向、归一化 |
| 动作 | 接口、scale/offset/clip、PD、控制频率 |
| 训练 | env 数、总 env steps、算法、超参、seed |
| 评测 | horizon、成功定义、fall rate、跟踪归一方式 |
| 产物 | commit、ONNX/MJCF 哈希、evaluator 版本、原始日志 |

## 2. MDP：真正决定行为的一层

### 2.1 观测

本地项目里最稳定的工程惯例是 **Go2 系的 45 维本体观测**：

```text
ang_vel(3) + gravity(3) + command(3) + joint_pos(12) + joint_vel(12) + last_action(12) = 45
```

在此基础上：

- **轮足** 加 12 个轮相关量，常见 57 维；
- **特技** 加相位特征，常见 60 维；
- **人形** 常用 47 维 × 历史（如 15 帧、47×15=705），或 45 维 × 历史；
- **感知跑酷** 加高度扫描/深度，观测可到 756 维。

观测的 **缩放** 也是事实契约的一部分。常见值：

| 项 | 常见 scale |
|---|---|
| 角速度 | 0.25 |
| 重力投影 | 1.0 |
| 命令 | 2 / 2 / 0.25（Go2 系）；也有 1 / 1 / 1 |
| 关节位置 | 1.0 |
| 关节速度 | 0.05 |
| 动作 | 上一帧动作直接拼接 |

历史有两种归属：**环境维护**（观测里已经是 N 帧）和 **导出器维护**（策略只吃单帧，历史在 TorchScript/ONNX 内部滚动）。两者都常见，但部署契约必须写清是哪一种；否则“训练 10 帧、部署 5 帧”这类漂移会静默发生。

### 2.2 动作

最常见的是 **默认角 + scale × 网络输出**：

```text
q_des = q_default + action_scale * a
```

- Go2 系常见 `action_scale=0.25`，PD 20/0.5；
- 髋关节常单独降到 0.125；后空翻等特技会用 0.5、PD 40/1；
- 轮足的动作由 **腿位置 + 轮速** 组成，轮速 scale 在 2 / 5 / 10 / 20 / 35 之间变化（取决于轮半径、减速比和训练配方）；
- 人形常用逐关节 scale，髋/膝/踝不同；
- 也有力矩、残差、末端空间接口，但在腿足低层控制里不是主流。

动作 scale 是最容易被复制错的字段。它同时影响探索幅度、力矩上限和 sim2real 行为；不能从别的机型直接照搬。

### 2.3 奖励

腿足奖励通常是四类之和：

| 类别 | 作用 | 常见项 |
|---|---|---|
| 任务 | 完成目标 | 速度/位姿跟踪、到达、目标链 |
| 正则 | 抑制坏行为 | 力矩、动作率、关节加速度、足滑、碰撞、姿态 |
| 风格/先验 | 像参考动作 | AMP 判别器、参考关节/连杆跟踪、相位条件 |
| 接触/步态 | 约束接触时序 | 足端接触、步态相位、轮轴对齐、站立抑制 |

跟踪奖励常见形式是 `exp(-e²/σ²)`（σ≈0.25），但“总 reward 高”不等于“走得好”。**奖励是优化目标，指标是验收口径**，两者必须分栏：

- 训练时看逐项 reward、KL、entropy、value loss、episode length、动作饱和；
- 验收时看跟踪误差、fall rate、survival、CoT、力矩/动作 RMS、最小净空；
- 不要用总 reward 跨项目比较。

### 2.4 终止、命令与课程

终止通常包括：摔倒、躯干触地、超时、出界、接触异常。人形还会加：锚点偏移、keybody 触地力超限、姿态角超限。

命令与课程常见三件套：

1. **命令范围课程**：从小范围逐步扩到目标范围（常见 20k/50k iter 两段）。
2. **零命令概率课程**：逐步增加站立/零速样本，防止“只会跑不会停”。
3. **地形/扰动课程**：地形等级、推力、延迟逐步加。

课程的关键不是“有没有”，而是 **单轴可解释**：一次只动一类，才能判断是哪一个在起作用。

### 2.5 域随机化

本地项目最一致的 DR 模板是：

| 项 | 常见范围 |
|---|---|
| 摩擦 | 0–2 |
| 基座质量 | ±1 kg |
| 连杆质量 | ±10% |
| COM | ±3 cm |
| PD | ±10% |
| 电机强度 | 0.8–1.2 |
| 零位 | ±0.035 rad |
| 推力 | 周期性外力 |
| 动作延迟 | 0–20 ms（0–4 个物理子步） |

推荐的 DR 顺序是：

```text
clean baseline
  → dynamics（质量/惯量/摩擦）
  → actuator（力矩/带宽/延迟）
  → perception（噪声/遮挡/深度）
  → pushes（外力）
  → robustness（组合）
```

一次只动一类。DR 范围应尽量由 SysID 推得；没有辨识的宽 DR 常常只是“更难的随机任务”，不是“更真实的机器人”。

### 2.6 执行顺序与跨端一致性

Manager-Based MDP 里，执行顺序有语义：

- termination 先于 reward（终止步仍计分）；
- reset 后算 obs（新 episode 首帧正确）；
- reward 在 `sim.forward()` 前（读到的派生量差一个子步）；
- command 先于 obs（观测与奖励一致）。

跨端一致性是硬约束：观测布局/顺序、动作缩放、PD、控制频率、normalizer、关节序，在训练 / sim2sim / ONNX / 真机必须同一份。ONNX 通常只含 actor 图；观测缩放、历史、命令生成、动作解码、安全 FSM 都在图外。

### 2.7 证据小结

**稳定惯例**（多项目重复，可作为起点）：50 Hz 控制、45 维本体观测、`q_default + 0.25a`、PPO 超参、DR 模板、命令/地形课程。

**真实分歧**（不能当标准）：观测顺序（角速度在前/命令在前）、历史长度与方向、动作 scale（0.125/0.25/0.5）、PD（20/0.5 vs 40/1 vs 50/1.5）、轮速 scale（2/5/10/20/35）、深度相机参数。

## 3. 学习算法：按层拆，不按名字

### 3.1 五个轴

| 层 | 回答什么 | 例子 |
|---|---|---|
| 学习信号/优化目标 | 用什么损失去更新 | PPO、SAC、BC、AMP、model-based RL |
| 模型族 | 策略/表示用什么概率模型 | Gaussian policy、VAE、GAN、diffusion、autoregressive |
| 网络组织 | 计算图怎么连 | MLP、CNN、RNN、Transformer、MoE |
| 系统角色 | 网络在系统里干什么 | policy、critic、estimator、world model、discriminator |
| 训练方案 | 数据怎么来、怎么更新 | on-policy、off-policy、teacher-student、DAgger |

同一张表只放同一层。VAE 是模型族，MoE 是网络组织；它们可以组合，但不是同类。

### 3.2 PPO：默认，但有边界

PPO 之所以成为默认，不是因为它“最强”，而是因为：

- 连续动作 + 高斯策略，天然匹配关节控制；
- clip 限制更新幅度，几千个并行环境也不容易崩；
- on-policy、无 replay，隐藏状态少，复现简单；
- 仿真步便宜，sample-hungry 不是问题。

本地项目里反复出现的超参是：

```text
24 steps/iter · 5 epochs · 4 minibatches · clip 0.2
γ 0.99 · λ 0.95 · lr 1e-3 · hidden 512/256/128 · ELU
```

但 PPO 的“默认”只适用于 **足式速度跟踪/盲走** 这类任务。抽样中同时存在：

- **APPO**（异步 PPO + V-trace，`unilab_new`）；
- **SAC/TD3/FastSAC**（`unilab_new`）；
- **FB/TeCH**（`UFO`，无监督 + 测试时任务指定）；
- **采样 MPC**（`dial-mpc`，training-free）；
- **AMP-PPO / CTS** 等组合。

更准确的说法是：**PPO 是工程基线，不是唯一方法；算法选择应由信息结构决定，而不是由流行度决定。**

### 3.3 Teacher-student / estimator：五种实现

教师-学生不是一种算法，而是一组训练方案。本地可核对的实现有五种：

| 实现 | 核心 | 代表 | 证据 |
|---|---|---|---|
| 并发 CTS | 教师/学生同环境，按比例分环境，共享 actor-critic | `go2_rl_gym`、`go2_rl_robotlab`、`legbot`、`LainLab` | A |
| HIM | 时序编码器 + 原型/Sinkhorn，估计特权状态 | `HIMLoco` | A/B |
| DreamWaQ | CENet/VAE 从本体历史估计 belief | `Dreamwaq`（M20、Go2） | A/B |
| 世界模型 | 用世界模型/对比学习学地形表示 | `MGDP` | B |
| 双编码器 + DAgger | 本体/扫描/深度分别编码，DAgger 蒸馏 | `extreme-parkour` | A |

**反例**：`parkour_mjlab` 的 PIE 用单阶段 Transformer + 辅助解码（map/VAE latent、successor/height 辅助损失），不需要显式教师。这说明“感知跑酷必须教师-学生”并不成立；教师-学生是降低样本复杂度的一种手段，不是唯一路径。

### 3.4 AMP：奖励层，不是性能保证

AMP 的机制是：判别器区分“参考动作”和“策略动作”，把判别器输出变成奖励项，再与任务奖励做 lerp。

本地证据：

- `AMP_mjlab`（G1）：`amp_reward_coef=0.1`、task lerp 0.75、判别器 1024/512/256、17 条 CSV 动作；
- `beyondAMP`（G1）：判别器奖励 `coef * clamp(1-0.25(d-1)²)`，与任务奖励 lerp（示例 0.3）；
- `LainLab`：AMP 经验池、判别器、Go2 的 AMP 数据；
- 四足 AMP 的完整训练证据很少，现有完整实现主要在人形。

**能写的结论**：AMP 是一种可组合的奖励塑形方法，权重和特征设计差异很大。**不能写的结论**：AMP 一定提升风格/性能——本地没有同预算对照。

### 3.5 MoE：证据有限的容量方案

本地 MoE 只出现在两条同源分支：

- `go2_rl_gym` 的 `moe_cts` 等变体；
- `go2_rl_robotlab` / `legbot` 的 MoE-CTS：8 专家、latent 32、teacher ratio 0.75、负载均衡损失。

门控输入刻意去掉命令，专家是学生编码器的一部分，不是“多个策略集成”。**本地没有真机证据，也没有与同参数 MLP 的同预算对照**。因此 MoE 可以作为一个“容量扩展/专家分工”的候选，但不能写成行业趋势。

### 3.6 Motion tracking：四条路线

| 路线 | 机制 | 代表 | 数据要求 |
|---|---|---|---|
| AMP | 判别器奖励 | `AMP_mjlab`、`beyondAMP`、`LainLab` | 参考动作片段 |
| BeyondMimic 式跟踪 | 参考关节/连杆位姿 + RSI | `wbc-mjlab`、`unitree_rl_mjlab`、`InstinctMJ` | 重定向后的动作 |
| DeepMimic + MPC | 参考模型 + 关节/根跟踪 | `motion-imitation` | 狗 mocap |
| 相位条件 | sin/cos 相位 + 目标姿态 | `GO2_backflip` | 无需 mocap |

这四条路线解决的是不同问题：AMP 学风格，跟踪学具体动作，相位条件学周期特技，DeepMimic 是最早的模仿框架。不要把“用了 AMP”与“会做动作跟踪”混为一谈。

**经典论文补线（awesome list）**：Barrier-Based Style Rewards（ICRA 2025）用 relaxed log-barrier 形状奖励，在无 mocap 条件下得到 bounding/trotting 等步态；Adversarial Imitation of Rough Partial Demonstrations（CoRL 2023）说明粗糙/不完整示范也能加速后空翻等动态技能；Lifelike Agility（Nature MI 2024）把生成式动物运动先验作为预训练。三者分别对应“奖励塑形 / 部分示范 / 生成先验”，不要都归到 AMP。

**LoCoWiki 补编**：`amp_go2`（Go2 AMP）、`smp`（冻结扩散模型运动奖励，G1）、`TWIST`（G1 遥操作/教师-学生）已入库；`smp`/`TWIST` 属人形，不替代四足 AMP 证据。

### 3.7 Model-based RL 与 MPC/WBC：控制层

MPC/WBC 不是 RL 算法，而是控制层：

| 项目 | 形式 | 频率/时域 | 许可 |
|---|---|---|---|
| `legged_control` | OCS2 NMPC + WBC | NMPC 100 Hz / 1 s；WBC 500 Hz | BSD-3 |
| `legged_mpc_control` | SRB 凸 MPC + CI-MPC | 100 Hz / 30 节点 | GPL-3.0 |
| `legged_perceptive` | NMPC + 高程图/凸平面 | 100 Hz / 1 s | 无独立 LICENSE |
| `dfki-quad` | acados LTV-SRB + TSID | MPC 100 Hz / 0.5 s；WBC 500 Hz | BSD-3 |
| `quaternion-mpc` | ALTRO 四元数 MPC | 200 Hz 主循环 | AGPL-3.0 |
| `dial-mpc` | 采样 MPC（MPPI + 退火） | 50 Hz | Apache-2.0 |
| `wbc-mjlab` | **学习式**全身跟踪（PPO） | 50 Hz | Apache-2.0 |

**关键区分**：`wbc-mjlab` 的 WBC 是“用 RL 学全身跟踪”，不是模型式 WBC。模型式 WBC 是带浮动基动力学、摩擦锥、力矩约束的 QP；两者不能混写。

本地没有真正的 RL+MPC 混合系统。唯一的成链混合是 `legged_mpc_amp`：用 NMPC/WBC 采数据，转成 AMP 训练数据；它不是 RL 训练器，也不是在线混合控制器。

MPC 的价值在于：接触时序、质心/单刚体动力学、摩擦/力矩约束、可解释性。它的代价是：需要模型、状态估计、步态表、逐机调参和实时栈；Windows/ROS 生态也限制部署。**它不能替代语义/地形理解，也不能替代无先验接触序列的高动态技能发现。**

**子方向综述的校准（B7/B8）**：B8 按“动力学模型 → MPC 算法 → 降阶到全身应用”组织，指出降阶模型（如 SLIP/SRB）与全身模型（浮基多刚体 + 接触力）之间的桥接仍是工程核心；B7 把 VMC、MPC、model-free RL 放在同一比较框架里，结论是任务/模型/实时性约束下的分工，而不是“谁替代谁”。这与本仓的边界一致：MPC/WBC 是控制层，RL 是策略层；本地仍没有真正的在线 RL+MPC 混合系统。

**LoCoWiki 补编**：`rl-mpc-locomotion`（高层策略 + 低层 MPC）、`Cheetah-Software`、`A1-QP-MPC-Controller` 已入库；三者都是控制层参考，不能据此声称本仓具备在线混合控制器。

### 4.2 并行与预算

- 四足项目常见 4096–16384 envs；人形常见 1024–4096；轮足 2048–4096。
- 预算从约 `1.5e8` 到 `1.2e11` env steps；不写预算的“更好”没有意义。
- PPO 超参高度同构（见 §3.2），但不同框架的 `num_steps_per_env`、minibatch、epoch 可能不同；跨框架比较要先对齐。

### 4.3 复现与诊断

最少记录：

| 项 | 为什么 |
|---|---|
| commit / 配置快照 | 否则无法复现 |
| seed / env 数 / 总 steps | 可比性 |
| 观测布局 / 动作 scale / PD | 行为解释 |
| 课程/DR 调度 | 难度解释 |
| 逐项 reward / KL / entropy / value loss | 诊断 |
| episode length / fall rate / 动作饱和 | 行为 |
| ONNX / MJCF 哈希 / evaluator 版本 | 部署复现 |

**固定病象**：reward hacking、suicide policy（学会快速终止）、课程台阶、慢性退化、动作饱和。先看逐项 reward 和回放，不要只看总曲线。

## 5. Sim2real 与部署

### 5.1 图边界

“导出 ONNX”不是一件事，至少要回答：

| 边界 | 选项 | 影响 |
|---|---|---|
| actor-only | 只导策略 | 观测缩放/历史/命令在外部 |
| actor + encoder | 视觉/估计器分开 | 两个 ONNX、两套输入 |
| actor + memory | GRU/LSTM 的 hidden/cell 外部传入 | 需要状态管理 |
| normalizer | 进图/不进图 | 不进图则部署侧必须复刻 |
| reset | 导出/不导出 | 首帧历史清零 |
| metadata | 关节名/默认姿/增益/动作维 | 部署校验 |

本地最佳实践是 `parkour_mjlab` 的启动期 ONNX 形状 + metadata 全量校验，以及 Go2W 的 dummy inference 门禁。**“用 ONNX”本身不构成可部署证据。**

### 5.2 契约

| 项 | 为什么 |
|---|---|
| 观测布局/顺序/缩放 | 错序会静默变差 |
| 历史长度/方向（term-major vs time-major） | 同一维度、不同语义 |
| 动作 scale/offset/clip | 直接影响力矩/步态 |
| PD 增益/控制频率 | 决定跟踪与稳定性 |
| 关节名/关节序/映射 | 换端必错 |
| 默认姿/初始状态 | 影响 reset 与站立 |
| 相机投影/深度口径 | optical Z vs ray distance |
| 安全限幅/FSM | 防摔/防烧 |

**观测 actor 层真值（2026-10-19）**：族骨架 actor = `base_ang_vel / projected_gravity / commands / joint_pos / joint_vel / last_action`（四足 45、轮足 57）；`base_lin_vel` 只进 critic。generic 默认回退与 Kit 同序；旧 47/48/53/69 宽策略须在 `registry/observation_legacy_policies.json` 逐条登记，新策略不再允许静默偏离。门禁：`tools/audit_observation_parity.py`（verify 清单）。

### 5.3 已证实的契约漂移

以下是本地能指认的例子（不是传闻）：

- `go2_rl_gym` 同一策略在 MuJoCo 与真机的命令缩放不同：`[2,2,0.25]` vs `[3,2,0.5]`；真机另有 `joint2motor_idx=[3,4,5,0,1,2,9,10,11,6,7,8]`。
- `go2_rl_robotlab` 训练 history=10，部署 YAML 写 5；实际推理只喂单帧，历史在 TorchScript 内维护——这是“配置漂移”，不是“模型真的只用 5 帧”。
- `Dreamwaq` 训练 5 帧，部署脚本硬编码 6 帧。
- `go2w_sim2sim` 的指南、`student_deploy.json` 与代码对输入维度/历史/图像帧数的描述不一致（729 vs 629；265 vs 3609）。
- `parkour_mjlab` 的 PIE 把 MuJoCo 光学 Z 转成射线距离再裁剪/归一化；同仓 V6 不做转换，且用 8 个时间偏移通道。
- `LainLab` 迁移矩阵记录 MJCF 大腿盒尺寸、缺失小腿碰撞、armature、头部 geom 误判为基座接触；PIE 在运行时注入 armature/增益，说明 MJCF 本身不是完整契约。
- `go2w_sim2sim` 的 MJCF 关节声明顺序与 `<actuator>` 顺序不一致，`ctrl` 按下标直写。

**结论**：部署前先做契约对拍，再谈调参。很多“sim2real gap”其实是契约 gap。

### 5.4 执行器、延迟与 SysID

本地实际有的：

- `go2_rl_gym` 在 decimation 内随机 0–4 子步混用旧动作（0–20 ms），并随机化电机强度；
- `LainLab` 迁移表记录动作延迟 1–3 物理子步，并明确没有建模子步传感器延迟；
- `rl_sar` 有离线执行器网络拟合脚本（6→32×2→1 MLP），但 C++ 部署侧没有加载路径；
- `legbot` 的串口网关以 500 Hz 下发 `q/dq/kp/kd/tau`，固件做 `τ=τ_ff+kpΔq+kdΔdq`；
- `sdk_deploy` 的 `PostureUnsafeCheck()` 被整体注释、恒返回 false；`rl_sar` 的 `TorqueProtect/AttitudeProtect` 也被注释。

**不能写的结论**：本地已做 T-N/带宽/SysID/在线适应并用于部署。实际只有延迟随机化、离线拟合脚本和迁移表；没有部署期执行器网络或完整 SysID 流程。

### 5.5 安全

安全层至少包括：

- 关节/力矩/速度限幅；
- 姿态/高度保护；
- FSM（Passive / FixStand / Velocity / Mimic）；
- 跌倒恢复；
- 通信超时/零指令；
- 日志与回放。

本地有的正例：`legbot` 的 `deploy_safety.h` 有位置/力矩/速度/姿态/温度限制；Go2W 有深度超时预算、无 lowstate 时零指令、动作维不足时零指令。
本地有的反例：`sdk_deploy` 的姿态检查被注释；`rl_sar` 的力矩/姿态保护被注释；跌倒恢复只有插值，不是学习式恢复。

### 5.6 sim2sim 能抓什么、不能抓什么

**能抓**：观测顺序、动作缩放、关节重排、历史布局、深度投影、metadata 缺失、动作维度不匹配。

**不能抓**：电机带宽、T-N 曲线、通信抖动、接触刚度、真实延迟分布、状态估计误差。

所以 sim2sim 是 **契约测试**，不是 sim2real 的充分证明。部署验收应分级：

```text
sim2sim → replay → 影子模式 → 低增益正弦 → 现场
```

本地很多项目只走到 sim2sim；不要把“sim2sim 过了”写成“可上机”。

### 6.5 开放问题

- 第二台四足的感知跑酷仍缺（相机声明/标定）。
- 四足 AMP 的完整训练证据少；现有 AMP 实现主要在人形。
- 评测仍以 sim2sim 和单 seed 为主；缺跨项目 benchmark。
- 契约漂移（关节序、历史、命令缩放）比动力学误差更常见。
- **感知运动的综述校准（B9）**：B9 系统梳理真实世界感知足式运动，核心是感知/状态估计与控制的耦合、以及真实部署证据，而不是“有深度相机就会跑酷”。本仓对应证据是 `parkour_mjlab`（PIE 单阶段）与 `InstinctMJ`（感知 VAE/parkour AMP，CC BY-NC）；`extreme-parkour` 仅只读参考；`legged_perceptive` 是模型式 NMPC + 高程图，不是学习式感知策略。不要把三者混为同一证据等级。
- **建图线（awesome list）**：Elevation Mapping（IROS 2022）把 GPU 局部高程图作为独立感知子系统；上游明确指出 odometry drift 仍是实时建图的最大挑战。不要把“有高程图/深度相机”当成“地图与里程计已验收”。

## 7. 轮足

### 7.1 16-DoF 的动作与奖励

轮足常见 12 个腿关节 + 4 个轮电机，动作拆成：

```text
腿：q_des = q_default + scale_leg * a
轮：wheel_vel = scale_wheel * a
```

轮速 scale 在 2 / 5 / 10 / 20 / 35 之间变化；腿 scale 常见 0.125–0.5。PD 也因项目而异（腿 20/0.5、50/1.5；轮 kp0/kd0.5 或 kp0/kd0.6）。

奖励分层：

- 速度/朝向跟踪；
- 轮速跟踪（`wheel_roll_tracking`）；
- 轮轴对齐（toe/camber）；
- 零命令站立（腿姿 + 轮速归零）；
- 轮地滑移/能耗；
- 腿轮协调。

### 7.2 经典线与能力边界（awesome list）

**节点论文**：Multiple AMP（ICRA 2023）在轮足平台上演示双足/四足姿态切换；Curiosity-Driven（CoRL 2023）把轮足 loco-manipulation 当作探索问题。两者说明轮足技能不只有速度跟踪，但本仓轮足矩阵仍以 velocity/traversal 为主，不能把这两条当成已落地的轮足能力。

**LoCoWiki 补编**：`HIMLoco-for-Go2W`（Go2W 训练 + MuJoCo 验证）、`RC_WheelLeg`（自研轮足 ROS 2/RL 工程）已入库；先按 16-DoF 动作/轮速契约复核，不直接当能力证据。

### 7.3 代表项目与证据

| 项目 | 内容 | 证据 |
|---|---|---|
| `legbot_lab_WF-CTS-MOE` | 57×4 obs、16 动作按腿交错、轮速 scale 20、轮轴/站立奖励、部署断言 | A |
| `unitree_rl_mjlab_go2w` | 腿 0.5、轮 35、轮半径 0.09/轮距 0.19、6 个任务、部署一致性测试 | A |
| `UniLab go2w` | 腿 0.5、轮 10、kp50/kd1.5、轮 kd0.5、SAC/APPO/HIM-PPO | A/B |
| `rc_old` | 53×6 obs、轮 5.0、HIM-PPO、ONNX | B |
| `Dreamwaq M20` | 57 obs、5 历史、轮 kp0/kd0.6 | A/B |
| `go2w_sim2sim` | 纯部署；metadata 不一致 | C（部署参考） |

### 7.4 开放问题

- 轮地接触/滑移建模仍弱；轮速延迟与轮半径误差直接影响跟踪。
- 站立/全向/越障多模式缺统一技能矩阵。
- 轮足几乎没有 mocap/动作数据；模仿/AMP 证据稀薄。
- 评测比四足更少，跨项目可比性更低。

## 8. 人形

### 8.1 为什么是当前投资主线

人形的产业投入集中在整机、关节/执行器、场景与数据。公开技术资料里，运动控制主线是 **RL + 运动跟踪 + 全身控制**；但“公司是否用 RL、用到什么程度”披露有限，产业信号不能当技术证据。

代表机型/公司包括 Unitree G1/H1、Boston Dynamics Atlas、Tesla Optimus、Figure、Agility Digit、傅利叶、优必选 Walker、小鹏 IRON、EngineAI PM01 等。这里只把它们当产业信号，不推断其内部算法。

### 8.2 技术路线

| 路线 | 核心 | 代表 | 证据 |
|---|---|---|---|
| 步态先验/速度 RL | 相位 sin/cos + 步态奖励 | `humanoid-gym`、Link-U A2 | A |
| 运动跟踪/模仿 | 参考关节/连杆 + RSI | `unitree_rl_mjlab`、`wbc-mjlab`、`InstinctMJ` | A |
| AMP | 判别器奖励 | `AMP_mjlab`、`InstinctMJ` parkour | A/B |
| 教师-学生/感知 | 特权/深度教师 → 学生 | `InstinctMJ`、`unilab` HORA/HIM、Link-U 长历史 | A/B |
| 通用/多技能 | 一策略多动作/隐变量条件 | `UFO` FB/TeCH、`wbc-mjlab` 多段 | A/B |
| RL + MPC/WBC | 模型控制/全身控制 | 本地无真正混合系统 | C |
| VLA/基础模型 | 视觉-语言-动作 | `WholebodyVLA` 等外部 | C |

**本地没有真正的 RL+MPC 混合系统。** `humanoid-motion-planning` 是规划 + 玩具 MPC + SB3 PPO 脚本，且 RL 只控 10 个腿关节；不能当混合控制证据。

### 8.3 经典论文线与综述校准（B1–B4、B11）

- **模型式与学习式不是替代关系**：B1 把接触规划、运动规划、WBC 与 RL/IL 放在同一框架；B3 按 model-based / learning-based 两条线梳理行走；B4 把动力学建模与学习控制器并列。共同指向“混合范式”，而不是单一方法胜出。
- **非结构化环境把 planning/control/end-to-end 重新拉到一起**：B2 按这三层组织，并强调感知与状态估计集成；这解释了为什么人形的难点从“步态”转向“全身 + 接触 + 环境理解”。
- **WBC 的新方向是“预训练 + 可复用技能”**：B11 把 behavior foundation model（BFM）描述为大规模预训练、可复用 primitive、零样本/快速适配；这是方向性判断，不是本仓已验证的能力。
- **人形/WBC 经典线**：Periodic Reward Composition（ICRA 2021）用周期奖励模板得到 Cassie 多种步态；Expressive WBC（RSS 2024）与 HOVER（ICRA 2025）把全身控制推向多任务/统一接口；HugWBC（arXiv 2025）把步频、身高、俯仰、接触时序做成可控参数；Open-TeleVision（CoRL 2024）补遥操作数据链；Deep/Visual WBC（CoRL 2022/2024）则是四足 + 机械臂的统一运动/操作线。共同点是“统一接口 + 多任务/多行为”，不是单一速度跟踪。
- **LoCoWiki 补编**：`TWIST`（G1 遥操作/教师-学生）、`smp`（冻结扩散运动先验）、`GMR`（通用动作重定向）、`TWIST2`（VR 全身数据采集）、`TienKung-Lab`（全尺寸人形 AMP/传感器工作流）已入库；`BFM-Zero` 仅在 `STATUS.md` 索引。它们补“数据/运动先验”，未做本仓真训。
- **本仓边界**：本地人形证据仍集中在 velocity/tracking/AMP；`UFO` 的 FB/TeCH 与多技能隐变量是最接近“通用技能”的工作，但不是 BFM；非结构化全身控制没有 A 级本地证据。

### 8.5 与四足/轮足的差异

| 维度 | 四足 | 轮足 | 人形 |
|---|---|---|---|
| DoF | 12 | 16 | 23–29 |
| 平衡 | 三/四腿支撑，容错高 | 腿轮支撑，容错中 | 单/双足，容错低 |
| 接触 | 足端为主 | 轮 + 足端 | 足/手/膝/肘/躯干 |
| 参考动作 | 常不需要 | 常不需要 | 跟踪路线强依赖 |
| 安全 | 摔倒可接受度较高 | 中等 | 代价最高 |
| 数据 | 少量 mocap 即可 | 少量 | 大量 mocap/重定向 |

### 8.6 数据、重定向与许可

人形跟踪的数据链通常是：

```text
SMPL-X / AMASS / LAFAN1 / BONES-SEED
  → 重定向（GMR / mink IK / 逐机型配置）
  → 50 Hz NPZ/CSV（关节/连杆位姿）
  → 训练（参考跟踪 / AMP / RSI）
```

关键事实：

- 格式：CSV 常见 `root_pos(3)+quat(4)+joints`；NPZ 常见 30/50 Hz；四元数有 xyzw/wxyz 两种，不能混。
- 重定向：`robo_re` 用 SMPL-X/机器人 CSV→关键点→mink+MuJoCo IK，含脚/腕接触锁定；`wbc-mjlab` 只消费预重定向数据；`InstinctMJ` 依赖外部 AMASS/LAFAN 路径。
- 许可：LAFAN1 为 CC BY-NC-ND 4.0；BONES-SEED 需接受协议；SMPL-X/AMASS 需注册；`motion-imitation` 的 mocap 非商用。**代码许可 ≠ 数据许可**；重定向产物也受原始数据许可约束。
- 缺失：`Quad-Imaginarium`、`QuadFM`、`T2QRM` 只有 README/占位，不能当可用数据。

### 8.7 开放问题

- 全身控制 + 手/臂接触 + 任务规划仍未打通。
- 跨机型通用策略缺本地证据；`UFO` 自述不支持跨机型复用 checkpoint。
- 人形环境数常见 1024–4096，不是 8192；算力需求高。
- 数据许可与重定向成本是商用化的硬约束。

## 10. 演进方向与检查表

### 10.1 五个转移

1. **从“算法 novelty”到“MDP/部署工程”。** 同一 PPO 在不同 MDP/契约上差异巨大；论文里的算法改进往往不如观测/动作/延迟修正有效。
2. **从单机到族/复用。** 机型是数据、技能是族级机制、配方是档案数据；同族换机型不应复制工程。
3. **从“仿真里会走”到“契约可部署”。** 导出图边界、历史/关节序/PD/相机投影的契约测试，比再训一版更重要。
4. **从单技能到感知/通用/全身。** 感知跑酷、人形全身跟踪、通用策略是前沿，但证据成熟度远低于速度跟踪。
5. **从手写奖励到动作数据与预训练。** B10 的 35 项模仿学习研究中行为克隆占近半、MPC 生成数据是高级 IL 最常用来源；B11 把大规模预训练/可复用技能引入人形 WBC；Lifelike Agility（Nature MI 2024）用生成式动物运动先验做预训练，是“生成先验 + RL”的早期证据。方向明确，但本地没有 BFM 级训练证据，IL 也主要是数据链/单技能。

### 10.2 开放问题

| 问题 | 现状 |
|---|---|
| 评测 | 预算差三个数量级，缺统一 metric card/benchmark |
| 执行器/延迟 | 延迟随机化有；T-N/带宽/SysID 部署链缺 |
| 数据/许可 | mocap 许可复杂；四足/轮足缺数据 |
| 安全 | FSM/限幅常见，但部分保护被注释；缺统一验收 |
| 通用策略 | 跨机型/cross-embodiment 缺本地证据 |
| 人形操作 | 全身控制 + 手/臂接触 + 任务规划未打通 |
| VLA 实时性 | 低层运动仍以 RL/跟踪为主 |
| 轮足 | 轮地接触/站立/全向标准化低 |
| 模仿学习 | 数据来源/许可/闭环评测不统一；BC 与 RL 的边界常被混写 |
| 行为基础模型 | 预训练数据、跨机型复用、零样本评测缺统一口径；本地无证据 |

### 10.3 给新项目的检查表

1. **先写 metric card**：任务、观测、动作、控制频率、预算、评测 horizon、成功定义、seed 数。
2. **先定契约**：观测布局、动作 scale/offset/clip、PD、关节序、历史长度/方向、相机投影。
3. **从 PPO + 45 维本体 + 50 Hz 起步**：这是最成熟的基线。
4. **只在需要时加复杂度**：感知 → 教师-学生/估计器；风格/动作 → AMP/跟踪；容量 → MoE（先做同参数对照）。
5. **DR 分阶段**：clean → dynamics → actuator → perception → pushes；一次只动一类。
6. **导出按图边界设计**：actor-only / +encoder / +memory；normalizer/reset/metadata 明确。
7. **sim2sim 当契约测试**：能抓顺序/缩放/关节重排/历史/投影；不能抓电机/接触/通信。
8. **评测同预算、多 seed、带 fall rate/CoT/动作饱和**；不要用总 reward 跨项目比较。
9. **许可分层**：代码、重定向产物、原始 mocap 分别登记；NC/ND 数据不进入商用产品。
10. **先做可复现的基线，再做“更强”的方法。**

### 10.4 调试/对拍工具

- `cfg_diff_dump.py`：机制层配置逐属性 diff（移植/对拍时先跑）。
- `dump_effective_recipe.py`：把生效配方 dump 成可对拍 JSON。
- `print_runtime_limits.py`：打印 `registry/{cameras,motion_commands,arrival_criteria}.json` 的运行时限值。
- `validate_motion_columns.py`：动作文件关节列校验（同名同序）。
