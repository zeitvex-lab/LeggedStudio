# 08 · 插件化重构分析 v2.0（全面奔赴一切皆插件）

> **版本**：2.0 ｜ **日期**：2026-10-02 ｜ **性质**：目标架构裁决（**用户指令：全方面重构，不要有任何历史包袱**；v1.0 的保守裁决「不搬容器」作废，见 §6 裁决变更）
> **对照源**：`00_open/deepseek-harness`（Cordis 之上的一切皆插件）+ **00_resources 参考库的 RL 界成熟先例**（legged_gym `TaskRegistry`〔Dreamwaq/go2_rl_gym/LeggedGym-Ex/HIMLoco 多仓同构〕、mjlab `register_mjlab_task`〔本仓已在用〕、Isaac Lab 扩展注册）
> **定位对齐**：`01` 主叙事「全链路工作台」——工作台的每格插槽都该是插件位，这正是项目定位本身。

---

## 0. 裁决

**全面重构为一套插件内核之上的系统：本产品的每个阶段（机型装配/地形课程/奖励配方/算法变体/任务组装/评测/导出/部署）都是一个 seam（扩展点），每个实现都是一个 provider 插件，训练配置 = 一棵 entry 树，装配 = 作用域内逐插件 activate，训练循环暴露事件位。历史分发代码（if-elif 注册表、硬编码族字典、专用 builder）全部退役。**

RL 界先例证明这不是空中楼阁：legged_gym 的 `TaskRegistry.register(name, env_cfg, train_cfg) / make_env(name)` 就是"任务即插件"的工业形态（多个参考仓同构复刻）；mjlab 的 `register_mjlab_task` 我们已在 native_worker 里动态调用——**训练后端本身已经吃插件，只是本仓自己的装配层没吃**。

## 1. 目标架构（三层）

```
┌─ 产品层 ──────────────────────────────────────────────┐
│ entry 树（一次训练 = 插件挂载列表 + config）           │
│  patch 层叠：族基线 → 机型包 → 档案 → CLI（id 定位，后写胜）│
├─ 内核层（~200 行，唯一非插件件）──────────────────────┤
│ plugins/core.py：Registry（按 seam 分桶）/ resolve     │
│ （requires 注入）/ effect（可逆注册）/ entry 装载      │
│ （合并+patch+fail-loud）/ 事件位（on_iteration_end 等）│
├─ Seam 层（本产品全部扩展点，冻结为协议 v1）───────────┤
│ robot.package · terrain.profile · reward.recipe/term  │
│ algorithm.variant · runner · action.pipeline（低通=段）│
│ obs.layout（wrap 进段词汇表）· task.profile/plugin     │
│ evaluator（criteria/traversal/stunt/trend）· exporter │
│ deploy.target · hooks                                  │
└────────────────────────────────────────────────────────┘
```

### 插件形态（本仓特色：数据为主、代码可选）

| 形态 | 例 | 注册方式 |
|---|---|---|
| **数据插件**（绝大多数） | 机型契约、配方、地形档、任务档 | registry JSON → entry 树引用 |
| **代码插件**（少数能力件） | 奖励函数集、评测器、导出器、命令课程 | Python 模块 `(ctx, config)` |
| **参考内化插件** | 00_resources 的参考实现包成 provider（rc_old 经济学、LainLab trot…） | 内化工作流 = 适配 + recipe_parity + 验收入册 |

**参考库支撑判断**（用户指令：resource 足够做判断/workflow）：97 项目里 legged_gym 系（Dreamwaq/go2_rl_gym/LeggedGym-Ex/HIMLoco/engineai_rl_workspace）提供 task-registry 先例，mjlab/AMP_mjlab 提供 task 动态注册先例，Isaac Lab 系提供扩展声明先例，Odin-Nav-Stack/Learn-It-All 提供部署面插件先例——**每个 seam 的设计都不需要发明，抄各自领域最成熟的形态**。

## 3. 迁移计划（四 Phase，每 Phase 独立交付 + 基线闸）

| Phase | 内容 | 交付判据（基线闸） |
|---|---|---|
| **0 内核** | `plugins/core.py`（Registry/resolve/effect/entry 装载）+ 测试；协议 v1 冻结 | 内核单测全绿；对 2 个既有 seam 试点 |
| **1 装配侧** | FAMILIES/FRAME_BUILDERS/判据分发 全部改注册表；删硬编码分发 | 全量后端测试绿 + go2-velocity-flat 1024×250 基线 reward 复现（**68.55**） |
| **2 配置面** | profiles → entry 树 + patch 层叠（extends 语法糖化）；effective-config = 装配快照不变 | 冒烟指纹等价验证 + 混合档 4096×2500 基线复现（**157.3**） |
| **3 消费链** | emit_assembly → 评测/浏览器消费；wrap 进段词汇表（零 builder）；hooks 进训练循环（趋势探针自动跑） | 混合档判据验收走通 + 趋势探针训中自动出 verdict |
| **4 清理** | 删旧分发路径/冻结专用 builder；doc 收口 | 全门禁绿 + 无孤儿 |

**止血不变量**：五层保真链 / 契约导出（emit_assembly）/ 9 张数据表 / 四轴模型 / 用户判据——全部保留，只是消费方式插件化。每 Phase 结束跑：后端全量 + JS 套件 + 冒烟（基线 run）+ doc 门禁。

---

## 4. 双轨期与回退

* Phase 1-2 期间新旧装配**并存一 Phase**（smoke 指纹天然区分新旧配置）；Phase 4 才删旧路径。
* 每个挂载点保留基线 run 复现闸（68.55 / 157.3 两条已知基线）；复现失败 = 该 Phase 不合入。
* 回退 = revert 单 Phase 提交（Phase 边界即提交边界）。

## 5. 风险表

| 风险 | 概率 | 止血 |
|---|---|---|
| 装配行为漂移（重构后 reward 曲线变） | 中 | 基线复现闸（两条已知基线）+ recipe_parity/emit sweep 全仓跑 |
| 浏览器消费链跟不上（新协议 vs applyLayoutSpec） | 中 | Phase 3 才动消费链；期间专用 builder 照常工作 |
| 档案迁移工作量大（55 份） | 低 | extends 兼容（无 extends = 原样），存量逐步收敛非强制 |
| 内核过度设计（把 Cordis 全搬） | 中 | 内核 ≤300 行硬上限；没有的能力不预置（dsh 教训只在需要处长出来） |

## 6. 裁决变更记录

* **v1.0（同日早）**：保守路线——「不搬 Cordis 容器、只做 G1-G4 三小步」。理由是训练装配一次性构造、无热插拔需求。
* **v2.0（本版，用户裁决推翻）**：全面奔赴。变更理由：① v1 只修分发点不修**协议**，几十台机器人的边际成本仍含法证成分；② 参考库证明 task-registry 模式是 RL 工业标准（legged_gym 系多仓 + mjlab 已在用），"运行时容器"的顾虑可用 ≤300 行内核消解；③ 项目定位是工作台，插槽化即定位本身；④ 阵痛 = 一次性迁移成本，换永久性边际成本下降——符合「用仿真换实机调试时间」的同款决策逻辑。
* v1.0 的差距清单（G1-G4）与对位表仍有效，收编进 §2/§3。
