# 08 · 插件化重构分析 v2.1（产品面全面奔赴：CLI/Web/桌面都是插件面）

> **版本**：2.1 ｜ **日期**：2026-10-03 ｜ **性质**：目标架构裁决（**用户指令升级：不要让任何机器人或功能有不一样的地方——CLI、Web、桌面程序、Web 的各项功能、桌面程序的各项功能都是插件，即插即用**）
> 前序：v2.0（训练域四 Phase：内核/装配/配置/钩子——已落地 Phase 0-3，见 §4）
> 本文新增：**产品面（UI/CLI）纳入同一插件协议**——训练域与产品面共用一套 seam 协议，机器人与功能在三个形态（CLI/Web/桌面）里没有任何"不一样的地方"。

---

## 0. 裁决（v2.1 增量）

**dsh 的本质不是"训练插件化"，是"产品的每个用户可见面都是插件的投影"。** 本仓此前只做到了训练域（Phase 0-3）；v2.1 把产品面拉进同一协议：

* **页面/面板 = 插件**：Web 的每个功能页（8 页）与工作台的每个面板（机器人包/视口/编辑器…）不再是写死的 HTML + 手写 NAV_ITEMS，而是**声明式插件**——`registry/panels/*.json`（或页内自带 manifest）声明 `{id, title, entry(html/panel), seam 依赖, 命令}`，顶栏/侧栏由注册表**生成**（`web/shared/topnav.js` 的 NAV_ITEMS 数组退役）。
* **CLI 命令 = 插件**：每个 CLI 子命令一个 provider（`module:attr`），命令表由注册表生成——新增一个 CLI 能力 = 新增一个 provider 文件，零 core 改动。
* **桌面 = 同一插件面的第三个投影**：electron launcher 渲染同一份面板注册表（桌面按 capability 裁剪：无 GPU 监控需求的面板可声明 `desktop: false`），**桌面与 Web 的功能差异是注册表里的字段差异，不是两套代码**。
* **机器人零特判**：任何机器人/功能的 UI、评测、部署入口全部来自其插件声明——框架代码里不允许出现具体机器人 id / 功能 id（dsh 教训：唯一例外是启动审计的必需项清单，且是"在不在"检查不是行为分支）。

## 1. 产品面协议 v1（`registry/panels` + CLI 注册表）

### 1.1 面板插件声明（Web 面板/页面统一）

```json
{
  "id": "training-monitor",
  "title": "训练任务",
  "kind": "page",                    // page（整页）| panel（工作台面板）
  "entry": "training_monitor.html",  // page=HTML 文件；panel=挂载函数 module:attr
  "group": "训练",
  "order": 40,
  "requires": {"services": ["backend"]},   // 不可用时置灰并显示原因（诚实禁用）
  "desktop": true,
  "cli": {"command": "training list", "provider": "backend.cli_panels:training_list"}
}
```

### 1.2 消费点改造

| 现状 | 改造后 |
|---|---|
| `topnav.js` NAV_ITEMS 数组（8 项手写） | 启动时 fetch `/api/panels`（注册表生成的导航）→ 渲染 |
| `workbench.html` 8 个 section 硬编码 | 侧栏 = 注册表 kind=panel 的投影；面板按 entry 动态挂载 |
| 桌面 launcher 的功能清单 | 同一注册表 + `desktop` 过滤 |
| CLI（onboard/verify/train/export/deploy）逐个写死 | `backend/cli_panels.py` 注册表 + argparse 子命令生成 |

### 1.3 服务不可用 = 诚实禁用（fail-loud 的 UI 版）

面板声明 `requires.services`；注册表生成时探测（backend /health），不可用 → 导航置灰 + 面板显示原因原文——**功能差异来自声明，不来自 if 机器人**。

## 5. 不变式（全 Phase 有效）

1. **框架代码零特判**：不出现机器人 id / 功能 id / 族 id 行为分支（审计可用 grep 门禁）。
2. **诚实禁用**：功能不可用 = 置灰+原因，永不静默隐藏或假跑。
3. **fail-loud**：声明缺失/形状错误 = 启动即报，不猜不默认。
4. **五层保真链/emit_assembly/用户判据**：不受重构影响，消费方式插件化而已。
5. **内核 ≤300 行**：能力只在被需要时长出来（dsh 教训）。
