# Legged Studio 最终愿景

**版本**：2.2 ｜ **日期**：2026-09-10 ｜ **产品版本**：0.17.0
**一句话**：Windows 下的桌面程序——双击启动，一切操作都在程序内完成，不需要懂命令行。它本质上是一台"足式机器人小脑的训练与部署流水线"：你给一个 URDF/MJCF，它还你一个经过验证、可追溯、可上实机的策略。

机器人、任务、感知、部署目标都是插件；训练框架、构型、奖励、观测全部高度抽象成"构型 + 角色"的语义描述——不写代码也能扩展。

---

## 三种形态：桌面程序、Web 与 CLI

只有三个形态，职责严格分开——**后端是唯一的能力中心，桌面程序、Web、CLI 都是它的客户端**；基础仿真不是第四个入口，它就是 **Web 里的一个页面**。

- **桌面程序（Electron 壳，Windows 桌面）**：本身**不做任何机器人计算**。它只干四件事——路径与运行时探测；按需下载嵌入式运行时（Python 3.12 + CUDA Runtime + MJLab 隔离 venv，`scripts/provision_windows_runtime.ps1`）；spawn 并守护 FastAPI 后端（默认 `127.0.0.1:8765`，启动前清僵尸进程、轮询 `/health` 并校验 instance ID 防止串到别人的端口）；系统集成（托盘、Windows 任务栏训练进度条、退出前确认、设置落 `userData/settings.json`）。它是三者中**唯一能供应运行时、能拉起训练后端的形态**——"零命令行"这个承诺只在桌面形态成立。
- **Web（工作台，含浏览器仿真）**：全部业务界面都在这里（五个分组、八个页面，见下节），由后端同进程静态托管在 `/web`，同源 `fetch` 调 `/api/*`。**基础仿真就长在 Web 里**——它是 `/web/sim2sim/` 这个页面：MuJoCo WASM + ONNX Runtime Web + Three.js 全部本地 vendor，运行库零 CDN、可离线；它需要的机器人包、场景、策略与运行配置由同源后端提供（`/api/robots/presets`、`/api/simulation/browser-config/<robot>`、`/api/simulation/browser-package/...`、`/api/play/*`），并因 MuJoCo 的 pthread 版依赖 `SharedArrayBuffer` 而由后端对该路径注入 COOP/COEP。它与工作台共用同一个后端、同一份契约。Web **不依赖桌面壳**——可以只起后端、直接用浏览器打开（前端无构建、刷新即生效）。
- **CLI**：与 Web 共用同一份 API 契约（同一能力、两个入口），是自动化与 CI 的入口，并支持 `--offline` 直连内核。

**能力归属（谁提供、从哪个入口用）**：

| 能力 | 提供方 | 入口 |
|---|---|---|
| 运行时供应 / 后端生命周期 / 系统集成 | 桌面壳 | 桌面程序 |
| 工作台各页面、3D 检查、配置编辑、任务监控、部署向导 | `web/`（后端静态托管） | Web |
| 基础仿真（Sim2Sim 回放，WASM + ORT-Web） | `web/sim2sim/`（数据由同源后端提供） | Web |
| 训练 / 评估 / 服务端仿真 / 打包 | 后端（隔离子进程） | Web 或 CLI |
| 自动化与 CI | 后端 API | CLI |

两条容易混的边界：**① 打开方式**——Web 既能被桌面壳打开，也能直接用浏览器打开（只要后端在跑）；"零命令行"只在桌面形态成立。**② 文件来源**——后端在本机时资源可直接按路径引用，后端在远端时同一资源只能上传，所以来源统一抽象为 `path | upload`。

**设置不是工作台页面**：它分两层——桌面壳的 `userData/settings.json`（是否自动拉起后端、Python 路径、端口、训练设备）与后端的 `/api/settings`（运行时管理、镜像源、工作区清理）。

**工作区属于后端，不属于前端载体**：桌面壳把默认工作区指向用户数据目录，远端 Web 部署用 `LEGGED_STUDIO_WORKSPACE` 指向服务端目录，两者共用同一套路径解析与哈希规则。本地部署是**单用户、可信、可读本机文件**的形态；Web 若被局域网访问，必须显式开启鉴权并收紧当前"全开放"的 CORS——**本地部署与远端部署不能共用同一套默认安全假设**。

## 启动与环境

启动器只读，双击打开不写任何东西；点"配置运行环境"才把固定版本的 Python + CUDA 下载到用户数据目录（CUDA Runtime 完全内置，用户只需 NVIDIA 驱动 ≥525.60，不用装 CUDA Toolkit；国内默认清华 + 上海交大镜像，也可离线 wheelhouse）。点"启动"才拉起后端，且先过身份校验——无关服务占了端口也不会被误认。

环境页是 **L0–L6 分层体检报告**：GPU → 框架 → 任务注册 → 场景 → zero agent → random agent → 最小训练，哪一层挂了一眼看出来；失败项附中文原因和"怎么办"。启动器、环境页、后端三者是同一份契约的三个视图，环境页读到的版本号就是运行时真实版本。

> 本节描述的是**桌面形态**。在纯浏览器形态下，运行时与后端生命周期由部署方提供，环境页只做只读体检。

## 首页（含资产库）—— 小优化

首页已经能承担"进来看清全局"：hero（NATIVE MJLAB PIPELINE）、系统状态、下一步建议、**资产库**（内置包 + 工作区包统一管理、支持按路径导入、卡片网格）、**预训练策略 · 免训练即玩**（demo 卡）、最近实验。本阶段只做小优化，不动结构——

- **预训练 demo 卡直连仿真**：预训练策略一进索引就出现在首页，点开直接进基础仿真跑起来，不必先建训练。
- **最近实验直达**：从实验条目直接跳进对应训练任务（`training_monitor.html`）或基础仿真。
- **系统状态与体检同源**：系统状态卡与 L0–L6 环境体检共用一份数据，异常时首页就能看出是哪一层、怎么办。
- **下一步建议更有针对性**：依据当前项目状态（是否已有契约、是否跑过冒烟、是否导出过策略）给建议，而不是罗列功能。

## 机器人工作台 —— 小优化

这一页已经是完整的三栏工作区，结构不动：

- **左栏**：机器人包列表（内置 + 工作区），支持"导入文件夹"（落到 `workspace/packages`）。
- **中栏**：Three.js 查看器，**7 个开关**——外观 / 碰撞 / 惯性 / 质心 / 网格 / 坐标轴 / 关节轴。
- **右栏 INSPECTOR**：**5 个页签**——关节控制（默认姿态 / 零姿态 / 设为默认）、动作映射、电机参数（Kp/Kd/力矩限/速度限，按关节组）、质量与惯量、**体检**；底部为删除包 / 保存配置。

体检页在界面上已经写明**五卡**：质量三来源 / 碰撞 / 惯量 / 电机参数（角色分组 + 与官方值 diff）/ 关节，三色徽章（通过 / 警告 / 失败）。本阶段的小优化：

- **把五卡的数据源补齐**：质量卡落到"URDF 声明 vs mesh 计算 vs 手工"三来源对比（mesh 不闭合降级"未知"）；电机参数卡落到"按角色分组 + 与上游官方部署值 diff、漂移红标"。
- **动作映射页签与契约打通**：动作索引、`reindex_from_model` 在这里可见可比对，改动即写回包。
- **保存即同步**：保存配置写回机器人包（契约 v3），并同步到浏览器仿真配置，避免两处不一致。
- **契约 v3 语义收口**：`morphology`（`quadruped_12dof / wheel_leg_16dof / biped / humanoid`）+ 执行器按角色声明（类型 `position / velocity / hybrid / bam`），足型分 `point / sole / wheel`，轮组记 `wheel_indices`；同构机器人共享一份参数，加新机器人只写角色覆盖。

## 训练配置 —— 优化与重构

这一页（`training_create.html`）现在是"一个大表单"，把物理、任务、算法、运行四层信息混在一份配置里，而且任务与奖励仍写在 Python 里。本阶段把它改成**数据驱动的 Recipe 编辑器**：

- **三层拆开，页面上也分三块**：**物理层**（关节 / PD / armature / 频率）不在这一页出现，它属于机器人契约；**任务层**（命令、奖励、课程、域随机化、终止、观测）来自 `registry/skills` 里的 **SkillRecipe（base + override）**；**运行层**（env 数、迭代数、学习率、seed、save 间隔）在点"开始"时才组装成一次 Run。
- **技能注册表数据化**：任务与奖励不再硬编码，而是 `registry/skills/*.json` + `registry/rewards/*.json`（`skill-recipe-2.0`）；**新增技能只写一份 Recipe JSON，不写代码**。
- **奖励按四层分组编辑**：Tracking / Regularization / Style / Contact，每项中文名 + 一句话 + 滑条，并标出三组经典冲突（大 tracking 权重→暴力追踪抖动、早期严罚接触→学会不动）。
- **观测/动作映射板**：左边标准观测库（带宽度 + scale），右边策略输入槽位，维度自动校验；观测组件五元组 `(source, role[actor|critic|teacher|student], history, encoder, deployment_available)` 在这里可视化。
- **模块化资源包**：盲走资源包（DreamWaQ 全家）、模仿三线（DeepMimic / AMP / teacher→student）、感知观测项（足端接触 → 高度场 → 深度相机）以"可挂载的包"出现，而不是散落的开关。
- **专家模式**：dot-path 改任意参数，作为图形编辑器的逃生门。
- **一键导入/导出配置**：导出的是 **Skill 包**（纯 JSON，可被他人导入并校验），不是整台机器人。
- **先冒烟再长训**：冒烟档（64 envs × 5 iters）作为"开始"按钮的前置门。

## 训练任务 —— 优化与重构

这一页（`training_list.html`，详情页 `training_monitor.html`）现在是"任务列表 + 一张进度图"。本阶段把它改成 **Run 档案页**：一次训练不是一个进度条，而是一份不可变、可回溯的档案。

- **Run 是一等对象**：`runs/<run-id>/` 下落 `resolved-config.json`（含输入哈希）、`environment-lock.json`（uv.lock / torch / cuda / mjlab 版本）、`checkpoints/`、`metrics/`。改任何东西 = 派生新 Run，不就地覆盖。
- **可复现四件套**：seed / 依赖锁 / resolved-config / 输入哈希，页面上直接可见、可对账。
- **分项曲线按奖励四层分组**：total 上涨可能只是 penalty 在降，四层分项各自成组，趋势一眼可辨。
- **五大健康仪表盘**：奖励 / KL / 熵 / 价值损失 / 回合长度。
- **中文症状诊断卡**：按"先验接口 → 再查 reward → 最后调 PPO"的铁律给排查链路。
- **告警与生命周期**：奖励崩溃 / NaN / OOM 告警；暂停 / 恢复 / 停止可用，关程序不留僵尸进程。
- **训练永远发生在后端**：隔离子进程执行，控制面不 import Torch，崩溃不影响工作台。

## 基础仿真 —— 优化

`/web/sim2sim/index.html` 是"本体 + 本体感知"验证——只靠 IMU / 编码器 / 接触，不依赖外部世界；以 `embedded=1&robot=<id>&view=workbench` 嵌进工作台。形态已经成立，本阶段优化而不重构：

- **扩到全部内置机器人**：现在本地场景资源以 Go2 为主，其余机器人靠后端在线供包；目标是让"即点即玩"覆盖全部内置机器人，并保留下载/缓存策略。
- **确定性回放作为默认验收**：同一策略两次回放要逐帧一致——"回放不通过 = 没学会"，这条规则写进页面而不是靠人记得去点。
- **加载即校验 ONNX metadata**：`joint_names / observation_names / scales / history_length / action_scale / default_joint_pos` 与契约对不上就拒绝加载。
- **多策略热切换槽位**：同一台机器人上在多份策略间热切换，方便对比。
- **交互与地形**：键盘遥控、十几种地形、可交互扰动保持并归组。

## 高级仿真 —— 重构

这一页现在是 `navigation_editor.html`（导航地图编辑器）。**本阶段直接重构**，把它从"一个独立编辑器"重建成 **Scenario 契约 + Executor**：

- **统一到一套 Scenario 契约**：`World（表征 + 地形）× Mode（sampling/replay/interactive/headless_eval）× Sensors（特权 / 可部署，含 DR 与延迟预算）× CommandSource（teleop/script/planner/dataset）× Checks（L0–L6 探针 / sim2sim 对照 / DR 网格 / D1–D2 验收）× Recorders`。基础仿真与高级仿真共用这一套，差别只在 Mode 与 CommandSource。
- **导航 = `CommandSource: planner`**：地图编辑器画障碍、设航点，规划器（A*/Dijkstra/Hybrid A*）输出 `cmd_vel`，**复用同一个 velocity 策略，无需重训**；反应式避障作为可选叠加。
- **感知 = `Sensors → obs_component`**：深度 / 高度场走 student 策略的观测项，而不是另起一套导航栈；Go2 parkour 的 PIE 106×60 深度相机是内置参考。
- **场景与地图库**：地形、障碍布局、航点路线、感知场景（Scenario Contract）统一管理，保存后可复现、可分享，基础仿真与高级仿真共用。
- **导航栈外挂**：ROS2 / Nav2 / RTAB-Map / OctoMap / VLM 作为 `adapters/nav_ros2` 的 executor 接入，用 D2–D6 telemetry 字段对接，**不进核心**。
- **Executor 可替换**：WASM 与服务端 MuJoCo 是同一 Scenario 的两个 executor，"服务器仿真"不再是一个独立概念。
- **报告写回**：路径完成率 / 跟踪误差 / 碰撞次数 / 稳定性写回策略档案。

## 部署与策略档案 —— 本阶段不展开

`deploy.html` 与 `artifacts.html` 现阶段可用：导出双 gate（dummy forward 维度 + 固定输入数值回放 <1e-5）、DENYLIST 语义（观测组 / action scale / 关节序 / 控制频率 / armature 不一致拒绝）、部署包（部署契约 + FSM 安全状态机 + 目标平台模板 + 动作解码层 + 人工确认清单 + 劣化档 + D2 台架）。但**本阶段的愿景不展开、不投入**这一块：先把训练配置、训练任务、基础仿真、高级仿真定型，再回到部署与策略档案（PolicyArtifact 的完整形态：训练元数据 / 观测动作规范 / 评估结果 / 实机回溯）。

"一键生成 ≠ 一键上机"这条底线不变。

## 技术上

**内容模型**是五份一等资源 + 一个组合层：

- **Morphology 形态**：事实内核（关节 / 角色 / 限位 / 质量 / 执行器 / 足型 / 轮组 / armature）+ 表征文件（MJCF / URDF / mesh，可再生成，CI 做漂移检查）+ 能力声明（inspectable → trainable → simulable → deployable，按"机型 × adapter × 技能"评估）。
- **Skill 技能**：SkillSpec（接口语义 + 考卷，评审制）＋ SkillRecipe（Manager 配置 × 管线拓扑，注册制）。
- **Motion 参考动作**：动作序列 + fps / 坐标系 / dof 布局 + 重定向血缘 + 许可。
- **Scenario 场景**：World × Mode × Sensors × CommandSource × Checks × Recorders。
- **Policy 策略**：ONNX + 契约快照（obs / reindex / normalizer）+ 谱系与哈希。
- **Capability Pack**：`morphology_ref × skill_ref [× scenario_ref] [× policy_ref]` 的**纯引用组合**，外加四个阶段的质量门（verify / train / simulate / deploy）。

资源各有一份 schema 独立演进，组合靠引用不靠拷贝，差异全部下沉为数据，事实只在内核出现一次；**资源里不放代码**——算法实现属 adapter 的 runner，Recipe 只用 `runner_ref` 引用它。上面"训练配置 / 训练任务的重构"与"高级仿真重构"，本质都是把页面搬到这套资源模型上。

**分层**是四层严格隔离：`contracts/`（零依赖）→ 控制面（FastAPI，**永不 import Torch**）→ 训练 adapter（隔离 venv 子进程，崩溃不影响控制面）→ 浏览器 WASM / 服务端 MuJoCo。训练框架是插件：前期 MJLab，后期 UniLab / IsaacLab 以同一份 manifest 接入，各后端独立锁死 Python 环境（mjlab-py312 / robogauge-py311 / isaacgym-py38 隔离）。机器人、任务、感知、部署目标都是插件包（目录 + manifest：能力 / 依赖 / 许可链 / 哈希），第三方包必须过校验 CLI 才进索引。

**宿主边界**在这里写死：后端是**唯一的能力中心**，桌面壳、浏览器、CLI 都是它的客户端，三者共用同一份 API 契约；凡"需要 Python/CUDA/子进程/本机文件"的能力只在后端实现，壳与前端不做业务、不复制逻辑。

整个体系由**一份 JSON Schema 契约驱动**——前端表单、校验 CLI、训练配置树是同一份数据生成的三种形态，前后端字段永不漂移。

**导入 / 导出**分五类粒度：Morphology 包、Skill 包、Scenario 包、Policy 包，以及可选的 Bundle（Pack 引用 + 被引用物的离线副本 + 哈希）。**保存语义**三层：内核只读 + 版本化（一改就出新 hash，不就地覆盖）、画像 base + override patch、产物不可变 + 引用 + hash。**复现**分三档：R1 复现"看"（基础仿真回放）、R2 复现"用"（重跑评测得同一分数）、R3 复现"训"（同 seed 近似复现，随包给出 environment-lock 与缺口清单）。路径一律包内相对 + 哈希，许可与出处随每个资源。
