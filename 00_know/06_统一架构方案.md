## 一、三层参数分类（统一的基础）

| 层 | 参数 | 归属 | 统一策略 |
|---|---|---|---|
| **硬物理** | 扭矩上限 / 速度上限 / 质量·惯量 / 关节限位 / 摩擦死区 / 电机带宽延迟 | 契约 v3 + MJCF（datasheet / 系统辨识） | ❌ 不统一数值，每包记录真值 |
| **半自主** | PD 增益（kp/kd）/ action_scale | 契约 v3（物理约束下的设计选择） | ⚠️ 不统一数值，**统一"怎么选"**（起点公式 + 诊断表） |
| **纯约定** | 逻辑关节序 / 关节逻辑命名 / 观测组件顺序·命名 / 命令源接口 / actor-critic 分组 | **Kit 层**（全仓一份） | ✅ 全仓统一 |

## 二、统一训练架构

### 2.1 三层结构

```
┌─────────────────────────────────────────────────────────────────┐
│ 第一层：形态 Kit（按形态全仓一份）                                 │
│                                                                 │
│   kits/quadruped_kit/    ← 四足（go2/go1/b2/lite3）              │
│   kits/wheel_leg_kit/    ← 轮足（m20/zex-w/go2w/b2w）            │
│   kits/humanoid_kit/     ← 人形（g1；🔒 已冻结暂不建）             │
│                                                                 │
│   Kit 管：奖励函数库 / 观测组装逻辑 / 课程与终止 / 命令生成 /       │
│           训练循环接线 / 算法插件接入点                            │
│   Kit 不管：任何物理数值（全在第二层）                              │
├─────────────────────────────────────────────────────────────────┤
│ 第二层：机器人包（每机器人一份，纯数据 + 少量 wiring）               │
│                                                                 │
│   assets/robots/<id>/                                           │
│   ├── contract_v3.json    ← 物理真值（PD/armature/限位/scale）     │
│   ├── model/robot.xml     ← MJCF（执行真值，由契约烘入物理）        │
│   ├── simulation/         ← 策略声明 + 基础仿真配置                │
│   └── training/profiles/  ← 任务配置（纯 JSON，不写 Python）        │
│                                                                 │
│   包内 .py = 0 或仅入口 stub（B8 目标终态）                        │
├─────────────────────────────────────────────────────────────────┤
│ 第三层：算法插件（全仓一份，可插拔）                                 │
│                                                                 │
│   adapters/mjlab/algorithms/                                    │
│   ├── base.py            ← AlgorithmPlugin 协议                   │
│   ├── registry.json      ← 算法名→模块→元数据（fail-closed）       │
│   ├── cts/ dreamwaq/ amp/ distill/    ← 已有算法迁移               │
│   └── him/ hora/ appo/                ← UniLab 提取               │
│                                                                 │
│   profile 里 algorithm: "him" 一行即可切换算法                     │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 统一的纯约定（全仓一份）

| 约定 | 内容 |
|---|---|
| **逻辑关节序** | `FL→FR→RL→RR`，每腿 `hip_abduction→hip_pitch→knee→wheel?` |
| **物理名→逻辑名映射** | 每包契约一份 `joint_logical_map`（onboard 时自动推断，人确认） |
| **观测固定槽位** | `[ang_vel(3), gravity(3), command(cmd_dim), joint_pos(N), joint_vel(N), wheel_vel(W?), last_action(N)]` |
| **观测维度公式** | `3 + 3 + cmd_dim + 2N + (W if has_wheel) + N`，N=驱动关节数，W=轮数 |
| **命令源三选一** | `velocity [vx,vy,wz]` / `motion 参考帧` / `none`（按任务类型） |
| **观测分组** | `actor / critic`（已统一，B26 裁决） |
| **算法接口** | `AlgorithmPlugin` 协议：`build_actor_critic / build_storage / build_optimizer / export_onnx` |

### 2.3 半自主参数的统一方法

| 参数 | Kit 提供什么 | 数值在哪 |
|---|---|---|
| **action_scale** | `suggest_action_scale(joint_ranges)` → 行程/2~4 起点 + 诊断表 | 契约 v3 `action.action_scale`（每包各自调） |
| **PD 增益** | 两种模式：`use_mjcf=True`（默认，MJCF 为执行真值）/ `use_dr=True`（kp U(0.75,1.5) 域随机化） | MJCF（bake_mjcf_physics 从契约烘入） |

### 2.4 新机器人移植流程（快速移植的落地）

```
onboard（1 目录 + 模型）→ 契约生成器（自动推断逻辑映射 + 建议 action_scale）
→ 人确认/微调 → 三件 JSON + MJCF 定稿
→ profile 复用 Kit 模板（只改关节表/地形偏好/算法选择）
→ verify → 冒烟 1024×300 → 训练 1024×1000+
```

**DoD 第 2 条落地形态**：新机器人 = 1 份契约 + 1 份 MJCF + 1 个 profile JSON，Kit 零改动。

## 三、统一仿真架构

### 3.1 基础仿真（sim2sim/index.html）

```
输入：包内策略声明（simulation/config.json）
     → /api/simulation/browser-config/<robot> 下发
       [模型文件清单 + 策略 URL + 契约摘要 + 物理参数（契约 v3 同源）]

执行：浏览器 MuJoCo WASM（与服务端同一仿真内核）
     → 策略 ONNX Runtime Web 推理
     → 加载即校验 ONNX metadata（G3，与契约不符拒绝加载）

统一约定消费：
     • 观测组装按固定槽位（与 Kit 同一份逻辑的 JS 镜像）
     • 关节序按逻辑序（与训练一致，部署零映射）
     • 物理参数从契约下发（与训练/部署同源，H23 门禁校验）
```

### 3.2 高级仿真（advanced_sim.html）

```
在基础仿真之上加：
     • 传感器坞（odom/IMU/测距/深度/高度扫描/LiDAR/点云/RGB）
     • 导航闭环（?nav=<map>，服务端规划 + 浏览器跟随）
     • Scenario（World × Mode × Sensors × CommandSource × Checks）
     • Episode 记录与回放（"预测 vs 实际"轨迹叠加）
```

### 3.3 仿真验证快速通道

| 步骤 | 命令/入口 | 判据 |
|---|---|---|
| 1. 逐机型浏览器实测 | `pytest tests/e2e/test_all_models.py --sweep` | 14/14 会话就绪 + 策略真加载 + 帧推进 |
| 2. 热切换对比 | `tests/e2e/test_policy_hot_switch.py` | 双向往返 + 非换标签 |
| 3. 确定性回放 | `python tools/replay_gate.py --auto <包>` | 两独立进程逐帧一致 |
| 4. 导航链路 | `pytest tests/e2e/test_navigation_route.py` | 7 路线零链路缺陷 |
| 5. 无头基准 | `python tools/sim2sim_headless.py --baseline` | 只拦退化 |

**训练完成→仿真验证全链**：promote 自动安装进包 → 浏览器刷新即见（B43/B44 产物自证）→ 上述 5 步全走 = 可信仿真验证。

## 四、统一部署架构

### 4.1 部署包（`deploy_pack.py` 生成）

```
deploy_package/
├── deployment-contract.yaml   ← 关节映射/控制频率/PD/armature/限位
│                                （从契约 v3 投影，真值同源）
├── policy.onnx               ← 策略（B44 产物自证：实测宽度为准）
├── fsm_safety_template.py    ← 安全状态机（PASSIVE→STAND→POLICY→ESTOP）
├── action_decoder_template.py← 逻辑关节序→真实电机命令（自动生成映射表）
└── 人工确认清单.md            ← 增益降50%/急停/零点/软限位
```

### 4.2 部署链路（Sim2Real 全链）

```
训练 → ONNX 导出（B44 自证）→ B11 评测达标（质量门）
→ CLI deploy gate（DENYLIST fail-closed）
→ deploy package 生成（含安全状态机 + 解码器 + 确认清单）
→ 人工确认 → 实机
```

**"一键生成 ≠ 一键上机"**：部署包带人工确认清单和劣化档，这是 01 §9 3C 原则的落地。

### 4.3 三端一致的物理真值

| 端 | 物理参数来源 | 校验 |
|---|---|---|
| 训练 | 契约 v3 → bake_mjcf_physics → MJCF | `validate_mjcf_contract` |
| 浏览器仿真 | 契约 v3 → browser-config 下发 | `audit_sim2sim_consistency`（H23） |
| 部署 | 契约 v3 → deployment-contract.yaml | `deploy gate`（DENYLIST） |

## 五、统一 vs 不统一总表

| 项 | 统一 | 说明 |

| 训练循环接线 | ✅ | Kit 层一份（mjlab runner 消费模式） |

| 观测组装逻辑 | ✅ | Kit 固定槽位 + JS 镜像 |

| 算法切换接口 | ✅ | AlgorithmPlugin 协议 + 注册表 |
| 逻辑关节序 | ✅ | 全仓约定 |
| 关节逻辑命名 | ✅ | hip_abduction/hip_pitch/knee/wheel |
| 命令源接口 | ✅ | velocity / motion / none 三选一 |
| actor-critic 分组 | ✅ | 已统一（B26） |
| 浏览器仿真内核 | ✅ | MuJoCo WASM（与服务端同源） |
| 仿真验证链 | ✅ | 5 步快速通道 |
| 部署包结构 | ✅ | 四件套模板 |
| — | — | — |
| PD 增益数值 | ❌ | 每包契约/MJCF 各自真值（半自主） |

## 六、确保快速移植与快速验证的关键机制

| 机制 | 落地 | 验证 |
|---|---|---|
| **快速移植** | onboard 双入口（CLI/Web 同一编排）+ 契约自动推断 + Kit 零改动 | `onboard → verify → 冒烟` 全链不改 Python |
| **快速仿真验证** | promote 自动装进包 + 浏览器刷新即见 + 5 步验证链 | e2e 全绿 + 确定性回放 pass |
| **快速部署** | deploy gate + 四件套模板 + 逻辑序自动映射 | DENYLIST fail-closed + 人工确认清单 |
| **产物可信** | B44 产物自证（ONNX 实测宽度为准）+ B11 质量门 | verify_artifacts 0 problems |
| **物理一致** | 契约 v3 唯一真值 + 四端同源 + 门禁校验 | audit_sim2sim_consistency + validate_mjcf |

## 维护规则

1. 本文只写"统一什么、不统一什么、为什么"——具体数值在 `04_参数真值标准`，任务状态在 `05_任务清单`。
2. Kit 层新增能力时，先问"这个属于哪个形态"——答不上来就不进 Kit。
3. 半自主参数（PD/action_scale）的起点公式和诊断表住在 Kit，具体数值住在契约——两处不混。
4. 冻结包（wuji_hand / microduck / tron1×3 / g1）不参与 Kit 迁移，维持现状。
5. 本文的修改需要同步更新 `05_任务清单` P 组架构描述。
