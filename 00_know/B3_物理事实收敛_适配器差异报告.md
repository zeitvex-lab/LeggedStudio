# B3 物理事实收敛 — mjlab 适配器差异报告

> **日期**：2026-09-10 ｜ **对应任务**：B3/2b（`adapters/mjlab` 消费者翻转）
> **结论**：**B3/2b 当前不具备"等价翻转"条件，暂缓执行**；需先做契约补全（B3/pre）。

## 1. 为什么要先量化而不是直接改

B3/2（浏览器载荷）能安全翻转，是因为前端解析语义（`controlValue`）会**逐级回退**，
只要同时给出角色键与逐关节键，两条路径即命中同一数值。

适配器侧不同。两处真实解析语义是：

```python
# adapters/mjlab/policy_acceptance.py
def gain_for(self, table, joint):          # ① 精确小写名 → ② "键名是关节名子串" → ③ 静默 0.0
    v = table.get(joint.lower())
    if v is not None: return float(v)
    lowered = joint.lower()
    for key, val in table.items():
        if key.lower() in lowered: return float(val)
    return 0.0

limit = c.torque_limits.get(name.lower())  # ★ 无任何兜底
```

```python
# adapters/mjlab/scene_builder.py 与 load_package_model
lowered = name.lower()
if lowered in armature: ...        # 只做"小写后精确匹配"
elif default_arm is not None: ...
```

即：**`torque_limits` 与 `armature`/`frictionloss` 的查找没有子串兜底**，而各包
`simulation/config.json` 的键形态并不统一（逐关节小写 / 角色键控 / 混大小写）。
所以"换源"会直接改变**查得到 / 查不到**，进而改变数值。

## 3. 三个必须分开处理的结论

### 3.1 `torque_limits` 只能用 `by_joint`

用 `by_role` 会让 m20 / g1 **丢失力矩限幅**（它们原本靠逐关节小写键命中）。
这是"翻转即回归"的陷阱，也是必须先量化的原因。

### 3.2 两个既有静默 bug（与本次重构无关，但被本次量化暴露）

1. **microduck 的 PD 刚度恒为 0**：config 只提供 `{"joint": …}` 兜底键，而
   `gain_for` 的子串匹配要求"键名出现在关节名里"——`joint` 不在 `left_hip_yaw` 中，
   于是落到 ③ 静默返回 `0.0`。即 **microduck 的验收/回放一直是零刚度**。
2. **go2 的力矩限幅从未生效**：config 为角色键控，`.get(joint.lower())` 未命中 → `None`。

两者都**不报错**，正是"静默降级"的典型形态。

### 3.3 契约尚未收全（关键阻塞点）

`unitree_go2w` 的 `armature`：config 侧有 `FL_calf_joint`/`FL_wheel_joint` 等值，
契约 `actuator_profile` 侧缺失。**契约目前是 config 的真子集**，因此现在翻转必然丢数据。

→ **B3 的"物理事实只在一处"当前不成立**，不是配置冗余问题，而是**契约覆盖不全**问题。
