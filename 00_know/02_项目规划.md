## 1. 三条需求 → 技术目标 → 判据（总表）

规划的验收主线就是定位里的三条需求。每条都要能落到可机验的判据上，否则不算落地：

| 需求 | 技术目标 | 判据（可机验） | 关键落点 |
|---|---|---|---|
| **进得来** | 环境不靠人装；仿真不靠人搭；失败能定位到层 | 只读启动器 + 显式配置；体检分层报告；镜像档位与离线 wheelhouse 结构核对 | `electron/launcher/main.js`、`scripts/provision_windows_runtime.ps1`、`tools/audit_provision_phases.py`、`web/sim2sim/` |
| **改得动** | 机型/任务/感知的差异全部下沉为数据；新增一台机器人不写 Python | `onboard → verify → train → export` 全绿且无 Python 改动；Pack 引用可解析（`require_refs_resolved`）；契约漂移检查 | `contracts/`、`registry/`、`packs/`、`scripts/legged_studio_cli.py`、`tools/generate_contract_models.py` |

**读法**：左两列是设计意图（不会变），右两列是证据（会变，所以指向路径与门禁，不抄数字）。下面三节按需求展开，第四节是**长期支点（生态）**。

## 2. 需求一 · 进得来（门槛由产品承担）

**目标**：让"想验证一个想法"和"能跑起来"之间的距离从几天压到几分钟；**跑不起来时，判断不是"失败"，而是"挂在哪一层"**。

**技术方案**：

- **环境供应四段**：只读启动器（双击不写任何东西）→ 点"配置"才下载固定版本 Python + CUDA Runtime 到用户数据目录 → 点"启动"才拉起后端（先过身份校验，无关服务占端口也不会被误认）→ 失败不留残局。镜像档位 `cn | official | custom | offline`（`custom` 必须显式给源；`cn` 失败自动回退官方并如实上报）；离线走 `--no-index --find-links <wheelhouse>`（缺 wheelhouse 直接报错，**绝不静默联网**）。
- **体检分层报告**：环境页按层给出报告（GPU → 框架 → 任务注册 → 场景 → zero agent → random agent → 最小训练），失败项配中文原因和"怎么办"。
- **即点即玩**：内置机型包与预训练策略进索引即可点开，在浏览器仿真里跑起来——**新用户不必先建训练**。
- **设置分两层**：本机偏好（是否自动拉起后端、端口、训练设备、工作区位置）归桌面形态；运行时管理（镜像源、工作区清理）归后端。

**上游取用**：**无**（这是产品侧能力，不是从上游抄来的能力）。相关工具链参照见 `03` §1 ⑦ 工具链（`urdf_tool` / `wandb` / `1000framesai` 的站点镜像）。

**判据与门禁**：`tools/audit_provision_phases.py`（结构核对，**自己声明"不代替 Windows 实机验证"**）；`00_know/05_任务清单.md` DoD 第 1 条。

**当前缺口与阶段**（→ 阶段一）：**A1 结构达成、干净 Windows 实机端到端未验证**；I3 的 Web 向导半边（后端与 CLI 编排已就位，差前端接出）；G1 覆盖面达标、**逐机型浏览器实测**待补。

## 3. 需求二 · 改得动（差异由数据表达）

**目标**：机器人、任务、奖励、参数都变成**可点选、可替换的数据**；新增一台机器人 = 1 目录 + 3 JSON + 模型文件，不写 Python。

**技术方案**：

- **契约为单一事实源**：机器人、任务、感知的差异全部沉到 `contracts/` 的 JSON Schema；前端表单、配置校验、训练配置树由同一份契约驱动（前后端字段不漂移）；`tools/generate_contract_models.py` 参与 CI 漂移检查。
- **数据化配方**：任务与奖励不硬编码，走 `registry/skills/*.json` + `registry/rewards/*.json` 的 **SkillRecipe（base + override）**；动作（Motion）进 `registry/motions/index.json`（fps / dof / 血缘 / 许可全部**从文件派生**，逐文件 sha256）。
- **插件与 Pack**：五份一等资源（Morphology/Skill/Motion/Scenario/Policy）+ 组合层 `packs/*.pack.json`（纯引用 + 四阶段质量门）；**新增一种能力 = 新增一份配置，不是复制一份工程**。
- **新机型 onboard**：`1 目录 + 模型 → 三件 JSON → 登记 → 对账`，CLI 与 Web 向导**共用同一份编排与内容摘要**（两入口产出同一 `package_id`，有测试钉住）；参数按 `03` §3 的多源对照取证后才登记（找不到源按"原本没有"登记，**不猜**）。
- **模块化资源包**：奖励四层分组（跟踪/正则/风格/接触，标出三组经典冲突）、模仿三线（DeepMimic/AMP/teacher→student）、观测/动作映射板（维度自动校验）——都以"可挂载的包"出现，不是散落的开关。

**上游取用**：`03` §1 ② mjlab 系（`mjlab_new`/`mjswan`/`parkour_mjlab`/`g1_spinkick_example` 的任务配置组织）；§1 ③ legged_gym 系多机型常量表（`robot_lab`/`MGDP`/`Dreamwaq`/`walk-these-ways` 等）；**PaddleX 骨架**（`03` §5.2：产线即数据 / 模块自注册 / 统一适配层，是 DoD 第 2 条的形态依据）。

**判据与门禁**：DoD 第 2 条（1 目录 + 3 JSON，不改 Python）；`contracts/tests` 134 项全绿；`tools/validate_packs.py` 14/14；`tools/audit_training_config_layers.py`。

**当前缺口与阶段**（→ 阶段三）：M2 Motion 消费统一、B8 训练框架上移、I1 的 `export`/`deploy`、I3 许可字段、`03` §8 的"待定"项细看。

## 4. 需求三 · 走得完（交接必须可检查）

**目标**：每一步的产物都**带来龙去脉**——任何一次结果都能说清它从哪来、和上一次差在哪、是不是更好。

**技术方案**：

- **训练**：配置三层拆开（物理层属机器人契约；任务层来自 SkillRecipe；运行层在点"开始"时组装成一次 Run）；**冒烟门在前**（64 envs × 5 iters，语义比对剔除规模三元组）；**Run 是一等对象**：`runs/<run-id>/` 落 `resolved-config.json`（含输入哈希）、`environment-lock.json`、`checkpoints/`、`metrics/`；**改任何东西 = 派生新 Run，不就地覆盖**。训练永远跑在后端隔离子进程（控制面永不 import Torch）。
- **验证**：**确定性回放是默认验收**（同一策略两次回放必须逐帧一致，不通过就是没学会）；**加载即校验 ONNX metadata**（关节名/观测名/scale/history/action_scale/默认姿态与契约对不上就拒绝加载）。
- **评测**：八指标照上游口径 + 四档（single/multi/level/stress），出报告才**放行**——"没有评估报告，就不算通过"；报告可随 Bundle 分发（`quality.json`）。
- **导出**：**五类粒度**（形态包/技能包/场景包/策略包/离线 Bundle），共用一份 manifest + 一套校验（逐条 sha256 / 必需角色 / 幽灵文件）；**导出双 gate**（dummy forward 维度 + 固定输入数值回放 <1e-5），DENYLIST 命中即拒绝。
- **复现三档**：R1 看（回放逐帧一致）、R2 用（重跑评测得同一结论，两个独立进程在导出物自身内比对）、R3 训（同 seed 近似复现 + `environment-lock` + 缺口清单）。
- **部署**：部署契约 + 安全状态机 + 目标平台模板 + 动作解码层 + **人工确认清单** + 劣化档。**"一键生成" ≠ "一键上机"**。
- **保存语义**（支撑上面全部）：事实内核只读且版本化（一改就出新哈希），配方走"基线加差异补丁"，产物不可变且只被引用。

**上游取用**：`03` §5.1（评测指标 ← RoboGauge `metrics/` + `QUALITY_WEIGHTS`；评测档位 ← `pipeline/{base,multi,level,stress}`；导出清单纪律 ← wandb `ArtifactManifest`；确定性判据 ← newton `test_solver_determinism.py`；sim2real 流程 ← `rc_old`/`parkour_mjlab`/`m20_rl_isaacsim`）；**R2/R3 是本仓自证**（`adapters/mjlab/replay_determinism.py` + `collect_environment_lock` + `_OMITTED.md` 缺口范式），不引外部。

**判据与门禁**：DoD 第 3 / 4 / 5 条；`tools/replay_gate.py --selftest`（在 CI）；导出双 gate；评测质量门（没有报告不放行）。

**当前缺口与阶段**（→ 阶段二）：L7 更大规模档位（受无人值守上限约束）、F 组页面消费、G2 采集器（"自动连跑两遍"）、H1–H7 Scenario 契约层、感知 provider 阈值标定。

## 7. 系统总览（支撑材料）

### 7.1 四层隔离 + 一个宿主边界

```
          桌面壳（Electron）     Web 工作台（静态页）      CLI（工程师入口）
                 │                      │                       │
                 └──────────── HTTP / 同一份 API 契约 ──────────┘
                                    ▼
   ① 契约层   contracts/          零依赖：JSON Schema + 生成的 Pydantic 模型
                 ▼ import
   ② 控制面   backend/            FastAPI，永不 import torch / mjlab
                 ▼ spawn（隔离 venv 子进程，JSON 协议）
   ③ 训练适配器 adapters/          per-后端独立锁死环境（mjlab-py312）
                 ▼ 产出 policy.onnx + 部署元数据
   ④ 仿真内核 服务器 MuJoCo 3.11 / 浏览器 MuJoCo WASM（同一 Scenario，两个 executor）
```

三条硬边界：**控制面不 import 训练栈**（训练跑隔离子进程，崩溃不带走工作台）；**后端是唯一的能力中心**（壳/浏览器/CLI 都是客户端，共用同一份契约）；**同一份仿真内核、两个 executor**（服务端 MuJoCo 与浏览器 WASM 是同一 Scenario 的两种执行方式）。

### 7.2 数据流主线

`assets/robots/<id>` → 机器人工作台检查与校准 → 训练创建（Recipe + 运行层）→ 冒烟门 → 长训 → 导出 ONNX（双 gate）→ 基础/高级仿真验证（回放判定）→ 评测矩阵出报告 → 导出五类粒度与复现三档 → 部署包 → 实机。

## 9. 数据与资源模型（支撑材料）

### 9.1 五份一等资源 ↔ 实体

| 资源 | 实体落点 | 要点 |
|---|---|---|
| **Morphology 形态** | `assets/robots/<id>/contract.json` + 模型与表征文件 | 事实内核（关节/角色/限位/质量/执行器/足型/轮组）+ 表征（MJCF/URDF/mesh，可再生成）+ 能力声明 |
| **Skill 技能** | `registry/skills/*.json`（含 `patches/`）+ `registry/rewards/*.json` | 配方 = 基线 + 差异补丁；新增技能只写一份 JSON |
| **Motion 参考动作** | `registry/motions/index.json` | fps / dof 布局 / 重定向血缘 / 许可全部**从文件派生**，逐文件 sha256 |
| **Scenario 场景** | `assets/maps/` + 场景契约 | World × Mode × Sensors × CommandSource × Checks × Recorders |
| **Policy 策略** | `policies/<id>/` + `policies/index.json` | ONNX + 契约快照（观测/关节序/归一化器）+ 谱系与哈希 |
| **组合层 Capability Pack** | `packs/<id>.pack.json`（schema `capability-pack-1.0`） | 纯引用组合，每个引用带 sha256；带四阶段质量门（verify/train/simulate/deploy） |

### 9.2 引用与保存纪律

- 包内引用一律**相对路径 + sha256**；缺失字段在验证阶段 **fail-closed**（报错，不回退默认值）。
- 内核只读 + 版本化（一改就出新哈希）；配方 = 基线 + override patch；产物不可变且只被引用。
- 许可与出处随资产走（`registry/licenses.json` 随包对账；**绝不默认 allowed**）。
- **上游依据也随资源走**：每个数值/资产都要能指回 `03` 的某一格（官方源、快照路径或已裁决结论），指不回去的按"原本没有"登记。

## 10. 核心功能地图（每一块 → 服务的需求 → 产物 → 判定）

| 块 | 服务的需求 | 这一段的产物 | 判定（怎么算做成了） |
|---|---|---|---|
| **环境与启动**（门槛站） | 进得来 | 一份"知道自己跑在什么环境里"的报告 | 挂在哪一层，一眼看得出来 |
| **资产与即玩** | 进得来 | 预训练 demo 与内置机型在浏览器里跑起来；同一入口承接导入 | 新用户不建训练也能看到机器狗动 |
| **训练** | 改得动 + 走得完 | 一次 Run 的完整档案（配置/依赖/seed 封存） | 同配置同种子应当一致；改过的东西必须派生新 Run |
| **仿真** | 走得完 | 回放与验收记录 | 回放逐帧一致才算学会，不通过就是没学会 |
| **评估** | 走得完 | 评测矩阵报告（多指标 × 多档位） | 没有评估报告，就不算通过 |
| **部署** | 走得完 | 部署包（契约 + 安全状态机 + 人工确认清单 + 劣化档） | 对不上的配置被拒绝，不放行；"一键生成" ≠ "一键上机" |
| **导出与复现** | 走得完（也是生态前提） | 五类导出物 + Bundle；R1/R2/R3 结论 | 三档能不能过，而不是"导出了" |

## 11. 环境与运行时（支撑材料）

- **控制面依赖**：`pyproject.toml`（`fastapi` / `uvicorn` / `pydantic` v2 / `numpy>=2,<3` / `mujoco==3.11.0`，`requires-python >=3.12,<3.13`）；`backend/requirements.txt` 与 CI 安装口径一致。
- **训练栈隔离**：`adapters/mjlab/pyproject.toml` + `adapters/mjlab/uv.lock`（mjlab 1.6.0 + torch cu128/cpu），**永不装进控制面环境**；进度兼容由 `runtime_compat.py` 处理。
- **运行时数据目录**：`registry/` 与 `packs/` 必须随包进 wheel（`force-include` 写明漏掉的后果：不是报错，而是"运行时读不到"）。
- **打包**：`package.json` 的 `extraResources` 把 `backend / contracts / registry / packs / assets/robots / web / adapters / tools / scripts / VERSION` 一并带走；**`00_resources/` 与 `/00_open/` 不进包**（一个是核对底座、一个是历史克隆，都不是运行时依赖）。
- **云原生开发**：根 `Dockerfile`（Ubuntu 24.04 LTS + Python 3.12）+ `.cnb.yml` 的 `vscode` 事件，控制面依赖 + Chromium + mjlab CPU 训练栈全固化。

## 12. 质量与门禁（支撑材料）

**测试基线**（数值口径见 `05` §0）：backend **1116** 项 / 91 个模块；contracts **134** 项；前端 6 组 node 断言。

**本地命令**（`package.json`）：`npm test`、`test:contracts`、`test:{obs,nav,fan,sensors,raycast,dock}`、`check:docs`、`check:licenses`、`check:motions`；一键全跑 `npm run test:all`。

**CI**（`.cnb.yml`，`unit-tests` 段）：语法检查 → 契约产物漂移 → 纯逻辑用例 → openapi 冒烟 → **backend 全量 discover** → 移植准入 → Pack 校验 → 许可注册表 → Motion 注册表 → 环境供应四段 → 观测组名 → 仿真分层 → 资源许可覆盖 → 验收可查性 → 工具登记 → 文档对账 → contracts 全量 → 确定性回放自检。

**门禁设计的一致做法**（值得照抄的三条）：① **门禁自己声明边界**（"不代替实机验证"/"静态扫描不渲染浏览器"）；② **判据双向**（新缺口判红 + 名单过期也判红）；③ **数字的家在门禁输出**（会漂的数字由 `--json` 提供，不写进文档）。

**故意不进 CI 的东西**（不是漏了，是有意）：`tools/cross_source_audit.py` 与 `tools/model_field_diff.py`（依赖 `/00_open/` 本地克隆）、浏览器 E2E（`tests/e2e/`，需真实后端与 Chromium）。

## 13. 指标与验收口径

**北极星指标**：一次"可信结果"的产出，即从操作开始到得到一份可回放、可追溯的结论，所需的**时间与人工干预次数**。它同时压住了门槛与可信度。

**支撑指标**（五类）：

| 指标 | 定义 | 对应需求 |
|---|---|---|
| **激活** | 新用户在限定时间内跑通首条结果的比例 | 进得来 |
| **可信** | 产物中能被完整溯源、且可复现同一结论的比例 | 走得完 |
| **复用** | 新增一种机型或任务所需的平均改动量 | 改得动 |
| **打包** | 把一份资产做成他人可直接导入的包所需的工作量（供给侧的入场成本） | 生态 |
| **留存** | 用户在拿到可信结果后，继续在同一条链路里迭代的比例 | 三者共同 |

## 14. 风险、依赖与不做清单

**技术风险**：

| 风险 | 说明 | 现有对策 |
|---|---|---|
| 上游 API 漂移 | mjlab / mujoco 版本一动，训练与验收口径就可能变 | `adapters/mjlab/runtime_compat.py` + 各自锁死环境 + `environment-lock.json` |
| **上游源不全** | 非宇树机型只有快照、`wuji_hand` 无源（`03` §2.3），数值争议可能无法三向裁决 | 缺源时按"原本没有"登记；优先补官方克隆；**不猜值** |
| 实机落差 | 仿真结论不等于实机结论 | 验证与部署分开看；部署包带人工确认清单与劣化档 |
| 门禁的假安全感 | 静态门禁会被读成"已跑过" | 门禁自述边界写进输出（见 §12）；对外表述只挂"能被证明"的部分 |
| **供给冷启动** | 打包不够便宜、校验不够透明，生态就只是一句口号 | 供给侧成本作为产品指标（§13 打包） |
| 许可取证缺口 | 上游资产许可不全或非商用 | 逐条取证 + 缺口登记不判红、新缺口判红 |
| 长训规模受限 | 无人值守上限约束规模档位 | 冒烟档全机型跑遍先行；规模档位另行安排 |

**外部依赖**：`00_resources/` 参考资源库（真值核对底座）、`/00_open/` 官方克隆（历史核对，工作区外）、MJLab 1.6、MuJoCo 3.11、NVIDIA 驱动（无独显时 CPU profile 可用，吞吐低约一个数量级）。

**不做清单**（与 [`01_项目定位.md`](./01_项目定位.md) §8 的边界一致，技术侧的具体形态见 `03` §7）：第二物理后端、通用机器人平台与机械臂/产线、云端训练服务、Nav2/ROS2 运行时、把命令行当使用者门槛。

## 15. 本文件的维护规则

1. **只写"怎么落地"**：定位与边界进 `01`，上游依据进 `03`，参数进 `04`，状态进 `05`。
2. **按需求组织，不按模块组织**：新增一节前先问它服务哪条需求；答不上来就不进这份文档（与 `01` §5 的选型规则同口径）。
3. **不抄会漂的数字**：能写进本文件的数字，必须是 `05` §0 已被门禁守住的值；新增的会漂数字放门禁输出。
4. **引用走路径不抄内容**：涉及具体实现时给文件路径，让读者去代码看，避免两处维护。
5. **每个能力都要有上游依据**：新增能力时先在 `03` §1 的分类里找到它的出处；找不到，就先立依据再动手（`03` §8.2 的准入顺序）。
6. **改动要留否决理由**：重要选型变更除了写"选了 A 和为什么"，还要写"**为什么不选 B/C/D**"——不写，同一个问题过几个月会被重新争论一遍。

**取舍顺序（排期用）**：需求之间按主线 `进得来 → 改得动 → 走得完`；**同一条需求内部**按下面这个顺序优先（原项目价值观文档已删除，正文不再维护，**只保留顺序**供排期使用）：

```
可追溯  >  契约  >  分层隔离  >  差异数据化  >  单一事实源
        >  只读版本化  >  减法  >  证据等级  >  零命令行
```
