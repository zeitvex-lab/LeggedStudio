> **日期**：2026-09-13 ｜ **对应任务**：B19（完整克隆）、B20（跨源对照工具）
> **方法来源**：用户提出（见任务清单 §方法固化），并已在 g1 上验证有效。
> **结论一句话**：**clone 不进 `00_resources`**（那是要 git 上传的，带历史的克隆实测 ~5.2 GB）；
> 克隆落在**工作区外** `/00_open/<name>`，仓库里只登记**上游地址 + commit + 用途**。

---

## 1. 为什么需要「完整 clone」（非浅克隆）

`00_resources/*` 全是**文件快照、没有 `.git`**——只能回答"现在是什么值"，
**回答不了"这个值是什么时候被改的、被去掉的"**。而浅克隆（`--depth 1`）同样只有 1 个 commit，
一样查不了历史。所以：**官方源要完整克隆**（本次实测 5 个仓共 20–488 个 commit）。

## 3. 用法（B20 工具）

```bash
python tools/cross_source_audit.py                # 全 14 机型
python tools/cross_source_audit.py unitree_g1     # 单机型
python tools/cross_source_audit.py --json         # 机器可读
```

判定口径（**工具只列事实，不替你判"谁对"**）：

| 现象 | 判定 |
|---|---|
| 多源一致、与我方不同 | **我方错**（应改我方） |
| 源间不一致（不同版本给不同值） | **版本差异**（登记，改数需人工拍板） |
| 任何源都没有 | **原本没有**（登记缺口；或按官方写明的公式推导，不猜） |

> 工具**不进 CI**：它依赖 `/00_open/` 的本地克隆，CI 里没有这些源（会全部报"无源"，没有意义）。
> 想在 CI 用需要先把源做成可获取的（体积/许可都要先决策）。

## 4. 已知局限（下次要补）

1. **关节名别名**：官方 URDF 里轮腿机的轮叫 `*_foot_joint` / `*_foot_motor_joint`，我方契约叫 `*_wheel_joint` → 会被报成"无源"。需要一张 per-robot 的关节名别名表。
2. **快照噪声**：`00_resources` 里同一机型常有 6–10 份副本（第三方工程各自 vendored），版本混杂 → "源间冲突"计数噪声大。应以**官方克隆**为一等源、快照为参考。
3. **只比 `effort` / `velocity`**：`armature` / `friction_loss` / 刚度阻尼还没纳入对照（URDF 侧无对应字段，需从训练常量抽）。

### 「还缺什么」按严重度归类

1. **执行器段整体缺失**（`unitree_b2w` 我方 `nu=0`）：包内 MJCF 没有 `<actuator>`，完全依赖运行时
   `apply_actuator_rebuild()` 重建。**任何不走我们那条路径的加载**（别人的评估脚本、mjlab 直接读 XML、
   第三方工具）都会得到"没有执行器"的模型。
2. **关节级物理量在 MJCF 文件里是空的**（g1：`frictionloss 0 vs 0.2`、`damping 0 vs 0.05`；
   go2/go2w 的 `damping` 又与官方不同）：我们把这些值放进**契约**、运行时注入——设计上是"单一真值"，
   但代价是**MJCF 单独拿出来就不是完整模型**。
3. **接触参数体系性不同**（go2 37 处、go2w 75 处、b2w 8 处）：摩擦 `0.6 vs 0.4`、
   `conaffinity 2 vs 1`、go1 的 **`cone` 摩擦锥 `pyramidal` vs `elliptic`** + `impratio 1 vs 100`。
   接触参数是 sim2sim/sim2real 偏移最常见的来源，且**不会报错**。
4. **积分器与求解器设置不同**（g1：`integrator IMPLICITFAST vs Euler`、`iterations 10 vs 100`、
   `ls_iterations 20 vs 50`）：数值结果会不同，属"有意 vs 无意"需人判。
5. **`timestep` 是占位值**（go2 0.02、go2w 0.005、g1 0.005，官方统一 0.002）：运行时由
   `model.opt.timestep = 1/physics_hz` 覆盖；但**文件里的值会误导**任何静态解读。
6. **结构与质量差异**：g1 `torso_link 7.818 vs 9.598`（差 23%）、go1 12 个体质量不同且关节
   **`range` 不同**（`-0.802851 vs -0.863`）；go2 官方有独立 `*_foot` body 而我方合并（nbody 14 vs 18）。
7. **几何数量**：g1 少 5 个、go1 少 24 个（多为 mesh/碰撞几何）——影响碰撞行为。

### 工具局限（下轮补）

* `ctrlrange` 被当作力上限：对 `<motor>`（gear=1）成立，对 position/velocity 执行器不成立 → 应优先
  `forcerange`/`actuatorfrcrange`，`ctrlrange` 仅作兜底；
* 关节**命名差异**未处理（官方 `*_foot_joint`/`*_foot_motor_joint` ↔ 我方 `*_wheel_joint`）；
* 只比了关节/几何/质量/执行器/option，**默认类（`<default>`）、`<contact>` 对、`<equality>` 约束、
  传感器段**还没比。
