# Legged Studio 产品愿景

Legged Studio 是面向足式机器人强化学习的 Windows 工作台。它把模型资产验证、Robot Contract、训练配置、仿真评估和部署产物放在同一条可追溯链路中，目标是让用户从一个 URDF/MJCF 文件开始，得到可复现的训练与验证结果。

## 用户入口

桌面程序只负责生命周期和工作区管理。打开程序时不修改环境、不安装依赖；用户点击“一键启动”后，程序才会依次创建工作区目录、探测 Python、按 `backend/requirements.txt` 补齐控制平面依赖、启动本地 FastAPI，并打开 Web 工作台。

## 闭环工作流

1. **模型验证**：选择 Go2/Go2W 等版本化 preset，检查 URDF/MJCF、关节映射、质量和控制频率，生成或修订 Robot Contract。
2. **训练配置**：选择任务、PPO 算法、设备、环境数量、迭代次数和奖惩项；每个奖惩项可单独启用并调权重。
3. **训练与基础仿真**：提交任务后实时查看状态、迭代、奖励和日志，可停止任务；训练产物写入用户工作区。
4. **评估与 Sim2Sim**：训练完成后运行多回合评估，记录平均奖励、速度、成功率和标准差，形成可复核结果。
5. **导航回放**：在场景和命令序列上回放 locomotion policy，为导航、障碍物和路线任务保留 Scenario Contract 扩展点。
6. **导出与部署准备**：生成 ONNX、PolicyArtifact 和部署配置；真实机器人上电、放行和执行始终需要人工确认。

## 产品边界

- MVP 冻结为 Go2 + MJLab/PPO + 本地 MuJoCo 评估，其他后端通过 adapter 接入。
- Robot Contract、PolicyArtifact 和 Scenario Contract 是跨模块的事实来源，禁止在 UI、训练器和部署脚本中重复维护关节顺序或观测布局。
- 不把本地资产清单、文件存在或单次导入成功描述成完整产品能力；能力状态必须区分候选、已验证和已闭环。
- Python/CUDA 依赖按运行时隔离，控制平面启动和训练 adapter 的环境不强行合并。

## 验收标准

- 双击桌面程序不会自动写入或安装；点击“一键启动”后才执行配置。
- 后端健康检查通过后，Web 工作台可直接进入模型验证、训练、仿真和评估页面。
- 同一份 Robot Contract 能被验证、训练、评估和导出流程共同读取。
- 训练停止、失败和桌面退出后不残留失控的子进程，日志和产物可定位。
