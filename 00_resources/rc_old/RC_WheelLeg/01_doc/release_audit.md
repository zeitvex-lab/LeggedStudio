# 发布前内容审计与待确认事项

> 审计基线：`main` 的 `v1.1.1` 之后工作树，日期 2026-07-27。本文区分“仓库可证实”和“需要项目负责人确认”，避免把代码存在、历史文件名或注释直接写成实机/比赛事实。

## 证据等级

- **源码可证实**：可由当前文件、Tag、Git 差异、默认配置或模型哈希直接核对。
- **历史记录**：原目录名、注释、媒体或整理过程有记录，但本次没有重新运行对应硬件/训练环境。
- **负责人确认**：比赛成绩、真实上机使用、机械验证和授权信息无法只靠仓库证明，需要负责人确认后才能作为公开结论。

本轮逐项检查项目自有 Markdown、关键 README、训练入口配置、真机默认配置、关键代码注释和路径边界。`mjlab` 上游源码及 Odin 厂商驱动的原始说明不按自研文档重写，只检查其在本仓库中的归属和授权边界。Windows 环境未执行 ROS 2、SocketCAN、Odin SDK、TensorRT 或真机闭环。

## 模块逐项结论

### 机械

- `02_mechanical` 当前只归档 CAD、STEP 和源说明，没有独立 URDF、BOM、二维工程图、装配手册或 CAD-MJCF 参数核对报告。
- 文件数量和整机入口可由仓库核对；“SolidWorks 26”、比赛最终机械状态及实机结构验证需要负责人确认。
- 顶层目录说明已改为“当前归档 CAD/STEP”，不再暗示 URDF 已存在。

### 硬件与固件

- `03_hardware` 只有范围说明，不是完成的硬件开源包。
- `04_firmware` 是 16DOF 预留入口；8DOF Keil 工程只在历史分支/Tag。Keil 工程属于源码工程，不应写成只有 HEX 固件。
- 公开前需要决定是否补充 16DOF 接线、BOM、计算平台和传感器安装说明。

### 训练、MJCF 与策略

- 当前训练源码的 166 个 Python 文件可通过语法解析；这不等于依赖可安装、训练可收敛或结果可复现。
- 当前代码可证实：`0.005 s` 物理步长、`decimation=4`、50 Hz、2048 环境、腿部 `Kp=50/Kd=1.5`、轮部阻尼 `1.0`、腿动作缩放 `0.125/0.25`、轮速缩放 `5.0`。
- `MAX_JOINT_VEL=13` 只是当前未传给 Builtin actuator 的参考常量，不能写成已生效限速。
- `rl_cfg.py` 当前值是 entropy `0.003`、5 epochs、4 mini-batches；旧注释中的 `0.001/0.0008` 和 4096 环境方案只是历史候选，最终 checkpoint 参数需负责人确认。
- `apply_continuous_disturbance` 仍有实现和导入，但当前 Rough 事件配置没有启用持续外力；文档不能把它写成当前已启用项。

### MuJoCo、Sim2Sim 与导航工具

- 工具入口和依赖文件存在，但本轮没有逐个启动 GUI、MPC、Sim2Sim 或导航实验。
- 抽样 PCD 适合 Git/预览和路线工具，不应描述为完整原始建图数据。
- v2 PCD 三维查看器缺少原工程的 `three.module.js` 和 `OrbitControls.js`。服务端现改为本地 `vendor/` 或 `--vendor-dir`，README 已明确全新克隆不能直接加载三维页面。

### Python 真机代码

- `ik_real` 中的备份脚本和图片输出仍含旧开发机绝对路径，已在 README 标为历史记录，不应当作开箱即用入口。
- 第一代 `sim2real` 优先使用仓库内驱动，但仍保留旧 `/home/rc2/...` fallback；部署清单模型路径已改为仓库相对路径。
- Python v2 的标定工具也保留旧路径 fallback。若希望公开主线完全无私人路径，需要负责人决定是清理、环境变量化还是保留历史原貌。

### ROS 2 三代工程

- 无后缀目录是 `v0.10.0` 初版；`_v2` 当前保存 `v0.12.0` odom 快照；`_v3` 是 `last_not_slalom_1050` 最终工程。该命名关系已统一。
- 初版启动文件虽然默认 `launch_driver:=true`，但对应驱动源码缺失；部署指南已改为先用 `dry_run:=true launch_driver:=false`，不再给出必然失败的默认启动命令。
- 三代 `deployment_contract.yaml` 都只是 C++ 契约的可读参考，运行时不读取它；其中模型路径和缺失 PT 来源已按各快照实际文件校正。
- v2/v3 部署指南原先把 `launch_nav2` 错写成默认 `true`；实际 launch 文件默认 `false`、`launch_simple_nav=true`，现已按代码修正。
- 三代遥控文档已按实际配置修正 deadzone、速度上限和急停锁存语义；v3 还明确区分 `launch_remote=true` 与 `remote_enabled=false`，并删除源码中不存在的急停通道/消抖参数。
- 遥控话题链路已修正为 `cmd_vel_remote -> cmd mux -> cmd_vel -> policy`；v2/v3 默认仲裁模式是 `NAV`，必须切换到 `REMOTE` 才会采用遥控速度。
- v3 遥控/Web 调试命令默认改用 odom fallback，避免全新克隆在缺少 `1hao.bin` 时误启动不可用的 relocal 配置；Web 限幅也已校准为 `0.9/0.3/0.85`。
- v2/v3 架构和遥控文档不再写成“只加载 ONNX”；源码实际是 TensorRT 优先、ONNX Runtime 回退。
- `competition_yaw_configuration.md` 已从“最终配置”改为历史草案，并列出与当前 `runtime.yaml` 的真实差异；原文引用的路线和地形文件在 v3 中并不存在。
- v2/v3 Odin 点云重投影代码中的 `Til=(-0.02663, 0.03447, 0.02174)` 是设备绑定值，已改注释为“换设备必须重标定”，但数值来源仍需负责人确认。
- Odin README/CHANGELOG 中的 `v0.10.x`、`v0.12.0` 是厂商驱动/固件版本，不是项目 Tag；它们与 ROS `package.xml=0.0.1` 也不完全一致，已加归档提示但未篡改厂商编号。
- v3 `calib.yaml` 含设备标识 `O1-P040100042`，公开前需确认是否匿名化。
- v3 默认 `relocal`，但比赛使用的 `map/1hao.bin` 未归档；没有该文件时只能按文档使用 odom 模式，不能声称重定位闭环可复现。
- 触控屏程序同样默认 `relocal`；屏幕 README 已补充 `SIM2REAL_LOCALIZATION_PROFILE=odom` 的缺图启动方式。
- 自研 ROS 包目前有 15 个 `Proprietary` 清单字段；三个 `sim2real_nav2` 包虽写 MIT，但维护者仍是 `USER <31560@todo.todo>`。必须在公开发布前统一。

### 第三方、模型与媒体

- 仓库没有覆盖自研内容的顶层许可证。
- Odin 驱动源码目录带 Apache-2.0 许可证，但不能据此自动推断 `liblydHostApi_arm.a`、`liblydHostApi_amd.a` 等 SDK 静态库允许再分发。
- TensorRT engine 与比赛机软件栈/GPU 绑定，应视为归档工件而非通用二进制。
- 模型权重、比赛图片和视频也需要确认作者、队伍和赛事发布权限。
