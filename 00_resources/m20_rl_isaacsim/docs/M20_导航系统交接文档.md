## 1. 系统架构总览

```
start_m20_nav.sh
       │
       ▼
m20_nav_app.py （主入口，CLI解析 + 主循环 + 规划器 + 控制器）
       │
       ├── 依赖 cli_args.py（RSL-RL CLI 参数）
       ├── 依赖 rl_utils.py（camera_follow 辅助函数）

       │                                      │
       │                                      ├── 继承 rough_fixed_obstacle_env_cfg.py
       │                                      │       └── 继承 velocity_env_cfg.py (基类)
       │                                      ├── 使用 m20_sensors_cfg.py（传感器参数）
       │                                      └── 加载 3DGS USDZ 场景
```

## 3. 启动流程详解

### 3.1 `start_m20_nav.sh` 执行步骤

```bash
# step1: source ROS2 环境
source ~/IsaacSim-ros_workspaces/build_ws/jazzy/jazzy_ws/install/local_setup.bash
source ~/IsaacSim-ros_workspaces/build_ws/jazzy/isaac_sim_ros_ws/install/local_setup.bash

# step2: 检查 m20_nav_app.py 和 onnx 文件是否存在

# step3: 启动仿真
python scripts/reinforcement_learning/rsl_rl/m20_nav_app.py \
    --task=PerceptionFixedObstacle-Deeprobotics-M20-v0 \
    --onnx=exported/m20_new_policy.onnx \
    --nav \
    --enable_ros2_bridge \
    --real-time \
    --goal_x 32.0 \
    --goal_y -53.0
```

**参数说明：**
- `--headless`：无 GUI 模式，键盘通过终端读取
- `--nav`：启用混合导航模式（A* 规划 + 键盘覆盖）
- `--goal_x / --goal_y`：导航目标点（世界坐标）
- `--real-time`：实时限速（每帧 sleep 保持真实时间步长）

### 3.2 `m20_nav_app.py` 启动顺序

```
1. CLI 参数解析（argparse + AppLauncher）
2. Isaac Sim AppLauncher 初始化（app_launcher = AppLauncher(args_cli)）
3. 导入所有依赖（在 app_launcher.app 之后）
4. @hydra_task_config 解析任务配置（env_cfg, agent_cfg）
5. 根据模式（keyboard/nav/cmd_vel）修改 env_cfg
6. gym.make(task, cfg=env_cfg) 创建环境
7. 3DGS 碰撞体初始化（apply_collision_to_3dgs）
8. 构建 ROS2 Bridge OmniGraph
9. 主循环 while simulation_app.is_running():
   a. 处理键盘请求（规划/取消/回家）
   b. 路径跟踪（A* nav mode）
   c. cmd_vel 注入（cmd_vel mode）
   d. ONNX 策略推理 → env.step()
   e. 实时限速 sleep
10. 清理退出
```

## 4. 场景配置体系

### 继承层次

```
velocity_env_cfg.py:LocomotionVelocityRoughEnvCfg (基类)
    └─ rough_env_cfg.py:DeeproboticsM20RoughEnvCfg (M20 粗糙地形)
        └─ rough_fixed_obstacle_env_cfg.py:DeeproboticsM20FixedObstacleEnvCfg
            └─ m20_perception_env_cfg.py:DeeproboticsM20PerceptionEnvCfg (最终)
```

### 场景定义链

```
MySceneCfg (velocity_env_cfg.py)
    └─ DeeproboticsM20FixedObstacleSceneCfg (rough_fixed_obstacle_env_cfg.py)
        └─ DeeproboticsM20PerceptionSceneCfg (m20_perception_env_cfg.py)
```

### 关键差异

| 配置项 | Rough | RoughFixedObstacle | Perception |
|--------|-------|--------------------|------------|
| 地形 | 程序化粗糙地形 | 平面 | 平面（无 terrain） |
| 障碍物 | 无 | 平台 + 三级台阶 | 3DGS USDZ 场景 |
| 传感器挂载点 | 无 | 无 | 相机/雷达/IMU 挂载点 |
| 随机化 | 完整 | 全部禁用 | 全部禁用 |
| num_envs | 可配置 | 1 | 1 |
| RayCaster mesh | `/World/ground` | `/World/ground` | `/World/envs/env_0/gauss/gauss/mesh` |

## 6. ROS2 Bridge 图（OmniGraph）

### 6.1 节点拓扑（`ros2_bridge_graph_m20.py`）

```
OnPlaybackTick ─┬── ClockPub
                ├── OdomCompute ──┬── OdomPub
                │                 ├── OdomTfPub
                │                 └── SensorTfPub ──→ TF (所有传感器)
                ├── CameraRP ──┬── CameraRgbPub
                │              └── CameraInfoPub
                ├── FrontLidarRP ── FrontLidarPub
                ├── RearLidarRP  ── RearLidarPub
                └── ReadImu ── ImuPub
```

节点类型：

| 节点 | 类型 | 用途 |
|------|------|------|
| `OnPlaybackTick` | `omni.graph.action.OnPlaybackTick` | 驱动所有流程 |
| `ReadSimTime` | `isaacsim.core.nodes.IsaacReadSimulationTime` | 仿真时间 |
| `ClockPub` | `isaacsim.ros2.bridge.ROS2PublishClock` | `/clock` |
| `OdomCompute` | `isaacsim.core.nodes.IsaacComputeOdometry` | 里程计计算 |
| `OdomPub` | `isaacsim.ros2.bridge.ROS2PublishOdometry` | `/odom` |
| `OdomTfPub` | `isaacsim.ros2.bridge.ROS2PublishRawTransformTree` | `odom → base_link` TF |
| `SensorTfPub` | `isaacsim.ros2.bridge.ROS2PublishTransformTree` | 传感器 TF 树 |
| `CameraRP` | `isaacsim.core.nodes.IsaacCreateRenderProduct` | 相机渲染产品 |
| `CameraRgbPub` | `isaacsim.ros2.bridge.ROS2CameraHelper` | 相机 RGB |
| `CameraInfoPub` | `isaacsim.ros2.bridge.ROS2CameraInfoHelper` | 相机内参 |
| `FrontLidarRP` | `isaacsim.core.nodes.IsaacCreateRenderProduct` | 前雷达渲染产品 |
| `FrontLidarPub` | `isaacsim.ros2.bridge.ROS2RtxLidarHelper` | 前雷达点云 |
| `RearLidarRP` | `isaacsim.core.nodes.IsaacCreateRenderProduct` | 后雷达渲染产品 |
| `RearLidarPub` | `isaacsim.ros2.bridge.ROS2RtxLidarHelper` | 后雷达点云 |
| `ReadImu` | `isaacsim.sensors.physics.IsaacReadIMU` | IMU 读取 |
| `ImuPub` | `isaacsim.ros2.bridge.ROS2PublishImu` | `/m20/imu/data` |

### 6.2 传感器 TF 树

`SensorTfPub` 发布以下 prim 的静态 TF：

```
base_link
  ├── front_camera（前相机）
  ├── front_lidar_mount
  ├── front_lidar（前雷达）
  ├── rear_lidar_mount
  ├── rear_lidar（后雷达）
  ├── body_imu_mount
  └── Imu_Sensor
```

### 6.3 `ros2_bridge_graph_m20_1.py` 的差异

四环视版本增加后/左/右三路相机（共 4 路），节点数量从 16 增加到 28，新增：

```
RearCameraRP → RearCameraRgbPub + RearCameraInfoPub
LeftCameraRP → LeftCameraRgbPub + LeftCameraInfoPub
RightCameraRP → RightCameraRgbPub + RightCameraInfoPub
```

## 7. 三种控制模式

三者**互斥**，通过 `--keyboard`、`--nav`、`--cmd_vel` 选择。

### 7.1 键盘模式 `--keyboard`

纯手动遥控，适合建图阶段。

```bash
python m20_nav_app.py --task=PerceptionFixedObstacle-Deeprobotics-M20-v0 --onnx=policy.onnx --keyboard
```

键位（Isaac Sim 窗口焦点）：

| 按键 | 功能 |
|------|------|
| `↑/↓/←/→` | 前后左右平移 |
| `N/M` | 左转/右转 |
| 松键 | 速度归零 |

### 7.2 自主导航模式 `--nav`

加载 ROS 占用栅格地图，Hybrid A* 规划 + WaypointFollower 跟踪。

```bash
python m20_nav_app.py --task=... --onnx=policy.onnx --nav \
    --map_yaml /path/to/map.yaml \
    --goal_x 5.0 --goal_y -3.0
```

**运行时键位：**

| 按键 | 功能 |
|------|------|
| `K` | 规划路径并立即执行 |
| `G` | 仅规划（预览） |
| `P` | 使用上次路径启动自动跟踪 |
| `C / Space` | 取消自动导航 |
| `↑↓←→ / N/M` | 键盘手动接管 |
| `R` | 停止导航，传送回初始位置 |
| `T` | 多路径巡游模式 |

**键盘优先机制**：键盘按下后 0.5 秒内键盘速度覆盖自动路径输出，松键超时后自动恢复路径跟踪。

**多路径巡游（T 键）**：生成 N 条（默认 5 条）随机扰动路径，逐条执行，每条走完后传送回原点再走下一条。

### 7.3 外部速度模式 `--cmd_vel`

订阅 ROS2 `/cmd_vel` 话题，用于接入 Nav2 等外部导航栈或速度响应测试。

```bash
python m20_nav_app.py --task=... --onnx=policy.onnx --cmd_vel
```

测试命令：
```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.5}, angular: {z: 1.0}}'
```

**速度注入机制**（`_inject_velocity_command`）：
1. 覆盖 `command_manager.get_command("base_velocity")` 的公开 buffer
2. 同步覆盖命令项的 `vel_command_b` 内部 buffer
3. **Monkey Patch**：冻结命令项的 `compute()` 方法为空函数，阻止 Isaac Lab 内部重置速度指令

**超时机制**：1.2 秒未收到 /cmd_vel 消息，速度自动归零。

## 8. 路径规划系统

### 8.1 地图加载

可使用isaac sim occupacymap生成2D栅格地图
读取 ROS 标准占用栅格地图：

```python
# 地图 YAML 格式：
image: full_warehouse.png
resolution: 0.05
origin: [-10.0, -10.0, 0.0]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.196
```

### 8.2 GridMap2D

`m20_nav_app.py` 内联类。核心功能：

- `world_to_grid(x, y)` / `grid_to_world(i, j)`：世界坐标 ↔ 栅格坐标
- `inflate(radius_m)`：障碍物膨胀（GPU CuPy > SciPy > Python 回退）
- `compute_obstacle_distance_map_m()`：欧几里得距离变换，用于 A* 的 clearance cost
- `nearest_free_cell(i, j)`：找最近的空闲单元格（路径起点/终点可能在障碍物内时使用）

### 8.3 双层膨胀策略

`HydridCmdVelSource._load_planner_grid()` 实现：

```
原始地图
  ├── 硬膨胀（机器人物理半径 0.35m）→ hard_map：A* 完全不可通行
  ├── Slim 地图（60% 硬膨胀 → 0.21m）→ slim_map：Bresenham 视线检测
  └── 软膨胀（用户指定的 inflation_radius）→ clearance cost 距离变换
```

### 8.4 AStarGridPlanner

A* 搜索特性：
- 支持 8 方向移动（允许对角线 `√2` 代价）
- **Clearance Cost**：根据到最近障碍物的距离添加代价惩罚，引导路径走宽阔区域
- **Bresenham 视线检查**：路径简化时确保视线内无遮挡
- **RDP 路径简化**（Ramer-Douglas-Peucker）
- **拐点注入**：在大角度拐弯处插入过渡点，使路径跟踪更平滑
- **路径均匀重采样**：保持航点间距一致

A* 参数（脚本顶部常量）：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `ASTAR_ALLOW_DIAGONAL` | True | 允许对角线移动 |
| `ASTAR_USE_CLEARANCE_COST` | True | 启用清障代价 |
| `ASTAR_CLEARANCE_SAFE_DIST` | 0.5m | 安全清障距离 |
| `ASTAR_CLEARANCE_COST_WEIGHT` | 6.0 | 清障代价权重 |
| `ASTAR_SIMPLIFY_PATH` | True | RDP 路径简化 |

## 9. 路径跟踪控制 WaypointFollower

内联在 `m20_nav_app.py` 中的纯路径跟踪控制器。

### 控制逻辑

每帧执行 `compute_command(x, y, yaw) → (vx, vy, wz)`：

1. **段状态计算**：计算当前段（`waypoints[index-1] → waypoints[index]`）的横向偏差（Cross Track Error, CTE）和到达距离
2. **冻结/卡死检测**：300 步内移动 < 0.02m 则强制推进到下一段
3. **拐角处理**：在拐点先原地旋转对准下一段，再前进
4. **到达判定**：距离 < `REACH_TOL`（拐角 0.40m / 普通 0.40m）时推进到下一段
5. **速度计算**：
   - `desired_heading`：根据 CTE 修正的段朝向
   - `wz`：比例控制偏航
   - `vy`：横移修正（抑制 CTE）
   - `vx`：距离比例 + 减速区缩放 + 边转边走余弦缩放
6. **终点处理**：到达最后航点后停止

### 关键参数

```python
AUTO_REACH_TOL        = 0.40    # 到达判定半径 (m)
AUTO_SLOWDOWN_RADIUS  = 0.80    # 减速区半径 (m)
AUTO_KP_FWD           = 1.000   # 前向 P 增益
AUTO_KP_YAW           = 1.20    # 偏航 P 增益
AUTO_CTE_GAIN         = 2.0     # 横向偏差增益
AUTO_SEGMENT_LOOKAHEAD= 0.35    # 前瞻距离
AUTO_CORNER_ANGLE_DEG = 35.0    # 拐角判定角度
AUTO_MAX_VX           = 2.00    # 最大线速度
AUTO_MAX_WZ           = 1.50    # 最大角速度
```

## 11. 3DGS 碰撞体初始化

Perception 环境加载的 3DGS USDZ 场景**不自带碰撞体**，需要在运行时通过 `apply_collision_to_3dgs()` 手动添加：

```python
def apply_collision_to_3dgs(prim_path, approximation="none"):
    # 遍历 prim 下所有 UsdGeom.Mesh
    for prim in Usd.PrimRange(root_prim):
        if prim.IsA(UsdGeom.Mesh):
            UsdPhysics.CollisionAPI.Apply(prim)
            UsdPhysics.MeshCollisionAPI.Apply(prim)
            # "none" = 直接三角网格（最精确，推荐用于 lidar）
            # "convexDecomposition" = 凸分解（性能好）
```

**碰撞体对 RTX LiDAR 非常重要**：如果没有碰撞体，LiDAR 光线追踪检测不到 mesh，点云为空。

执行时间线：
```
env 创建后 → apply_collision_to_3dgs → 仿真走 5 帧确保注册 → 开始主循环
```

## 12. 机器人复位/传送机制

`_full_reset_robot(env, x, y, yaw)` 实现完整状态重置：

```python
with torch.inference_mode():
    # 1. 设置根节点位置 + 四元数
    root_state = robot.data.default_root_state.clone()
    root_state[0, 0] = x
    root_state[0, 1] = y
    root_state[0, 3] = cos(yaw/2)  # w
    root_state[0, 6] = sin(yaw/2)  # z
    root_state[0, 7:13] = 0.0      # 速度清零
    
    # 2. 写入物理引擎
    robot.write_root_state_to_sim(root_state, env_ids=env_ids)
    
    # 3. 关节状态清零
    robot.write_joint_state_to_sim(joint_pos, joint_vel, env_ids=env_ids)
    
    # 4. 重置内部缓存
    robot.reset(env_ids=env_ids)
```

**关键注意**：必须在 `torch.inference_mode()` 中执行，否则 PyTorch 会阻止对张量的 in-place 修改。

触发时机：
- R 键：传送回初始位置
- 多路径巡游（T 键）：走完一条路径后传送回 home

## 17. 常见问题排查

### ROS2 扩展未找到

报错：`extension not found: isaacsim.ros2.bridge`

解决：在 Isaac Sim 扩展管理器中搜索并启用 `isaacsim.ros2.bridge`、`isaacsim.sensors.rtx`、`isaacsim.sensors.physics`。

### 3DGS 碰撞体加载失败

现象：LiDAR 点云为空，或机器人直接穿过场景

检查：
- 确认 USDZ 文件路径正确
- `apply_collision_to_3dgs()` 中遍历到了足够的 Mesh prim
- 仿真启动后至少更新 5 帧让碰撞体注册

### A* 规划失败

"no path found" 或 "goal is not near a free cell"

可能原因：
- `--hard_inflation_radius` 太大导致起点/终点被障碍覆盖
- 目标点坐标超出地图范围
- 地图未知区域被视作障碍（`OCC_MAP_TREAT_UNKNOWN_AS_OCCUPIED = True`）

### ONNX 推理维度不匹配

现象：ONNX inference 报 shape 错误

原因：训练时的观测维度（obs_dim）与当前环境的实际观测不匹配。确认 `m20_nav_app.py` 的 `_extract_policy_obs()` 中的拼接逻辑正确，特别检查是否使用了 HIM 策略（`obs_history` + 当前 obs → 318 维）。

### IMU 传感器找不到

报错：`IMU sensor NOT FOUND`

解决：在 USD Composer 中打开 M20 USD 文件，在指定路径手动创建 IMU Sensor prim。

### 传送失败

机器人卡在原来位置不动

解决：确保 `_full_reset_robot` 在 `torch.inference_mode()` 上下文中执行。如果仍失败，可能 `robot.write_root_state_to_sim()` 需要多帧才能生效——可在传送后多走几帧空转。
