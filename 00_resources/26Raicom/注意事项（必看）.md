## 🔴 一、安全规范（重中之重）

### 1.1 人身安全
- **始终有人值守**：运行机器人时必须有人在旁边，随时准备急停
- **保持安全距离**：机器人启动前，确保周围 2 米内无人和易碎物品
- **机械臂运动范围**：D1 机械臂伸展半径约 50cm，运动时请勿靠近
- **跳跃动作最危险**：FrontJump 前跳前务必确认前方无人无障碍物

### 1.2 设备安全
- 不要在光滑地面上高速奔跑或跳跃（容易打滑摔倒）
- 机械臂不要强行超出限位（代码已做钳位保护，但手动控制时注意）
- 关机前先停止所有运动，不要直接断电
- 不要让机器人从高处跌落
- ⚠️ **宇树 D1 机械臂非常容易坏**：摔一下就可能坏掉，一定要保护好机械臂，比赛前绝对不能出危险
- ⚠️ **上台阶一定要保护好机器人**：机器狗一旦摔倒，会直接影响到机械臂，可能造成不可逆损坏
- 搬运机器人时机械臂收回至安全姿态，避免碰撞

### 1.3 紧急停止
- 方法一：`Ctrl + C` 终止程序（会触发安全停车流程）
- 方法二：使用宇树遥控器按急停
- 方法三：直接按机器人电源键（最后手段）

## 🔌 二、硬件连接与布线

### 2.1 接口清单

| 设备 | 接口类型 | 推荐连接位置 |
|------|---------|-------------|
| D435i 深度相机 | USB 3.0（蓝色） | 机器人 USB 3.0 口 |
| GC2093 USB 摄像头 | USB 2.0 | 任意 USB 口 |
| TinyF TOF × 3 | USB 转串口（CH340） | USB HUB 或直连 |
| D1 机械臂 | USB（控制线） | 机械臂专用接口 |
| USB 网卡 | USB | 拓展坞（可选） |

### 2.2 拓展坞选型（非常重要！）

> 🚨 **踩坑预警：不要买带网口的拓展坞！**
>
> 我们之前买的**绿联带网口的拓展坞**会干扰 D1 机械臂的 USB 通信，导致机械臂一直检测不到，排查了很久才找到原因。
>
> **推荐：选择不带网口的纯 USB 拓展坞**

#### 拓展坞用途
- 连接 **3 路 TinyF TOF 测距模块**
- 连接 **USB 网卡**（可选，用于有线网络）
- 连接 **GC2093 USB 摄像头**

#### Go2 Edu 拓展坞显示器功能
- Go2 Edu 的拓展坞上**带有显示器接口**
- 可以单独购买一个显示器，通过**雷电线（Thunderbolt）**直接调出拓展坞上的系统桌面
- 这样可以直接在机器人上操作，不用远程连接，调试和导入代码非常方便

### 2.2 TOF 传感器方向映射

> 默认映射（代码中已标注）：
> - `/dev/ttyUSB0` → **左侧**
> - `/dev/ttyUSB1` → **右侧**
> - `/dev/ttyUSB2` → **前方**

**验证方法**：运行 `python3 TOF_read3.py`，用手分别遮挡左/右/前方传感器，确认方向对应正确。

如果方向不对，有两种修正方式：
1. 交换物理接线
2. 修改 `TOF_read3.py` 中的 `SENSOR_LABELS` 映射

### 2.3 USB 带宽注意事项
- D435i 必须接 **USB 3.0**，否则深度流会卡顿或降帧
- 多路 USB 设备尽量分散到不同 USB 控制器（避免共用带宽）
- 如果出现摄像头丢帧，可考虑：
  - 降低 D435i 分辨率（从 640×480 降到 424×240）
  - 降低 GC2093 帧率
  - 跳跃期间自动关闭摄像头（代码已实现）

```bash

pip install opencv-python numpy pyserial

# RealSense SDK
pip install pyrealsense2

# 参考宇树官方文档安装 unitree_sdk2py
```

### 3.2 环境配置须知

> ⚠️ **代码不是复制过去就能用的！需要自己配置环境！**

需要配置的环境包括：
- **ROS2**：根据 Go2 机载系统版本安装对应 ROS2（推荐 Humble 或 Foxy）
- **宇树 SDK（unitree_sdk2py）**：机器人控制的核心库
- **RealSense SDK**：D435i 深度相机驱动
- **CycloneDDS**：DDS 通信库
- **串口权限**：TOF 传感器需要 dialout 组权限

**学习路径建议**：
1. 先学习宇树官方 SDK 的基本使用（怎么让机器人走路、跳跃）
2. 再学习 Go2 的动作调用 API
3. 最后再跑比赛代码

### 3.3 DDS 库修复

`dds_lib_fix.py` 用于修复 CycloneDDS 的库版本不匹配问题。**导入顺序很重要**：

```python
import dds_lib_fix  # 必须最先导入！
import cyclonedds
# ... 其他
```

如果不先导入 `dds_lib_fix`，可能出现：
- DDS 通信失败
- 段错误（segmentation fault）
- 找不到 `libddsc` 符号

### 3.4 网络配置

- Go2 默认 IP：`192.168.123.15`（或类似网段）
- 确保开发机和机器人在同一网段
- 有线连接（eth0）比 Wi-Fi 稳定，比赛时强烈推荐用有线
- 测试连接：`ping 192.168.123.15`

#### 📶 比赛现场网络应对
- **比赛现场人多，Wi-Fi 会非常卡**，强烈建议用**网线直连**
- 我们的代码需要用 **ToDesk** 调用画面，务必提前测试 ToDesk 在比赛网络环境下是否可用
- 准备备用方案：SSH + tmux / screen，即使远程桌面卡也能命令行操作
- 如果用拓展坞的 USB 网卡，注意不要和机械臂有冲突（参考拓展坞选型）

## 🎯 四、传感器校准指南

### 4.1 黑线检测（GC2093）

**关键参数**：`black_threshold`（二值化阈值）

**校准步骤**：
1. 将机器人放在场地上，对准黑线
2. 运行巡线代码，观察检测效果
3. 如果黑线检测不到（太暗）→ 降低阈值
4. 如果噪声太多（误检测）→ 提高阈值
5. 调整 `min_area` 和 `min_width` 过滤细小干扰

**经验值**：
- 室内普通光照：`black_threshold = 80 ~ 100`
- 强光环境：`black_threshold = 100 ~ 130`
- 暗光环境：`black_threshold = 60 ~ 80`

### 4.2 TOF 测距（TinyF）

**关键参数**：`MAX_DISTANCE`（最大有效距离）

- 规格书标称 4500mm，代码默认 4000mm（留余量）
- 深色墙面 / 吸光材质：有效距离会缩短，可适当调低
- 白色墙面 / 反光材质：可适当调高
- ⚠️ **测距偏移问题**：TinyF 测距模块的偏移可能较大，特别是按一下按钮后偏移会变得很大，使用前一定要重新校准偏移量

**毛刺滤波参数**：
- `SPIKE_DELTA_MM`：单帧跳变超过此值视为可疑毛刺
- `CONFIRM_FRAMES`：连续多少帧才采信跳变（默认 3 帧）

### 4.3 红圆检测（D435i）

**关键参数**：HSV 范围、圆形度阈值、最小面积

使用 `color_object_detector.py` 中的 Trackbar 调参：
```bash
python3 color_object_detector.py --color red
```

调节 HSV 上下限，直到画面中只显示红色圆形，没有其他红色干扰。

### 4.4 PID 参数

**每个 Phase 独立配置**，调参口诀：
1. 先设 **Ki=0, Kd=0**，从小到大调 Kp，直到出现轻微震荡
2. 然后加入 Kd，抑制震荡
3. 最后加少量 Ki 消除静差
4. 如果震荡严重 → 减小 Kp，增大 Kd
5. 如果响应太慢 → 增大 Kp

## 🦾 五、机械臂使用须知

### 5.1 参考姿态（零位）

IK 求解的参考原点由 `REF_JOINT_ANGLES` 定义。**不同批次的 D1 机械臂零位可能不同！**

代码中提供了两个版本：
- 版本 A：`[-90.0, 10.0, 55.0, 0.0, -61.0, 0.0, 60.0]`
- 版本 B：`[68.7, 10.0, 55.0, -2.0, -61.0, 1.0, 60.0]`

**确认方法**：
1. 机械臂上电后，记录初始角度
2. 手动将机械臂调整到你认为的"前方伸直"姿态
3. 记录此时的关节角度
4. 与参考姿态对比，调整 `REF_JOINT_ANGLES`

### 5.2 J4 关节补偿

由于 D1 机械臂的 J4（腕部俯仰）关节轴线偏移，需要额外的补偿系数：

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `j4_scale_y` | 0.73 | Y 方向每厘米补偿角度（deg/cm） |
| `j4-scale-x-pos` | 1.3 | X 正方向每厘米补偿角度 |
| `j4-scale-x-neg` | -0.1 | X 负方向每厘米补偿角度 |
| `j4_bias` | 0.0 | J4 固定偏置角（deg） |

**校准方法**：
1. 让机械臂对准已知位置的物体
2. 记录实际位置与 IK 计算位置的偏差
3. 根据偏差方向和大小调整对应 scale 参数
4. 反复迭代直到对准精度在 ±5mm 以内

### 5.3 坐标系统

```
        X+（前方）
          ↑
          |
Y+（左）←  +  → Y-（右）
          |
          ↓
        Z-（下方）
```

单位：**厘米（cm）**，夹爪单位是**度（deg）**。

### 5.4 最佳测距距离

> ⚠️ **机械臂 + D435i 的最佳测距距离：15 ~ 30 厘米**

- 在这个范围内，深度数据精度最高，IK 求解最准确
- **距离太近（<15cm）**：深度数据可能饱和或出现盲区
- **距离太远（>30cm）**：深度精度下降，加上机械臂 IK 累积误差，抓取精度会明显下降
- 抓取策略：先将机器人移动到目标约 20cm 处，再进行精细对准和抓取

### 5.5 常见机械臂问题

| 现象 | 可能原因 | 解决方法 |
|------|---------|---------|
| 夹爪夹不住物体 | 夹爪角度太小 | 增大 `gripper` 参数 |
| 目标点到达不了 | 超出工作空间 | 检查可达性，换一个更近的姿态 |
| 运动卡顿 | DDS 通信延迟 / IK 求解慢 | 检查网络，关闭其他占用带宽的程序；优化求解频率 |
| 角度反馈不动 | 舵机未使能 | 重新使能关节（funcode=5） |
| **检测不到机械臂** | **拓展坞干扰 / USB 冲突** | **拔掉带网口的拓展坞，换纯 USB 拓展坞** |
| 抓取位置不准 | 深度距离不在最佳范围 / J4 补偿不对 | 调整机器人位置到 15~30cm 区间，校准 J4 参数 |
| 运动不丝滑 | IK 步进不够平滑 | 可加入轨迹规划或插值 |

### 5.6 售后与维修

- **宇树科技售后非常好**，机器狗和机械臂出问题都可以联系售后
- 通过**学校采购方**联系售后，走官方修理或置换流程
- **不要自己拆机维修**，以免失去保修
- 比赛前确认售后联系方式，以防万一

## 🏃 六、步态与运动控制

### 6.1 步态选择

本项目主要使用 **ClassicWalk（经典步态）**，原因：
- 稳定性好，适合精细操作（抓取、对准）
- 速度可控，方便 PID 调节
- 对台阶、不平地面适应性强

其他步态（如普通 Walk）速度更快，但稳定性稍差，长距离快速移动时可以考虑。

### 6.2 速度档位 SpeedLevel

- **Level 1**：普通速度，适合平地巡线、迷宫
- **Level 2**：高扭矩模式，适合上台阶、负重

**注意**：切换 SpeedLevel 会自动切换步态，调用后需要重新执行 `ClassicWalk(True)` 才能回到经典步态。

### 6.3 控制频率

控制线程运行在约 **100Hz**（`CTRL_HZ = 100`），即每 10ms 下发一次运动指令。

不要将控制频率设得太高：
- DDS 通信有延迟，太高频率无意义
- 增加 CPU 负载
- 可能导致机器人运动不连贯

## 🏟️ 七、场地适配建议

### 7.1 赛前场地勘察
1. 带笔记本和摄像头到场地，实际测试黑线检测效果
2. 用 TOF 传感器实际测一下迷宫墙面的测距值
3. 观察光照条件，是否有强烈反光或阴影
4. 测量台阶高度和数量，调整上台阶参数
5. **踩踩地面**：感受地面软硬和摩擦力，和训练场对比

### 7.2 地面材质适配（重要！）

> 💡 不同地面材质对机器人步态影响很大，一定要提前测试！

| 地面类型 | 特点 | 注意事项 |
|---------|------|---------|
| **比赛场地（地毯/毛面）** | 较软、摩擦力大、不打滑 | 步态更稳，但速度可能需要调小 |
| **水泥地** | 硬、摩擦力中等 | 标准训练地面 |
| **瓷砖/地板** | 硬、光滑、容易打滑 | 跳跃和转弯要小心，降低速度 |

**适配建议**：
- 到比赛现场后，先在实际地面上测试基本行走和转弯
- 检查 PID 参数是否需要调整（软地面可能响应更慢）
- 测试跳跃动作是否会打滑
- **所有地面条件的参数都做好备份**，到现场可以直接调用

### 7.3 迷宫场地
- 墙面材质影响 TOF 读数：
  - 白色光滑墙面：测距远，读数稳定
  - 深色/粗糙墙面：测距近，可能有波动
- 如果迷宫墙体有缝隙/孔洞，毛刺滤波（`SpikeFilter`）会处理单帧跳变
- 如果缝隙太宽（多帧都是大值），需要增加 `CONFIRM_FRAMES`
- 半圆行走参数根据实际场地微调（每台机器狗有差异）

### 7.4 台阶场地
- **台阶高度**影响俯仰角阈值：
  - 台阶越高 → 俯仰角峰值越大 → `P3_PITCH_CLIMBING_THRESH` 可设大些
  - 台阶越矮 → 俯仰角峰值越小 → 需要调小阈值
- **台阶数量**影响：
  - 上台阶速度：台阶多可以冲快点，台阶少要慢
  - 下台阶时间：根据台阶数调整 `P3_STAIRS_DOWN_DUR`
- ⚠️ **上台阶一定要保护好机器人和机械臂**，失败摔倒可能损坏设备

### 7.5 光照条件
- **强烈阳光**：
  - 黑线检测阈值需提高
  - 摄像头可能过曝，降低曝光值
  - D435i 深度数据可能受干扰
- **昏暗环境**：
  - 摄像头噪点增多
  - 降低检测阈值
  - 提高增益（如果支持）

### 7.6 Phase 5 丢线点位适配

> 💡 我们的 Phase 5 利用了回头弯处的固定丢线点作为中转抓取位置的触发

- 这个"bug 点位"是特定场地的黑线布局决定的
- **换场地后需要重新确认**：
  1. 在新场地跑一遍 Phase 1~4，观察黑线是否会在固定位置丢失
  2. 如果丢线位置不同，调整 Phase 5 的触发条件
  3. 如果没有稳定的丢线点，建议改为主动识别中转标志（如地标、色块）
- 这是一个**有待优化**的点，有能力的同学可以改进为更通用的方案

## 🐛 八、调试技巧

### 8.1 分步调试

不要一上来就跑全流程！建议按以下顺序调试：

1. ✅ **传感器测试**：单独运行 TOF、摄像头、深度相机，确认硬件正常
2. ✅ **机械臂测试**：测试 IK 控制、夹爪开合，确认坐标正确
3. ✅ **单 Phase 调试**：每个 Phase 单独跑通
   - Phase 1：黑线循迹 + 跳
   - Phase 2：迷宫导航
   - Phase 3：台阶
   - Phase 4：抓取
   - ...
4. ✅ **联调**：相邻两个 Phase 串联测试
5. ✅ **全流程**：所有 Phase 串联跑一次

### 8.2 日志分析

代码中有详细的打印日志，格式统一：
- `[INIT]`：初始化信息
- `[P1]` ~ `[P8]`：各阶段运行信息
- `[CAM]`：摄像头相关
- `[ARM]`：机械臂相关
- `[ERROR]`：错误（红色，需要关注）
- `[WARN]`：警告（黄色，留意即可）

调试时重点关注：
- 状态切换是否正常（`[STATE] -> XXX`）
- 传感器读数是否稳定
- PID 输出是否有剧烈震荡

### 8.4 离线仿真

迷宫导航模块支持离线仿真，无需硬件即可验证逻辑：
```bash
python3 迷宫_tof.py eth0 --sim
```

会运行 4 项测试：
1. SpikeFilter 毛刺滤波
2. 横向纠偏控制律 vy
3. 多阶段状态机（模拟传感器场景）
4. `run_maze_navigation` 库函数接线

全部 PASS 说明逻辑正确，可以放心上机。

## 📞 十、问题排查速查表

| 问题 | 排查方向 |
|------|---------|
| **程序启动就报错** | 检查依赖是否安装、网络是否通、DDS 库是否正常 |
| **机器人不动** | 确认网络连接、检查 SportClient 是否初始化成功、查看遥控器是否接管 |
| **摄像头黑屏** | 检查设备索引、确认 USB 连接、尝试重启摄像头 |
| **TOF 无数据** | 检查串口权限（`sudo usermod -aG dialout $USER`）、确认波特率 115200 |
| **巡线走不直** | 检查 PID 参数、确认黑线检测稳定、检查机器人是否跑偏 |
| **迷宫撞墙** | 确认 TOF 方向、调整纠偏增益、降低速度 |
| **上台阶失败** | 调高 SpeedLevel、降低上台阶速度、调整俯仰阈值 |
| **抓取不准** | 校准 IK 参考姿态、调整 J4 补偿、确认深度数据准确 |
| **机械臂不动** | 确认舵机已使能、检查 DDS 通信、查看角度反馈 |

## 🧩 已知问题与可优化方向

### 视觉识别
- [ ] 红圆检测算法较基础，复杂光照下容易误检，可升级为 YOLO 等深度学习检测
- [ ] 模板匹配精度有限，可改用特征点匹配或深度学习
- [ ] 缺少多目标跟踪能力

### 机械臂控制
- [ ] 运动有轻微卡顿，可优化 IK 求解频率或加入轨迹规划
- [ ] J4 补偿参数较经验化，可通过标定优化
- [ ] 最佳测距范围有限（15~30cm），可增加近/远距离策略

### 巡线控制
- [ ] Phase 5 依赖固定丢线点，换场地可能失效，建议改为主动识别
- [ ] PID 参数通用性一般，每台机器狗需微调

### 其他
- [ ] 代码模块化程度可提升
- [ ] 缺少图形化调试界面
- [ ] 可考虑接入 ROS2 框架
