# 睿抗多模态比赛 Go2 四足机器人竞赛代码 — 国一（第六名）

> 🎉 本项目为 **睿抗（RAICOM）多模态机器人挑战赛** 全国一等奖（第六名）获奖代码。基于宇树 Go2 Edu 四足机器人 + D1 机械臂，实现了从黑线循迹、迷宫穿越、台阶上下、物体抓取到标志识别的全流程自主竞赛任务。

## 🤖 硬件清单

| 类别 | 设备 | 型号 / 规格 | 数量 |
|------|------|-------------|------|
| 机器人本体 | 四足机器人 | 宇树 Unitree Go2 Edu | 1 |
| 机械臂 | 七自由度机械臂 | 宇树 Unitree D1 | 1 |
| 深度相机 | 深度摄像头 | Intel RealSense D435i | 1 |
| 视觉相机 | USB 摄像头 | 200 万像素 GC2093（USB Live camera） | 1 |
| 测距传感器 | 激光/红外测距模块 | 亚博智能 TinyF 测距模块（TOF） | 3（左 / 右 / 前） |

### 传感器布局
- **GC2093 USB 摄像头**：安装于机器人头部前方，用于黑线循迹、白线检测、黑色区域识别、标志模板匹配等地面视觉任务（**额外增加的巡线专用摄像头**）
- **D435i 深度相机**：**安装于机械臂末端**，随机械臂移动，用于红圆检测 + 深度测距，辅助机械臂抓取对准
- **TinyF TOF 测距模块 ×3**：分别安装于机器人左前、右前、正前方，用于迷宫导航时的墙体距离检测

### 拓展坞配置
> ⚠️ **重要：Go2 Edu 机载 USB 接口有限，需通过拓展坞扩展**
>
> - 本项目使用拓展坞连接 **3 路 TOF 测距模块 + USB 网卡 + 摄像头**
> - **🚨 不推荐购买带网口的拓展坞**（如绿联带网口款），我们实测发现带网口的拓展坞会干扰 D1 机械臂的 USB 通信，导致机械臂检测不到，踩了很大的坑
> - 推荐选择**不带网口的纯 USB 拓展坞**
> - Go2 Edu 的拓展坞上带有**显示器接口**，可单独购买显示器，通过**雷电线（Thunderbolt）**直接调出拓展坞上的系统桌面，方便直接在机器人上调试和导入代码

## 🎮 比赛任务全流程（8 个 Phase）

### Phase 1：黑线循迹 + 白线检测 → 前跳
- 通过 GC2093 USB 摄像头采集地面图像
- OpenCV 二值化 + 轮廓检测识别黑色引导线
- **PID 控制器**实时计算偏航角纠偏，保持机器人沿黑线前进
- 检测到白色横切线时触发 **FrontJump 前跳**动作
- 跳跃期间自动关闭摄像头释放 USB 带宽，落地后自动重启并继续循线
- 跳后丢线 → 原地站立结束

### Phase 2：迷宫穿越（TOF 激光测距导航）
- 三路 TinyF TOF 传感器实时采集左/右/前墙体距离
- **五阶段状态机**：
  1. **靠右墙前进** — 入口处采样左右墙中间值，以右墙为参考保持距离
  2. **左回头弯** — 固定步态持续前进 + 左转（经典步态 Move）
  3. **跟左墙前进** — 弯道后右墙不可靠，切换到左墙参考
  4. **右转弯 + 跟右墙** — 第二个弯道后恢复右墙参考
  5. **收尾左转** — 左转弯时间减半，完成迷宫
- **半圆行走定点策略**：
  - 通过前向 TOF 和左右 TOF 检测距离进行定点定位
  - 到达指定位置后执行半圆形行走（弧形路径）
  - 到位后再次检测左墙和前方距离，继续行走
  - 走到指定位置后停下
  - 我们测试时非常稳定，10 次中约 1~2 次扣 5~10 分，基本没有 0 分
  - ⚠️ 每台机器狗的前进和左右旋转状态有差异，可根据比例调整半圆行走参数
- **毛刺滤波**：墙体缝隙导致的单帧距离跳变通过 `SpikeFilter` 过滤（需连续 `CONFIRM_FRAMES` 帧才采信）
- 减小方向读数不过滤，保证前方逼近时能及时触发停车

### Phase 3：巡线 + 黑区检测 → 上台阶 → 左转 → 下台阶
- **初始居中**：横向平移对齐黑线（超时强制进入下一步）
- **PID 巡线**：边跑边记录偏航角（采样取均值），作为上台阶目标朝向
- **黑区检测**：画面黑色像素占比超过阈值 → 触发上台阶
- **IMU 姿态闭环上台阶**：
  - 俯仰角偏离零 → 正在爬升，全速前进 + 偏航实时纠偏
  - 俯仰角回零 → 到达台阶顶部，立即停车
  - 顶部微调：后退 + 左平移，为左转留出空间
- **IMU 闭环左转**：台阶顶部原地左转 90°
- **下台阶**：ClassicWalk 直走下台阶（纯延时）
- **二次居中**：左旋搜索 → 右旋搜索 → 循线对齐，确保下台阶后重新对准黑线

### Phase 4：机械臂识别 + D435i 红圆检测 → OCR 识别平台标志 → 抓取
- D435i 深度相机安装在机械臂上，随机械臂运动，采集彩色 + 深度帧
- **红圆检测**：HSV 颜色分割 + 圆形度判别，定位抓取平台红色靶心
- 深度数据获取物体距离（mm 级精度），为机械臂提供精确的位置反馈
- **OCR 标志识别**：识别抓取平台编号（1号/2号），决定 Phase 7 放物方向
- **D1 机械臂 IK 控制**：
  - 基于 URDF 的正向运动学 + 阻尼最小二乘法（DLS/LM）逆运动学求解
  - 支持 XYZ 厘米级坐标直接控制
  - 关节限位保护 + 可达性检查
  - 夹爪开合角度独立控制
- 对准红圆 → 机械臂下降 → 夹爪闭合 → 提升 → 完成抓取
- ⚠️ **机械臂最佳测距距离 15~30cm**：超出此范围深度数据精度下降，IK 求解可能不准确

### Phase 5：循线 → 丢线放物 → 二次抓取
- 携带抓取物体沿黑线继续前进
- 利用了一个**"bug 点位"**：在回头弯处黑线会固定丢失，我们借此让机器人停在中转抓取位置
- 在此位置配合视觉识别，完成物体放置和二次抓取操作
- ⚠️ 该方案依赖特定场地的黑线布局，换场地需重新确认丢线位置

### Phase 6：循线 + USB 红圆检测 → OCR 识别警示标志 → 对应动作
- 沿黑线继续前进
- USB 摄像头检测红色圆形标志，出现→彻底消失后计时 2s
- 左转 85° → 后退
- **OCR 识别警示标志**（打招呼/伸懒腰/闪烁前灯三次），执行对应动作
- 识别模型与 Phase 4 共用，只加载一次

### Phase 7：右转 + 前进 + 循线 → 两侧黑色触发 → 放物
- 右转调整方向
- 前进到指定位置后继续循线
- 检测到两侧黑色区域（触发倒计时）→ 机械臂放置物体
- 放物方向由 Phase 4 OCR 识别的平台编号决定（1号=左，2号=右）
- 放物后前进 1.5s

### Phase 8：循线 + 白线检测 → 前跳 → 前进 → 左转 → 蓝色驱动前进
- 最后一段黑线循迹
- 白线检测触发最终前跳
- 前进 + 左转
- USB 摄像头检测画面下半部分蓝色区域占比，驱动机器人前进至终点

## 🔧 核心技术亮点

### 1. 多传感器融合
- **视觉 + 深度 + TOF + IMU** 多模态感知融合
- USB 摄像头负责地面视觉（循迹、标志检测）
- D435i 负责空间定位（红圆对准、深度测距）
- TOF 负责近距墙体检测（迷宫导航）
- IMU 负责姿态闭环（台阶、转弯）

### 2. PID 控制系统
- 所有循迹任务均使用带**积分抗饱和 + 输出限幅**的离散 PID 控制器
- 每个 Phase 独立配置 PID 参数（Kp / Ki / Kd / 最大输出 / 积分上限）
- 偏置修正（offset bias）补偿机器人身体偏移

### 3. 状态机架构
- 每个 Phase 内部采用**有限状态机（FSM）**设计
- 状态切换条件明确，便于调试和参数调整
- 所有可调参数集中在文件顶部常量区，真机调参无需改逻辑

### 4. 机械臂逆运动学
- 基于 D1 机械臂 URDF 参数的**解析雅可比**计算（非数值差分，精度更高）
- **阻尼最小二乘法（Damped Least Squares）**求解 IK
- 支持关节锁定（locked_joints），可固定特定关节
- 自适应阻尼因子 + 关节限位钳位保护
- 可达性分析器（Reachability Analyzer）提前预判目标是否在工作空间内

### 5. OCR 标志识别
- **YOLO 分类 + ORB 特征匹配**双路识别，加权融合置信度
- 支持 5 类标志：1号平台、2号平台、打招呼、伸懒腰、闪烁前灯三次
- 模型预加载：Phase 4 快跑段后台加载，Phase 4/6 共用同一实例
- 模板匹配兜底：YOLO 置信度不足时回退到 OpenCV 模板匹配

### 6. 硬件健壮性设计
- **TOF 动态端口检测**：每 1s 扫描 `/dev/ttyUSB*`，热插拔自动识别
- **无数据看门狗**：打开成功但长时间无有效帧时强制断开重连
- **摄像头自动重启**：`read()` 连续失败时停车并自动重启摄像头（防止 USB 总线复位导致的失明）
- **跳跃期间关闭摄像头**：释放 USB 带宽，避免落地震动导致丢帧
- **错开串口打开时刻**：避免多个 TOF 传感器同时上电导致个别设备静默

### 7. 离线仿真 / 逻辑自检
- 迷宫导航支持 `--sim` 参数离线验证状态机逻辑
- 内置单元测试：毛刺滤波、横向纠偏控制律、多阶段状态机、库函数接线
- 机械臂 IK 支持 `--dry-run` 离线测试求解精度

## 🧩 已知问题与可优化方向

> 本项目代码虽然获得了国一成绩，但仍有多处可改进的地方，欢迎各位同学继续优化：

### 视觉识别方面
- **红圆检测算法较基础**：当前使用简单的 HSV 颜色分割 + 圆形度判别，在复杂光照或背景干扰下容易误检/漏检，可考虑升级为深度学习目标检测（如 YOLO 系列）
- **模板匹配精度有限**：标志识别使用传统模板匹配，对角度和缩放敏感，可改用特征点匹配或深度学习
- **缺少多目标跟踪**：当前一次只处理一个目标，复杂场景下可能遗漏
- **OCR 识别不稳定**：比赛时动作识别不好，导致扣了 20 分，可优化模型或增加数据增强

### 机械臂控制方面
- **运动有轻微卡顿**：IK 求解 + DDS 通信链路较长，机械臂运动不够丝滑，可优化求解频率或加入轨迹规划
- **J4 补偿参数较经验化**：目前的 J4 关节补偿系数是实测调出来的，缺少严格的运动学推导，可通过标定优化
- **最佳测距范围有限**：15~30cm 范围内精度最佳，超出范围深度数据和 IK 精度均下降，可考虑增加近距离 / 远距离策略切换

### 巡线控制方面
- **Phase 5 依赖固定丢线点**：利用了回头弯处的丢线 bug 作为中转位置的触发条件，换场地可能失效，建议改为主动识别中转标志
- **PID 参数通用性一般**：每台机器狗的机械特性略有差异，PID 参数需要根据实际机器人微调

### 其他可优化点
- **代码模块化程度可提升**：部分 Phase 之间耦合较紧，不利于独立调试和复用
- **缺少图形化调试界面**：可考虑做一个实时显示传感器数据和状态的调试工具
- **可加入 ROS2 框架**：便于扩展更多传感器和算法模块

## ⚠️ 注意事项

### 🔴 安全第一

1. **运行前确保周围空间充足**，特别是跳跃、转弯、机械臂动作时
2. **始终有人值守**，随时准备按急停或遥控器接管
3. **第一次运行建议低速**，确认各传感器和控制正常后再提速
4. 机械臂运动前确认夹爪周围无障碍物

### 📡 通信与网络

1. Go2 默认 IP 段为 `192.168.123.x`，确保开发机在同一网段
2. 有线连接（eth0）比 Wi-Fi 更稳定，推荐使用有线
3. DDS 通信对网络质量敏感，网络延迟大会导致运动指令卡顿
4. `dds_lib_fix.py` 会预加载匹配的 `libddsc`，**请在导入 cyclonedds 之前导入**（位于 `视觉抓取/dds_lib_fix.py`）

### 🔌 USB 设备

1. **USB 带宽问题**：D435i + GC2093 + 3 路 TOF 同时使用时注意 USB 带宽
   - D435i 必须接 USB 3.0（蓝色接口）
   - 多个 USB 设备尽量分散在不同 USB 控制器上
2. **TOF 传感器端口映射**：默认 `ttyUSB0=左, ttyUSB1=右, ttyUSB2=前`，请根据实际接线确认
   - 使用 `测距模块/TOF_read.py` 实时查看三路读数，手遮挡验证方向
3. **摄像头索引**：代码会自动尝试 `/dev/video0,1,2,8`，如有其他 USB 摄像头可能占用索引
4. **热插拔**：TOF 支持热插拔自动检测，但建议开机前全部接好

### 🎯 传感器校准

1. **黑线检测阈值**：`black_threshold` 需根据场地光照调整
   - 推荐先运行巡线代码，用 Trackbar 实时调参
   - 场地越亮，阈值可设越高
2. **TOF 测距**：
   - 有效量程默认 4000mm（规格书 4500mm），深色/吸光墙面会缩短有效距离
   - 墙面有缝隙/孔洞时会出现距离跳变，已通过毛刺滤波处理
3. **红圆检测**：
   - HSV 范围需根据场地光照调整
   - 使用 `视觉抓取/color_object_detector.py` 的 Trackbar 功能调参
4. **PID 参数**：
   - 每个 Phase 都有独立的 PID 参数，建议从较小 Kp 开始调
   - 出现震荡 → 减小 Kp 或增大 Kd
   - 响应太慢 → 增大 Kp

### 🦾 机械臂使用

1. **上电顺序**：先开机器人电源，再启动机械臂控制程序
2. **使能关节**：程序启动时会自动检测舵机是否已上电，未上电则自动使能
3. **参考姿态**：`REF_JOINT_ANGLES` 定义了 IK 参考原点（0,0,0）对应的关节角度
   - 不同版本的 D1 机械臂参考姿态可能不同，需根据实际情况调整
   - 代码中提供了两个版本（`arm_ik_control.py` 零点 -90°，`arm_ik_control1.py` 零点 68.7°），请确认使用正确的版本
4. **坐标方向**：
   - X+：前方（机器人正前方）
   - Y+：左方
   - Z+：上方
   - 单位：厘米（cm）
5. **J4 补偿**：由于机械臂结构原因，J4 关节需要额外补偿
   - 这些参数需要根据实际抓取效果微调
6. **夹爪角度**：`angle6` 控制夹爪，角度越大开合越大（需根据实际校准）

### 🏃 步态与运动

1. **ClassicWalk（经典步态）**：本项目主要使用经典步态，稳定性好，适合精细操作
2. **SpeedLevel（速度档位）**：
   - 台阶任务使用 SpeedLevel 2（更高扭矩）
   - 普通巡线使用 SpeedLevel 1
   - 切换 SpeedLevel 会改变步态，之后需要重新调用 `ClassicWalk(True)`
3. **跳跃动作**：
   - FrontJump 前跳前必须确保机器人完全静止
   - 跳跃前关闭摄像头，落地后重启
   - 跳跃对地面摩擦力有要求，光滑地面可能打滑
4. **控制频率**：控制线程运行在约 100Hz，指令通过 DDS 实时下发

### 🏟️ 场地适配

1. **黑线宽度**：不同场地黑线宽度可能不同，调整 `min_width` 参数过滤细线干扰
2. **场地光照**：
   - 尽量在稳定光照下运行
   - 强烈阳光/阴影会影响视觉检测
   - 可调整摄像头曝光参数（`CAMERA_EXPOSURE`）
3. **迷宫墙体**：
   - 墙体材质影响 TOF 读数（深色墙面测距更短）
   - 建议在实际场地上重新校准 TOF 阈值和偏移量
4. **台阶高度**：
   - 上台阶的俯仰角阈值需要根据实际台阶高度调整
   - 台阶越高，俯仰角峰值越大
   - `P3_PITCH_CLIMBING_THRESH` 和 `P3_PITCH_STOP_THRESH` 需实地标定

### 💾 代码规范

1. **所有可调参数集中在文件顶部常量区**，方便调参
2. **打印日志分级**：`[INIT]` 初始化、`[P1]`~`[P8]` 各阶段、`[ERROR]` 错误、`[WARN]` 警告
3. **安全退出**：`Ctrl+C` 会触发安全停车流程，机器人保持站立
4. **模块化设计**：各 Phase 可独立运行调试，也可通过 `Final_code.py` 串联全流程
5. **库函数接口**：迷宫导航通过 `run_maze_navigation(driver)` 可被主程序调用，复用已初始化的机器人控制线程

## 🛠️ 常见问题

### Q1: 启动时提示 "TOF 三路传感器未就绪"
- 检查 TOF 传感器是否接好，`ls /dev/ttyUSB*` 查看设备节点
- 运行 `python3 测距模块/TOF_read.py` 单独测试
- 尝试重新插拔 USB

### Q2: 摄像头画面卡顿或黑屏
- 检查 USB 带宽是否充足（`lsusb -v` 查看）
- 降低分辨率或帧率
- 确认 D435i 插在 USB 3.0 接口
- 运行 `python3 视觉抓取/depth_camera.py` 单独测试 D435i
- USB 摄像头白屏问题：运行 `3.sh` 或 `set_camera_exposure.sh` 设置亮度/对比度

### Q3: 机械臂 IK 求解失败 / 位置不准
- 确认 `REF_JOINT_ANGLES` 是否与实际机械臂零位一致（尝试 `arm_ik_control.py` 或 `arm_ik_control1.py`）
- 调整 J4 补偿参数
- 先用 `--dry-run` 离线测试目标点是否可达
- 检查目标点是否在工作空间内（最大伸展约 500mm）

### Q4: 巡线时机器人走 S 形 / 震荡
- 减小 PID 的 Kp
- 适当增大 Kd（微分抑制震荡）
- 降低前进速度
- 检查黑线检测是否稳定（有无跳变）

### Q5: 上台阶失败 / 冲过头
- 调整 `P3_STAIRS_FAST_SPEED`（上台阶速度），建议从低速开始
- 调整俯仰角停止阈值 `P3_PITCH_STOP_THRESH`
- 确认偏航角采样是否准确（巡线时是否走直）
- SpeedLevel 设为 2 获得更大扭矩

### Q6: 迷宫中撞墙
- 检查三路 TOF 方向是否正确（左/右/前映射）
- 调整 `CENTER_GAIN`（横向纠偏增益）
- 降低前进速度 `BASE_FORWARD_SPEED`
- 增大前方停车阈值（如 `P1_FRONT_MM`）

### Q7: OCR 标志识别不准 / 识别不到
- 确认 `Recognition/` 目录下模板图齐全（5 张 jpg）
- 确认 `Recognition/models/sign_classifier/best.pt` 存在
- 调整摄像头角度和距离，确保标志在画面中央
- 现场光照变化大时重新采集模板图

### Q8: DDS 通信报错 / 段错误
- 确认 `dds_lib_fix.py` 在 `import cyclonedds` 之前导入
- 确认 CycloneDDS 版本与 `libddsc.so` 匹配
- 检查网络接口是否正确（eth0 / wlan0）
